## 一、B+树核心原理

### 1.1 结构

B+树是B树的变体——所有数据存放在叶子节点，内节点只存键用于导航。

```
                    [50, 100]                  ← 内节点
                   /    |    \
           [20, 35]   [70, 85]   [120, 140]   ← 内节点
          /   |  \    /   |  \    /    |   \
    [10,15][20,30][35,40] ... [140,150,160]  ← 叶子节点
      ←—————————— 叶子链表（双向）————————→
```

### 1.2 关键操作

| 操作 | 复杂度 | 过程 |
|------|--------|------|
| 点查 | O(log n) | 从根向下，二分查找 |
| 范围扫描 | O(log n + k) | 定位起点后沿叶子链表遍历 |
| 插入 | O(log n) | 查找到叶子节点插入；满则分裂 |
| 删除 | O(log n) | 查找到叶子节点删除；不足则合并或借 |

### 1.3 分裂 vs 合并

**分裂**（插入触发）：
1. 叶子节点满 → 分裂为两个节点，中间键上提至父节点
2. 内节点满 → 分裂，中间键上提（不保留副本）
3. 根满 → 创建新根

**合并**（删除触发）：
1. 叶子节点小于半满 → 尝试从兄弟借一个 key
2. 借不到 → 合并到兄弟，下推父节点分隔键

## 二、LSM-Tree 原理

### 2.1 整体架构

```
写入 → MemTable (内存有序表)
        ↓ 满
      冻结 → SSTable (L0)
        ↓ compaction
       SSTable (L1)
        ↓ compaction
       SSTable (L2) ...
```

### 2.2 写入路径（所有写入都是 Append-Only）

1. 顺序写 MemTable（内存跳表/红黑树）
2. MemTable 满 → 冻结为不可变的 SSTable
3. 后台 Compaction 归并 SSTable

### 2.3 读取路径

```
请求 → 查 MemTable → 查 L0 SSTables（最新优先）→ 查 L1 → ... → 返回
```

### 2.4 Compaction 策略

| 策略 | 特点 | 写放大 | 读放大 | 空间放大 |
|------|------|--------|--------|----------|
| Leveled | 每层仅一个文件，层间大小递增 | 高(10-30x) | 低 | 低 |
| Tiered | 每层多个文件，合并到下层 | 低(2-5x) | 高 | 高 |
| 混合 | Leveled+Tiered 组合（如RocksDB） | 中等 | 中等 | 中等 |

## 三、B+树 vs LSM-Tree 对比

| 维度 | B+树 | LSM-Tree |
|------|------|----------|
| **写性能** | 随机写 | ✅ 顺序写（Append-Only） |
| **读性能** | ✅ 稳定 O(log n) | ❌ 需查多层 |
| **范围扫描** | ✅ 叶子链表遍历 | ❌ 归并多文件 |
| **空间放大** | 低 | 中到高（过期数据） |
| **写放大** | 中（分裂/合并） | 高（Compaction） |
| **压缩比** | 低 | ✅ 高（定期合并） |
| **典型引擎** | InnoDB, PostgreSQL | RocksDB, LevelDB, HBase |
| **适用场景** | OLTP 点查多 | 写密集型、IoT |

## 四、B-Link Tree（并发B+树）

并发控制的核心机制：

### Lock Crabbing（锁耦合）
```
锁定父节点 → 锁定子节点 → 释放父节点 → 继续向下
```

### B-Link 改进
每个节点添加：
- **high_key**：该子树的最大 key
- **right_link**：同层兄弟指针

分裂时：
1. 创建右兄弟，拷贝一半数据
2. 设置 right_link 和 high_key
3. **不立即更新父节点**（后续查询通过右链找到正确节点）

优势：写入不阻塞读取，高并发友好。

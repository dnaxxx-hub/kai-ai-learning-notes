# 数据库 #23：分片与再平衡

## 分片策略对比

| 策略 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 范围分片 | key 区间划分 | 连续扫描友好 | 可能热点（顺序写入） |
| 哈希分片 | hash(key) % N | 均匀分布 | 范围查询跨分片 |
| 一致性哈希 | 哈希环 + 虚拟节点 | 再平衡数据少 | 实现复杂 |

## 一致性哈希（虚拟节点）
```
            Node1
             |
    Node4 ----+---- Node2
             |
            Node3

虚拟节点：一台物理机在环上有 150-200 个虚拟节点（虚拟节点数 × 物理节点）
新增节点：从其他节点各拿一部分虚拟节点 → 数据迁移量 ≈ 1/N
```
- Redis Cluster 用 CRC16 哈希槽（不是一致性哈希，但等价）
- etcd 用 Range 分片
- TiDB 用 Region 动态分裂

## 热点治理
- 顺序写入（自增主键）→ 同一 Region 热点 → 置换主键为散列值
- 单 key 热读 → 本地缓存 + Redis
- Join 查询跨分片 → 考虑按维度分片（用户ID/HotelID）

## 动态分裂（TiDB/Spanner 模式）
- 初始 1 个 Region
- 达到阈值（96MB）自动分裂为 2 个
- 平均分配到不同 store
- PD 持续监控 Region 大小和访问频率

## etcd vs Redis Cluster vs TiDB 对比
| 特性 | etcd | Redis Cluster | TiDB |
|------|------|---------------|------|
| 分片 | Range（自动） | 哈希槽（静态） | Range（自动分裂） |
| 一致性 | Raft（强） | 最终 | Raft（强） |
| 再平衡 | 自动（etcd 3.5+） | 手动 reshard | 自动 |
| 数据量 | <10GB | 内存上限 | TB 级 |

## 核心心法
**"主干硬、尾巴软"**

| 原则 | 含义 |
|------|------|
| 主干硬 | 固定列（谁、何时、从哪来、类型）必须严格定义 |
| 尾巴软 | 其余所有可变字段进 JSON/键值对 |
| 先全量保留 | 原始数据完整落库，不丢任何信息 |
| 再按需提键 | 需要查/统计时才建索引 |
| 分层演进 | 原始层→软字段层→业务视图层 |

## 三层模型
1. **原始层** — 整条记录原样存（+哈希去重+来源）
2. **软字段层** — JSON动态属性 + 键值对索引
3. **业务视图层** — 物化表+索引用于高频查询

## 应用到 kai_sdk
升级记忆皮层 v2，新增4张表：
- `memory_raw` — 原始输入保留
- `memory_kv` — KV键值对索引
- `memory_fts` — FTS5全文搜索
- `memory_props` — JSON动态软属性

## 关键收获
- 之前 kai_sdk 的 memories 表把每样字段固定了，缺乏灵活性
- v2 升级后：任意动态属性都能存（props_json），高频查询提为KV索引
- FTS+LIKE回退覆盖中英文搜索
- "不要一上来穷举所有可能字段"——过去经常犯这个错

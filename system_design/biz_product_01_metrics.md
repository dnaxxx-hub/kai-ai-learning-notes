# 课时1：指标体系——从北极星到增长飞轮

> 面向对象：AI/技术从业者
> 核心命题：如何用指标度量产品健康度，驱动数据化决策

## 一、为什么技术人需要懂指标？

技术团队最常见的陷阱：**把「上线功能」当作「创造价值」**。

某AI公司花3个月做了一个智能推荐改版，模型AUC提升5%，团队庆祝。但业务数据——用户次日留存率下降了2%。为什么？因为模型优化了点击率，但推荐了更吸引注意力的低质内容，长期看反而伤害了用户体验。

**指标不是数字，是业务的语言。** 不懂指标的技术人，做的是「技术正确」而非「业务正确」的产品。

---

## 二、核心框架

### 框架1：北极星指标（North Star Metric）

**定义**：唯一能指引产品长期价值的核心指标。它反映「用户从产品中获得的核心价值」，是所有人的行动方向。

**好北极星的特点**：
- 前瞻性（leading indicator，而非滞后指标）
- 可量化、可拆解
- 与商业价值强相关
- 团队所有人都能影响

| 公司 | 北极星 | 为什么选这个 |
|------|--------|-------------|
| Airbnb | 预订过夜数 | 核心价值是住宿体验，而非浏览 |
| Spotify | 总收听时长 | 用户听得越多，价值越大 |
| Uber | 完成行程数 | 供需匹配的最终体现 |
| Facebook（早期） | 10天7个好友 | 社交粘性的临界点 |

**AI产品案例**：一家AI写作助手团队把北极星设为「周活跃用户数」（WAU），但数据显示用户每周回来用3次就流失了。改为「每周完成文档数」（用户每次生成一篇完整文档并获得价值），团队才真正关注「输出质量」而非「打开次数」。

**技术人的坑**：不要选「模型准确率」「API调用次数」等技术指标做北极星。用户不关心你的模型多好，他们关心是否解决了问题。

---

### 框架2：AARRR 海盗漏斗（Pirate Metrics）

Dave McClure 提出的经典框架，定义了用户旅程的5个关键阶段。

| 阶段 | 指标 | 关注点 | AI产品案例 |
|------|------|--------|-----------|
| **Acquisition（获取）** | CPM, CPC, CPI, 新用户数 | 获客效率 | 某AI客服产品通过SEO文章获客，CPC远低于投放广告 |
| **Activation（激活）** | 激活率, 首次关键行为完成率 | 用户是否体验到"Aha Moment" | Midjourney的激活=用户首次生成一张满意的图 |
| **Retention（留存）** | 次日/7日/30日留存, 回访率 | 产品是否不可或缺 | ChatGPT的7日留存率远超传统App——因为聊天是高频场景 |
| **Revenue（收入）** | ARPU, ARPPU, LTV, 付费转化率 | 商业变现能力 | Notion AI的付费转化关键点：免费用户使用了3次AI功能后 |
| **Referral（传播）** | 病毒系数K, NPS, 邀请转化率 | 口碑增长 | Grammarly通过签名档传播——每封邮件都是推广 |

**经典案例：Spotify的AARRR拆解**
- 获客：Facebook广告 → 免费用户
- 激活：用户创建第一个歌单（Aha Moment）
- 留存：每周推荐歌单 → 形成习惯
- 收入：免费用户→付费订阅转化
- 传播：歌单分享到社交网络 → 好友点击注册

**技术人的坑**：很多人只看「留存」和「收入」，忽略「激活」。实际上大多数流失发生在前48小时。如果你的AI产品用户注册后第一句对话就AI回复太慢，激活率会断崖下跌。

### 框架3：同期群分析（Cohort Analysis）

**核心思想**：不是看所有用户的平均数，而是看「同一批用户」(同一周/月注册)随时间的变化。

**为什么需要同期群？**
- 整体留存率可能被「近期新增的大量低质用户」稀释
- 不同获客渠道的用户行为差异巨大
- 产品迭代的效果必须在「同期群」中比较才公平

**同期群留存表解读**：

```
        Week1  Week2  Week3  Week4
Jan群    100%   45%    32%    28%
Feb群    100%   52%    40%    36%  ← 改进后效果明显
Mar群    100%   48%    35%    —   ← 新版本可能有问题
```

如果只看「整体留存率」，你可能错过Feb群因为某次推荐优化带来的真实提升。

**AI产品案例**：某AI绘画产品每月留存率看起来稳定在25%。但用同期群分析发现：去年9月注册的早期用户留存已达40%，而本月新用户留存仅15%。原因是新用户的「出图质量」因Prompt复杂度提升而下降，团队随后做了新手引导优化。

### 框架4：LTV（用户生命周期价值）计算模型

**LTV = 平均每用户贡献收入 ÷ 流失率**

简化版：如果用户每月付$10，月流失率5%，则 LTV ≈ $10 / 0.05 = $200

**实操中的三个要点**：
1. **CAC（获客成本）** 必须 < LTV，通常要求 LTV:CAC ≥ 3:1
2. **回本周期**：需要在3个月内回收CAC
3. **区分付费与免费用户**：不要用平均数掩盖结构问题

**案例：SaaS AI产品LTV测算**
```
月ARPU: $50
月流失率: 4%
LTV = $50 / 0.04 = $1,250
CAC = $300（广告）+ $100（销售时间）= $400
LTV:CAC = 3.1 ✅ 健康
回本周期 = $400 / ($50 - $10服务器成本) = 10个月 ⚠️ 偏长
```

### 框架5：指标体系搭建——KPI树

**核心思想**：顶级指标（如营收）可以逐层拆解为可操作的子指标。

**示例：SaaS AI产品的KPI树**

```
├── 营收 (Revenue = New MRR + Expansion MRR - Churn MRR)
│   ├── 新增MRR = 新用户数 × 转化率 × ARPU
│   │   ├── 新用户数 = 流量 × 注册转化率
│   │   ├── 免费→付费转化率（关注7天免费体验转付率）
│   │   └── ARPU（分Basic/Premium/Enterprise）
│   ├── 扩展MRR = 升级率 × 加购率
│   │   ├── 免费→入门升级率
│   │   └── 入门→专业升级率
│   └── 流失MRR = 取消订阅收入
│       ├── 主动取消率（关注取消原因分析）
│       └── 被动流失率（支付失败等）
├── 用户健康
│   ├── 留存率（D1/D7/D30）
│   ├── NPS（推荐者 - 贬损者）
│   └── 活跃度（DAU/MAU > 0.2 才算健康）
└── 效率指标
    ├── LTV/CAC（>3）
    ├── 回本周期（<12月）
    └── Gross Margin（>70%）
```

**技术人如何用KPI树**：
- 后端团队关注：API响应时间 → 影响用户激活率 → 影响留存
- 算法团队关注：推荐精准度 → 影响用户活跃度 → 影响ARPU
- 前端团队关注：加载速度 → 影响注册转化率 → 影响LTV

## 三、AI技术人必备的指标思维

### 1. 不要只看「平均值」

> 某人一只脚在冰水里，一只脚在火里，平均温度舒服。但他的感受是「不舒服」。

- 中位数比平均数更有意义（尤其是收入分布）
- 按分位数看（P25/P50/P75）
- 注意长尾用户的影响

### 2. 区分「相关」与「因果」

- 不要因为「付费用户DAU更高」就说「付费带来活跃」
- 可能是「活跃用户更愿意付费」
- 详见课时3（因果推断）

### 3. 警惕「虚荣指标」（Vanity Metrics）

| 虚荣指标 | 可操作指标 |
|---------|-----------|
| 总注册用户数 | 周活跃用户数 |
| 下载量 | 次日留存率 |
| 页面浏览量 | 关键行为转化率 |
| API总调用次数 | 平均每用户每日调用次数 |

**真实案例**：某AI公司PR说「注册用户突破1000万」，但DAU只有5万。这是典型的虚荣指标——1000万注册中对产品没感觉的人占95%。

### 4. 建立「指标变化→行动」的反馈闭环

指标下降不是终点，是起点：

```
指标异常检测 → 拆解到子指标 → 定位变化来源 → 提出假设 → A/B测试 → 上线/复盘
```

## 四、实战练习：给你的AI产品搭建指标体系

假设你负责一个新AI产品「AI简历优化助手」：
- 用户上传简历 → AI诊断 → 优化建议 → 付费下载优化版

尝试回答：
1. 北极星指标是什么？（提示：不是「生成的简历数」）
2. AARRR每个阶段的关键指标？
3. 用户激活的"Aha Moment"是什么？
4. 如何搭建KPI树？

**参考答案**：
1. 北极星：「每周获得面试邀请的用户数」（最终价值是帮用户找到工作）
2. 获客→SEO「简历优化」关键词；激活→用户看到修改前后的对比效果；留存→用户每次更新简历都回来；收入→付费下载/订阅；传播→用户在Offer上晒图
3. Aha Moment：用户看到AI修改后的简历「对比效果」——"原来我的简历可以这样写！"
4. KPI树根节点为「获得面试数」，向下拆解到简历完整性、关键词匹配度、投递量等

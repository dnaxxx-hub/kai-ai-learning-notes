# 课时2：A/B测试——科学验证的产品引擎

> 面向对象：AI/技术从业者
> 核心命题：如何设计、执行、解读A/B测试，做出数据驱动的产品决策

## 一、为什么技术人需要懂A/B测试？

**没有对比，就没有伤害。**

AI工程师小明做了一个推荐算法改进，离线评估AUC提升了3%。上线后整体GMV增长了0.5%，团队庆祝。但三个月后业务复盘发现——那次改动实际上让头部用户流失率上升了8%。

问题出在哪？没有做严格的A/B测试。

**A/B测试不是「比大小」，而是一个科学实验框架。** 它帮你回答：
- 这个改动真的有效吗？（统计显著性）
- 效果有多大？（效应量）
- 对谁有效？（异质性分析）
- 有什么副作用？（统一性检查）

---

## 二、核心框架

### 框架1：假设检验——从直觉到科学

**核心逻辑**：

```
H₀（零假设）：新版本 = 旧版本（没有效果）
H₁（备择假设）：新版本 ≠ 旧版本（有效果）

如果p值 < α（通常0.05）→ 拒绝H₀ → 认为有效果
```

**但p值不是万能的——常见误解**：

| 误解 | 真相 |
|------|------|
| p<0.05 意味着「改版有效」的概率95% | p值不是「H₁为真的概率」，而是「H₀为真时观察到这个结果的概率」 |
| p<0.01 比 p<0.05 更好 | p值越小，结果越不可能由随机波动引起，但效应量大小更重要 |
| p>0.05 意味着「改版无效」 | 可能样本量不够（统计功效不足），或效应量太小 |

**AI产品案例**：某AI客服团队做了意图识别模型升级，A/B测试显示「解决率」提升了1.2%，p=0.04。看起来很漂亮。但团队进一步分析发现：这个提升主要由「简单问题」驱动，「复杂问题」解决率反而下降了0.8%（只是不显著）。如果只看p值，这个副作用就会被忽略。

**实战要点**：
1. 报告效应量（提升百分比、Cohen's d），不只是p值
2. 同时报告置信区间——「提升1.2%，95%CI [0.1%, 2.3%]」
3. 做统一性检验——效果是否对所有用户一致

### 框架2：样本量计算与MDE（Minimum Detectable Effect）

**最常见的A/B测试失败原因**：样本量不够。

**样本量公式（简化版）**：

```
n = (Z_α/2 + Z_β)² × 2σ² / δ²
```

其中：
- Z_α/2 = 1.96（α=0.05双边检验）
- Z_β = 0.84（80%统计功效）
- σ = 指标标准差
- δ = 最小可探测效应（MDE）

**MDE的实际含义**：「你的实验能检测多小的变化？」

| MDE | 基准转化率5% | 基准转化率10% | 单组所需样本量 |
|-----|------------|-------------|-------------|
| 1% | 5.05% | 10.1% | ~50,000+ |
| 5% | 5.25% | 10.5% | ~15,000 |
| 10% | 5.5% | 11.0% | ~4,000 |

**现实案例**：某AI写作工具团队想测试一个「一键优化」按钮是否提高付费转化率。基准付费率3%。他们预计能提升到3.3%（10%相对提升）。
- MDE = 0.3个百分点
- 单组需要 ≈ 30,000 用户
- 但他们只有每天1000新用户，实验跑7天 = 7000用户
- **结果：实验跑了2周，p=0.12，不显著**
- 实际可能有效果，但样本量不够

**三个速查技巧**：

1. **先跑AA测试**：不用计算，直接看两个对照组之间是否有显著差异——如果有，说明你的实验系统有问题
2. **用在线计算器**：Evan Miller的样本量计算器比手算靠谱
3. **不要中途看结果**：频繁查看结果并提前停止，会增加假阳性率（Peeking Problem）

### 框架3：多重比较校正（Multiple Testing）

**问题**：你跑一个实验，看10个指标，纯随机也会有0.5个指标显著（10×0.05）。

**常见的多重比较场景**：
- 「我们实验看5个核心指标」
- 「我们按10个用户群分别分析」
- 「我们每周都看一次显著性」
- 「我们测试了10个不同的版本」

**校正方法**：

| 方法 | 原理 | 适用场景 |
|------|------|---------|
| Bonferroni | α ÷ 比较次数 | 最保守，适合关键决策 |
| Benjamini-Hochberg (FDR) | 控制错误发现率 | 探索性分析 |
| Holm-Bonferroni | 逐步校正，比Bonferroni强 | 折中方案 |

**案例**：Netflix测试新缩略图，看了50个国家的转化率。按Bonferroni校正，α=0.05/50=0.001。只有两个国家达到这个标准——但如果按FDR校正，可能有8个国家有效果。前者避免假阳性但可能漏掉真阳性，后者反之。Netflix选择了FDR+后续验证。

**AI技术人的特殊问题**：
- 多臂Bandit算法会在「每次决策」时做统计检验，天然有peeking problem
- 深度模型的超参数搜索 = 多重比较的极端形式
- 需要用贝叶斯方法或交叉验证来做校正

### 框架4：网络效应下的A/B测试（最难的问题）

**经典网络效应**：Uber的测试。如果把一半司机关进对照组，那全平台体验都受影响——乘客等车时间变长，司机收入变少。

**网络效应下的三个技术挑战**：

1. **干扰（Interference）**：实验组和对照组互相影响
   - 例子：Facebook测试新信息流排序，你看到的内容变了→你点赞→你的朋友在对照组也看到了你点赞→被你影响
   
2. **溢出（Spillover）**：实验效果「溢出」到对照组
   - 例子：LinkedIn测试新邀请机制，实验组邀请了更多好友→对照组被邀请的好友变多了

3. **市场均衡变化**：双边市场供需平衡被改变
   - 例子：Uber测试司机端激励，实验组司机多→乘客等待时间变短→对照组乘客也可能受益

**应对方案**：

| 方法 | 原理 | 案例 |
|------|------|------|
| 网络分区（Cluster Randomization） | 按地理/社交集群分组，而非单个用户 | LinkedIn按公司分组测试 |
| Switchback测试 | 时间片轮换，今天A明天B | Uber按城市/时间段测试 |
| 网络干扰的Eicker-Huber-White标准误 | 统计校正 | 学术论文常用 |
| 模拟+因果推断 | 用DAG建模链路 | 复杂业务场景 |

**AI产品案例**：抖音（TikTok）做内容池推荐算法测试。如果随机分组——A组看新推荐，B组看旧推荐——但A组的内容会被B组用户看到（因为创作者在不同组都有粉丝），新推荐算法产生的爆款内容也会「感染」B组。抖音的解决方案是**按创作者分组**：一部分创作者的视频用新算法推荐，另一部分用旧算法。这样每个用户看到的都是混合内容，但比较的是「新算法推荐的视频」vs「旧算法推荐的视频」的表现。

### 框架5：贝叶斯A/B测试（技术人的进阶选择）

**传统频率学派vs贝叶斯学派**：

| 维度 | 频率学派（p值） | 贝叶斯 |
|------|---------------|--------|
| 问题 | 数据在H₀下的概率是多少？ | H₁为真的概率是多少？ |
| 结果 | p值，拒绝/不拒绝H₀ | 后验概率分布 |
| 决策 | 依赖于实验前设定的α | 可以随时更新，灵活性高 |
| 直觉性 | 反直觉（p值含义容易误解） | 直观（"版本A有85%概率优于B"） |
| 先验 | 传统上不依赖先验 | 需要先验分布 |

**贝叶斯的三个优势**：

1. **自然处理peeking**：随时可以看，后验概率一直有效
2. **结果更直观**：「版本A比版本B好的概率是87%」
3. **可以引入先验**：之前的实验、行业基准可以作为先验

**案例**：一个AI翻译工具测试新模型。传统p值：跑了3天，p=0.08，"继续跑吧"。贝叶斯：跑了1天，后验概率「新模型更好」=72% ; 3天后→98% ; 可以更早做决策。

**贝叶斯的坑**：
- 需要选先验——先验偏强会影响结果
- 计算更复杂（MCMC采样，但现在有PyMC、Stan等工具）
- 业务方不理解「后验概率」是什么

## 三、AI产品A/B测试的特殊问题

### 1. 模型版本的A/B测试

**与传统前端A/B测试的区别**：
- 模型效果有「冷启动」问题（初期不准确，需要数据积累）
- 模型效果可能随时间衰减（concept drift）
- 需要评估的不是一次点击，而是「累积效果」

**最佳实践**：
- 运行时间至少覆盖1个完整业务周期（如1周）
- 监控模型指标（准确率、召回率）和业务指标（留存、收入）双重指标
- 做「在线评估」而非「离线评估」——离线AUC再高，上线后用户行为会变

### 2. 个性化算法的A/B测试

**问题**：如果算法为每个人定制体验，你怎么比较「个性化」vs「非个性化」？

**典型方法**：
- **Holdout**：保留1%用户不用该算法
- **逆倾向评分（IPS）**：纠正选择偏差
- **Switchback**：每隔几小时切换算法版本

### 3. 实验平台的工程架构

一个成熟的实验平台需要：
- **分层实验**：流量可复用在多个实验层（如推荐层、UI层、模型层）
- **正交实验**：各层之间通过哈希正交
- **实时指标监控**：实验跑几分钟就能看初步结果
- **自动异常报警**：核心指标显著下降时自动通知并暂停实验

## 四、A/B测试的10个常见坑（技术人版）

| # | 坑 | 表现 | 解决 |
|---|-----|------|------|
| 1 | Peeking | 每天看一次结果，看到显著就停 | 预设运行时间，或使用贝叶斯方法 |
| 2 | 样本量不足 | 不显著但效应量很大 | 跑更长或接受小样本的贝叶斯分析 |
| 3 | 多重比较 | 10个指标1个显著 | Bonferroni或FDR校正 |
| 4 | 基数效应 | 在低基数指标上测出显著性 | 关注效应量而非p值 |
| 5 | 新奇效应 | 用户对新功能新鲜感带来短期提升 | 至少跑1-2周以上 |
| 6 | 交互效应 | 多个实验同时跑互相干扰 | 分层+正交实验设计 |
| 7 | 网络干扰 | 实验组和对照组互相影响 | 聚类随机化或switchback |
| 8 | 存活者偏差 | 只看完成实验的用户，不看流失的 | 做ITT分析（意向性分析） |
| 9 | 截断偏差 | 用户被屏蔽规则排除 | 检查筛选条件是否引入偏差 |
| 10 | 后验分组 | 实验跑完后按用户行为分组比较 | 这是观察性研究，需要因果推断 |

## 五、实战练习

**场景**：你的AI产品新增「AI助手」功能，目标是提升用户周活跃度。你设计了一个A/B测试：
- 对照组：现有产品
- 实验组：增加一个AI助手入口

**问题**：
1. 你的主要指标是什么？次要指标是什么？
2. 样本量需要多少？（假设基准WAU率40%，想检测到5%相对提升）
3. 需要跑多久？
4. 如果结果p=0.06，但不显著，你的下一步行动是什么？

**参考思路**：
1. 主要指标：月活跃用户率（避免周级别的短期波动）、次要：NPS、功能使用频次
2. 40%基准，5%相对提升→42%→单组约13,000→总量26,000
3. 取决于每日流量。如果日活1万，约2.6天；但建议跑至少7天覆盖一周模式
4. p=0.06不显著：①检查效应量（是0.1%提升还是1.9%提升？）②检查样本量（是否够？）③检查是否有新奇效应④继续多跑一段时间⑤分层分析（对谁有效？）

## 2. 传感器数据模拟策略

**为什么用正弦波+噪声？**

真实物联网传感器的数据天然具有周期性：
- 温度：白天上升、夜晚下降（周期~60秒模拟日周期）
- 湿度：与温度反相关（周期~90秒）
- 光照：太阳周期（周期~120秒）
- 气压：日变化+天气系统（周期~180秒）
- PM2.5：早晚高峰（周期~45秒）

**数据生成公式**：
```
value = base + amplitude * sin(t / period * 2π + phase) + gaussian_noise(μ=0, σ=5%range)
```

**异常模拟**：
- 2%概率的随机尖峰（3~8倍噪声幅度）
- 95% good / 4% fair / 1% bad 的数据质量标记

## 3. 告警引擎双机制

1. **阈值检测**：硬界限（温度>45°C、湿度<20%、PM2.5>200）
2. **3σ异常检测**：当值偏离滚动均值超过3倍标准差时触发
   - 滚动窗口30个样本，至少5个样本后才启用心跳检测
   - 优势：能检测到仍在阈值内但异常的突变（如气压骤变）

## 4. 聚合窗口设计

三个时间窗口同时维护：
| 窗口 | 用途 | 描述 |
|------|------|------|
| 5秒 | 实时监控 | 快速响应 |
| 30秒 | 近实时 | 短趋势 |
| 5分钟 | 长期趋势 | 稳定统计 |

每个窗口维护一个deque（最大2000条），每次新数据到达时：
1. 追加到缓冲区
2. 清除窗口过期数据
3. 计算avg/min/max/std/count

## 5. HTTP仪表盘

- `http.server` 自托管，无Flask依赖
- API端点：`/api/sensors`, `/api/data`, `/api/alerts`, `/api/aggregations`, `/api/events`
- Server-Sent Events (SSE) 实时推送
- HTML/CSS/JS全嵌入式，单页SPA风格
- 深色主题仪表盘，数据自动刷新

## 6. 关键设计决策

1. **单文件vs多模块**：初期用单文件方便测试和部署，后续可拆分
2. **in-process总线**：省略真实MQTT broker，用asyncio.Queue内部通信
3. **SensorNode无状态**：每次read()独立计算，方便并行
4. **deque环形缓冲区**：自动丢弃旧数据，O(1)追加
5. **SSE替代WebSocket**：http.server原生支持长连接，JS端EventSource自动重连

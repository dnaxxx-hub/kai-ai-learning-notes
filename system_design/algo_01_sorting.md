# 第1课：比较排序极限 — 决策树下界与排序算法深度

> 本课通过实现8种排序算法、5种数据分布、6个规模，验证比较排序的 Ω(n log n) 下界，深入理解各算法特性。

---

## 1. 决策树模型与Ω(n log n)下界

**决策树模型**：每个比较排序可以建模为一棵决策树，每个内节点代表一次比较，叶子节点代表一种排列。

- n个元素的排序有 n! 种可能结果
- 决策树至少有 n! 个叶子节点
- 树的高度 h ≥ ⌈log₂(n!)⌉
- Stirling近似：⌈log₂(n!)⌉ = n·log₂(n) − n·log₂(e) + O(log n)
- ⇒ **比较排序下界：Ω(n log n)**

**实验验证**：对归并排序统计不同 n 下的平均比较次数，与 n·log₂(n) 对比。

## 2. 归并排序变体

### 2.1 自底向上归并排序（迭代版）

- 从 size=1 开始，逐层合并，直到 size ≥ n
- 时间 O(n log n)，空间 O(n)，**稳定**
- 优点：无递归调用，节省栈空间，cache-friendly

```python
# 核心逻辑
size = 1
while size < n:
    for lo in range(0, n - size, 2 * size):
        merge(arr, aux, lo, lo+size-1, min(lo+2*size-1, n-1))
    size *= 2
```

### 2.2 自顶向下归并排序（递归版）

- 经典的分治实现：mid = (lo+hi)//2
- 时间 O(n log n)，空间 O(n)，**稳定**
- 优点：实现直观，易于理解分治思想
- 小优化：arr[mid] ≤ arr[mid+1] 时跳过合并

### 2.3 三路归并排序

- 分3段，每段约 1/3，三路合并
- 三路合并需更多比较逻辑，但减少递归深度（log₃ n vs log₂ n）
- 依然是 O(n log n)，**稳定**
- 实际常数更大，通常不如二路归并

## 3. 快速排序优化

### 3.1 Lomuto分区（基础版）

- pivot 选最后一个元素，i 记录 ≤ pivot 的位置
- 最坏 O(n²)，平均 O(n log n)
- **不稳定**
- 简单但效率较低（partition 每次交换较多）

### 3.2 三路切分优化（荷兰国旗问题）

- 数组被分为 `< pivot / = pivot / > pivot` 三部分
- 大量重复元素时效率极高（全部相等时 O(n)）
- 随机选 pivot 可进一步避免最坏情况

### 3.3 随机化QuickSort + 尾递归优化

- 随机选 pivot，Hoare 分区（双向扫描，交换更少）
- 尾递归：递归处理小半部分，循环处理大半部分
- 递归深度从 O(n) 降至 O(log n)

### 3.4 综合优化版

- **三数取中**选 pivot（median-of-3）
- **小数组（< 16）**用插入排序
- **尾递归**优化
- 实际运行最快的 QuickSort 变体之一

## 4. 堆排序深度

### 4.1 最大堆实现

- `build_max_heap`：自底向上下滤 sift-down，O(n)
- 提取最大元素放到末尾 → sift-down / O(log n)
- 时间 O(n log n)，空间 O(1) 原地，**不稳定**

### 4.2 上滤 vs 下滤构建

| 构建方式 | 时间复杂度 | 说明 |
|---------|-----------|------|
| 下滤（sink） | O(n) | 从 i=n/2-1 到 0 逐层下滤 |
| 上滤（swim） | O(n log n) | 每个元素插入堆尾再上滤 |

下滤构建更高效的原因是：越往底层节点越多，但下滤距离短。

## 5. 排序稳定性分析

| 算法 | 稳定？ | 原因 |
|-----|--------|------|
| 归并排序 | ✅ | 等值时优先取左半边元素 → 保持原序 |
| 快速排序 | ❌ | 分区过程中远距离交换破坏原始顺序 |
| 堆排序 | ❌ | 父子节点长距离交换，完全无法保证稳定性 |

## 关键总结

| 知识点 | 结论 |
|--------|------|
| 比较排序下界 | Ω(n log n)，由决策树模型的叶子数决定。归并排序实际比较次数 ≈ 0.9·n·log₂(n) |
| 归并排序 | 稳定，O(n log n)，需 O(n) 额外空间。自顶向下在小数据有序时更快（跳过合并检查） |
| 快速排序 | Lomuto 基础版在有序/逆序数据退化到 O(n²)（≈ 3.6s @ n=10k）。必须随机化或三数取中 |
| 综合优化快排 | **实际最快**（7.26ms @ n=10k vs 堆排 25.42ms），三数取中+插入排序+尾递归效果显著 |
| 三路快排 | 在重复值数据上表现最佳（11.66ms vs 综合优化 9.95ms，但非重复数据稍慢） |
| 堆排序 | 原地 O(1) 空间，但实际较慢（cache 不友好），n=10k 时约 25ms |
| 稳定性 | 归并类全部稳定；快排稳定性依赖具体实现（三路切分和综合优化版在测试中稳定） |
| 自顶向下 vs 自底向上 | 迭代版(自底向上)略慢于递归版(自顶向下)，因为跳过合并优化在迭代版中更难实现 |

### 关键发现

1. **基础快排的致命弱点**：Lomuto 分区在有序/逆序/部分有序数据上退化到 O(n²)，n=10000 时耗时 ~3-4 秒，而其他算法仅需几毫秒——**天壤之别**。

2. **综合优化快排全面领先**：三数取中 + 插入排序 + 尾递归的组合在几乎所有场景下都是最快的。

3. **决策树下界验证通过**：归并排序的比较次数始终在 0.82~0.91·n·log₂(n) 范围内，符合 Ω(n log n)。

4. **堆排序的"快排悖论"**：理论 O(n log n) 有保证，但实际比快排慢 2-4 倍——cache 局部性差是主因。

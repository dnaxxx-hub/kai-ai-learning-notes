# 文本预处理与词表示

> 日期：2026-05-07 20:00 | 课程：NLP路线 Phase 1-1
> 目标：理解"怎么把文字变成计算机能处理的数字"

## 核心问题

```
计算机不认识"猫"、"dog"、"今天天气好"
只认识数字
所以: 文字 → 数字（词向量）
```

## 三步走

### 1. 文本预处理

```python
# 中文和英文的处理不同
# 
# 英文: 按空格分词
# "I love NLP!" → ["I", "love", "NLP", "!"]
# 
# 中文: 没有空格 → 需要分词工具
# "我爱自然语言处理" → ["我", "爱", "自然语言处理"]
# 工具: jieba, HanLP, LAC
#
# 预处理步骤:
# 1. 分词(Tokenization)
# 2. 去停用词（的/了/是 → 没什么语义，去掉）
# 3. 小写化（English → 统一）
# 4. 词干提取/词形还原（running → run）
```

### 2. 词袋模型（BoW）

```python
# 最简单: 统计每个词出现了多少次
# 
# 语料: ["我 爱 猫", "猫 爱 鱼"]
# 词表: {"我":0, "爱":1, "猫":2, "鱼":3}
#
# "我 爱 猫" → [1, 1, 1, 0]
# "猫 爱 鱼" → [0, 1, 1, 1]
#
# 问题: 
# - 没考虑顺序（"我爱你"和"你爱我"向量一样）
# - 稀疏（词表很大，但每个句子只用到很少词）
```

### 3. TF-IDF

```python
# 改进BoW: 不只是统计次数
# 
# TF = 词在文档中出现的频率
# IDF = log(总文档数 / 包含该词的文档数)
# TF-IDF = TF × IDF
#
# 效果: 常见词(的/是)被降权
#       稀有词(Transformer)被加权
#       重要词得高分
```

## Word2Vec（词嵌入的突破）

### 思想

```python
# 之前的表示: 每个词是独立的（One-hot或BoW）
# 
# Word2Vec: 每个词是一个稠密向量（300维）
# "猫" = [0.12, -0.33, 0.75, ...]
# "狗" = [0.15, -0.30, 0.72, ...]  # 相似的词向量也相近
```

### 两种训练方式

```python
# CBOW (Continuous Bag of Words):
# 上下文 → 预测目标词
# "我是[____]的程序员" → 预测"优秀"

# Skip-gram:
# 目标词 → 预测上下文
# "优秀" → "我" "是" "的" "程序员"

# Skip-gram在少量数据上效果更好（但训练慢）
```

### 最著名的例子

```python
# vector("国王") - vector("男人") + vector("女人") ≈ vector("女王")
# 
# 词向量空间有"语义方向":
# "国王"→"女王" 和 "男人"→"女人" 是同一个向量差
# → 词向量学会了"性别"这个抽象概念
```

## GloVe

```python
# Word2Vec的改进
# 
# Word2Vec: 用局部上下文窗口
# GloVe:    用全局共现矩阵
#
# 效果: 差不多，GloVe在某些任务稍好
# 但2018年后都被BERT/ELMo替代了
```

## 词嵌入的演进

```
One-hot (10^4维,稀疏) 
→ Word2Vec (300维,稠密,2013)
→ GloVe (300维,全局统计,2014)  
→ ELMo (上下文相关,2018)
→ BERT (上下文+双向+动态,2018) ← 现在的标准
```

## 今日收获
- 文本 = 分词 + 向量化
- BoW/TF-IDF = 简单但丢失语义
- **Word2Vec = 词嵌入的开端**（国王-男人+女人=女王）
- 句子的表示：把词向量平均（太粗糙）或是用BERT（更准）
- 词嵌入的演进：静态(Word2Vec) → 动态(BERT)

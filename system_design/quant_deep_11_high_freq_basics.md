# 高频交易：HFT 架构与延迟优化

> 高频交易不是关于速度——是关于**确定性**。

## 1. HFT 的核心原则

### 速度层级

```
毫秒级（高频）    微秒级（超高频）    纳秒级（硬件级）
   ↓                 ↓                   ↓
 做市商报价       统计套利           FPGA解码
 套利延迟         市场数据       FIX/行情硬解码
```

### HFT 信条
1. **延迟决定一切** — 1微秒的延迟优势值百万
2. **确定性 > 快** — 可预测的延迟比偶然的慢更重要
3. **本地计算** — 所有决策在本地完成，不依赖外部API
4. **先到先得** — 市场是按时间优先，不是按价格优先

## 2. HFT 系统的典型架构

```
         行情源
           ↓
    [FPGA 行情解码]    ← 硬解码市场数据（纳秒级）
           ↓
    [共享内存行情]     ← 微秒级内存访问
           ↓
   ┌─────────────┐
   │ 策略引擎     │    ← 模式匹配 + 统计模型（微秒级）
   └─────────────┘
           ↓
    [订单管理系统]    ← 风控 + 订单路由
           ↓
    [FPGA 下单接口]   ← 硬编码下单（纳秒级）
           ↓
        交易所
```

## 3. 关键延迟指标

| 组件 | 典型延迟 | 说明 |
|------|---------|------|
| 网络传输（上海→深圳） | 10-20ms | 光纤/微波 |
| 网卡到用户态 | 1-10μs | 内核绕过（DPDK） |
| 行情解码 | 0.1-1μs | FPGA硬解码 |
| 策略计算 | 0.1-5μs | 简化为查表 |
| 订单编码 | 0.5-2μs | 二进制协议 |
| 全链路 | 10-50μs | 顶级HFT |

## 4. 硬件加速

### FPGA vs CPU

| 特性 | CPU | FPGA |
|------|-----|------|
| 逻辑执行 | 串行（指令流水线） | 并行（硬件逻辑） |
| 延迟 | 1-100μs（取决于OS调度） | 10-100ns（纯硬件） |
| 灵活性 | 无限 | 重新编译 |
| 典型应用 | 策略逻辑 | 行情解码/下单接口 |
| 成本 | 低 | 高（一块卡几万到百万） |

### DPDK（Data Plane Development Kit）

```
传统路径：
网卡 → 内核网络栈 → socket → 用户态应用  （50-100μs）

DPDK路径：
网卡 → 用户态轮询 → 应用接收           （1-5μs）
```

## 5. 套利类型

### 跨市场套利

```python
class ArbitrageScanner:
    """
    检测同品种不同市场间的价差，推送到订单系统
    """
    def scan(self, bid1, ask1, bid2, ask2, cost=0.0003):
        """
        Market 1 和 Market 2 各自的买卖价
        cost: 交易成本（延迟保证模式下需要预估）
        """
        # 可能套利机会
        if bid1 > ask2:  # 市场1的买价 > 市场2的卖价
            return {'action': 'BUY_M2_SELL_M1', 'profit': bid1 - ask2}
        if bid2 > ask1:
            return {'action': 'BUY_M1_SELL_M2', 'profit': bid2 - ask1}
        return None
```

### 统计套利

```
配对交易 HFT 版：
1. 监控两只高度相关股票的价差（比如 茅台/五粮液）
2. 价差偏离 2σ 以上 → 做空强势，做多弱势
3. HFT 的优势：在价差回归前平仓（分钟级 vs HFT级）
```

## 6. 主存储器分层

```

L1 Cache       ←1ns
```

## 7. HFT 与普通量化的区别

| 维度 | 普通量化 | HFT |
|------|---------|-----|
| 持仓时间 | 天~月 | 秒~分钟 |
| 决策时间 | 秒~小时 | 微秒~毫秒 |
| 策略 | 多因子/趋势 | 做市/套利 |
| 基础设施 | Python | C++/FPGA |
| 交易成本 | 占比小 | 决定生死 |
| 数据 | 日线/分钟线 | Tick/逐笔 |

## 8. HFT 的争议

- **流动性提供** vs **抢先交易** — 做市商提供流动性，但抢单者损害市场
- **军备竞赛** — 谁花钱多谁赢，社会价值存疑
- **闪崩风险** — 2010 Flash Crash（Dow Jones 5分钟跌1000点）
- **监管** — 中国A股对HFT限制严格（T+1、涨跌停、交易费用结构）

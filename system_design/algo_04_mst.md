# 第4课：最小生成树 — Kruskal / Prim / Union-Find

> 日期: 2026-05-08
> 代码: `mst.py`
> 图: `figures/mst_comparison.png`

## 1. Union-Find (并查集)

### 操作
- `Find(x)`: 返回 x 所属集合的根
- `Union(x, y)`: 合并 x 和 y 所在集合
- `Connected(x, y)`: 判断 x 和 y 是否连通

### 优化
- **路径压缩 (Path Compression)**: Find 时将路径上所有节点直接挂到根
- **按秩合并 (Union by Rank)**: 将较矮的树挂到较高的树下

### 时间复杂度
- 近似 O(α(N)) — α 是阿克曼函数的反函数，≈常数
- 单次操作均摊 O(1)

## 2. Kruskal 算法

### 思路
1. 将所有边按权重排序
2. 从小到大遍历，若两端不连通则加入MST
3. 直到选中 V-1 条边

### 复杂度
- 排序: O(E log E)
- Union-Find: O(E α(V))
- 总体: O(E log E)

### 优点
- 适合稀疏图
- 实现简单，不需要邻接表

## 3. Prim 算法

### 思路
1. 从任意节点开始，维护已访问集合
2. 每次选连接已访问/未访问的最小权重边
3. 将新节点加入已访问集合

### 实现
- 优先队列: 每次选最小权重边
- 需要标记visited避免重复

### 复杂度
- 使用二叉堆: O(E log V)
- 使用斐波那契堆: O(E + V log V)

### 优点
- 适合稠密图
- 不需预排序

## 4. 算法对比

| 特性 | Kruskal | Prim |
|------|---------|------|
| 思路 | 选边 | 选点 |
| 数据结构 | Union-Find | 优先队列 |
| 时间复杂度 | O(E log E) | O(E log V) |
| 适合 | 稀疏图 | 稠密图 |
| 实现复杂度 | 简单 | 中等 |

## 关键发现
1. Kruskal 比 Prim 略快（稀疏图场景，排序比堆操作更高效）
2. Kruskal 的边集和 Prim 的边集可能不同，但总权重一定相同
3. Union-Find 的路径压缩 + 按秩合并是算法竞赛中并查集的标准实现
4. MST 不一定唯一（存在多条等权边时），但最小总权重唯一

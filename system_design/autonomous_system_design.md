### 问题诊断
1. **信息过载**：每天心跳要检查8+状态点（传感器/总线/系统/cron/桥接/图谱/学习/任务）
2. **优先级模糊**：所有检查平铺，重要的（用户消息响应）和次要的（桥接复习）优先级相同
3. **跨周报缺失**：每个子系统单独工作，但没有"本周围绕系统整体发生了什么"的视角

## 优化方案

### 三级调度优先级
```
P0（每心跳必跑）: 传感器 → 总线消费 → 用户消息检查 → 安全自检
P1（每3心跳跑1次）: 系统状态 → 知识桥复习 → 好奇探针
P2（每日1次）: 深度学习 → 知识图谱遍历 → 反思日志
```

### 交互仪表盘
不需要UI，但需要每个心跳输出一行状态摘要：
```
[12:00] 🟢 system:11/11 ☑️ | 🧪 bridge:234条(复习3) | 📈 cron:9/11 | 📚 学:172篇
```

### 跨系统信息流改进
目前 bus 主要是单向通知（A→B），缺少：
- 消费确认（B读了A的消息，结果如何？）
- 超时重试（A的消息B没处理怎么办？）
- 聚合报告（今天所有系统发生了什么？）

## 可操作产出

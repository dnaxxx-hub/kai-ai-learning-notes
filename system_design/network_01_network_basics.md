# 计算机网络基础 — OSI七层 vs TCP/IP四层模型

## 分层思想

**为什么需要分层？**

网络通信极其复杂，分层将庞大问题拆解为多个子问题：
- 每一层只关注自己的职责
- 层与层之间通过标准接口通信
- 某层改动不影响其他层（eg: 应用层换协议，底层传输不变）

## OSI 七层模型（理论标准）

| 层 | 名称 | 职责 | 典型协议/设备 | 数据单元 |
|----|------|------|-------------|----------|
| 7 | 应用层 | 用户接口，提供网络服务 | HTTP, DNS, FTP, SMTP | 数据(Data) |
| 6 | 表示层 | 数据格式转换、加密、压缩 | SSL/TLS, JPEG, ASCII | - |
| 5 | 会话层 | 建立/管理/终止会话 | NetBIOS, RPC | - |
| 4 | 传输层 | 端到端可靠传输 | TCP, UDP | 段(Segment) |
| 3 | 网络层 | 路由寻址、分组转发 | IP, ICMP, ARP, OSPF, BGP | 包(Packet) |
| 2 | 数据链路层 | 帧封装、MAC寻址、差错检测 | 以太网, 交换机, PPP | 帧(Frame) |
| 1 | 物理层 | 比特流传输、电气信号 | 网线, 集线器, 光纤 | 比特(Bit) |

## TCP/IP 四层模型（事实标准）

| 层 | 对应OSI | 核心功能 | 核心协议 |
|----|---------|----------|----------|
| 应用层 | 5-7 | 应用通信 | HTTP, DNS, SSH, TLS |
| 传输层 | 4 | 端到端通信 | TCP, UDP |
| 网络层 | 3 | 路由寻址 | IP, ICMP |
| 网络接口层 | 1-2 | 物理传输 | 以太网, WiFi |

## 数据封装过程（发送方视角）

```
应用层数据 (HTTP Request)
    ↓ 添加 TCP 头部
TCP 段 (源端口 + 目的端口 + 序号 + ...)
    ↓ 添加 IP 头部
IP 包 (源IP + 目的IP + TTL + ...)
    ↓ 添加 以太网头部 + 尾部
以太网帧 (源MAC + 目的MAC + 类型 + FCS)
    ↓ 转为比特流
物理层传输
```

接收方逐层**解封装**，每层剥离对应头部，最终得到原始数据。

## 关键概念

### 协议 = 通信的"语言规则"
双方必须遵守同一套规则才能通信，类似人类语言。

### 封装 Encapsulation
每层为上层数据添加自己的头部信息。  
eg: TCP 头部包含端口号，IP 头部包含 IP 地址，以太网头部包含 MAC 地址。

### 对等通信
逻辑上，每一层只与对端的同一层"对话"。  
eg: HTTP 客户端和 HTTP 服务器之间的对话，底层细节对它们透明。

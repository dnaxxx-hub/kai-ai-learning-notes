## 1. 结构化剪枝（Structured Pruning）

### 1.1 为什么比非结构化剪枝更适合LLM

| 特性 | 结构化剪枝 | 非结构化剪枝 |
|------|------------|--------------|
| 计算开销 | 标准稠密矩阵乘法 | 需要稀疏矩阵乘法库（spMM） |
| 内存效率 | 直接减少矩阵维度 | 索引开销大 |
| 硬件友好性 | 兼容GPU/TPU标准引擎 | 需要稀疏硬件支持 |
| 部署难度 | 低（ONNX/TensorRT原生支持） | 高（需稀疏算子） |
| 推理速度 | 线性加速（层数减少） | 非线性（受硬件限制） |

**核心优势**：LLM 的大规模矩阵运算（Attention 8x8, FFN 1200x4000）在结构化剪枝下可直接减少维度，无需稀疏计算库，在标准 GPU 上获得天然加速。

### 1.2 常见剪枝方法

#### 剪掉注意力头（Head Pruning）
- **操作**：移除最不重要的注意力头
- **指标**：基于注意力输出的范数 $\|Attention_i\|_F$ 或梯度幅度
- **剪枝比**：通常 10-30%，保持剩余头的权重不变
- **精度影响**：较小（注意力头冗余度高）

#### 剪掉FFN神经元
- **操作**：移除 FFN 层的神经元
- **指标**：$\|W_{in}W_{out}\|_F$ 或激活值的方差
- **剪枝比**：10-50%（逐层）
- **精度影响**：中等（需保留关键神经元）

#### 剪掉整个层（Layer Pruning）
- **操作**：移除整个 Transformer 层
- **指标**：层贡献损失（Layer-wise impact assessment）
- **剪枝比**：20-40%（早期层 > 晚期层）
- **精度影响**：中等（可被蒸馏补偿）

### 1.3 SparseGPT：基于OBS的一步剪枝

**基本原理**：将剪枝建模为最优脑外科（OBS）问题，无需微调。

```
算法：SparseGPT
输入：LLM 权重 W, 目标稀疏度 sparsity
输出：稀疏权重 W'

for 每个层 W in 模型:
    1. 计算 O = W @ A (前向激活 A)
    2. 计算 OBS 矩阵 F = diag(||O||_2 / ||W||_2^2)
    3. 求解 F^{-1} = inv(F) 的最优 F 矩阵
    4. W' = W - ΔW, 其中 ΔW = argmin||O - W'@A||_F^2
    5. 剪枝比 = 1 - ||W'||_0 / ||W||_0
```

**关键特性**：
- 基于二阶近似，不改变激活值
- 逐层精确匹配精度损失
- 无需梯度，一次前向传播完成
- **精度损失**：<1%（GPT-2 Base）

### 1.4 Wanda：Weight-Activation Amplitude

**基本原理**：按权重与激活值的乘积排序剪枝。

```
算法：Wanda
输入：模型参数 W, 层激活 A_batch
输出：剪枝后权重 W'

1. 计算重要性分数 S_{ij} = |(W[i,:] @ A[j,:])|
2. 按 S 降序排序所有权重
3. 剪掉排序靠后的权重（阈值 k）
4. W'[重要] = W[重要], W'[不重要] = 0

// 重新缩放保留的权重
scale = 1 / sqrt(sum(S[i,:] for i in 保留) / num_keep)
W'[重要] = W'[重要] * scale
```

**关键特性**：
- **剪枝策略**：$\text{importance}(w_i, a) = |w_i \cdot a|$
- **剪枝率**：可达 30-50%
- **精度损失**：<2%（无需 retraining）
- **推理加速**：2-4x（在稀疏硬件上）
- **内存节省**：15-25%（权重压缩）

## 2. 非结构化剪枝（Unstructured Pruning）

### 2.1 基础概念

| 特性 | 非结构化稀疏 | 结构化稀疏 |
|------|--------------|--------------|
| 稀疏模式 | 任意权重置零 | 按块/通道规律稀疏 |
| 精度损失 | 更小（逐权重） | 较大（结构化限制） |
| 硬件需求 | 稀疏矩阵乘法硬件 | 标准稠密硬件 |
| 内存占用 | 权重 + 索引 | 仅权重/2^sparsity |
| 推理加速 | 依赖硬件加速引擎 | 标准 GPU 加速 |

**精度优势**：非结构化稀疏允许更精细的剪枝粒度，理论上可获得更高压缩率。

### 2.2 非结构化 + 量化的协同效应

```
压缩管道：非结构化稀疏 + INT4量化
=================================

层内存占用 = (参数数 × sparsity) / 2^bits

例子：Llama-2-7B

| 技术 | 内存占用 | 压缩率 |
|------|----------|--------|
| FP16 稠密 | 14GB | 1x |
| INT4 权重 | 7GB | 2x |
| INT4 + 30% 非结构化稀疏 | 4GB | 3.5x |

注：INT4 + 稀疏的加速来自：
1. 权重本身量化（2x）
2. 非稀疏权重零值跳过计算（加速取决于硬件稀疏支持）
```

### 2.3 NVIDIA Ampere 稀疏架构

**2:4 结构化稀疏机制**：
- 每个计算块（tile）包含 2 个稠密子块
- 每个子块内 50% 权重硬件强制置零
- 实际稀疏度 = 2 x 50% = 50%

```
计算 tile: 64x64 (NVIDIA Ampere)
┌──────────────────────────────────┐
│ [稠密块1] [零位块1]               │
│ 32×32     32×32                   │
│ 非零权重           全零             │
├──────────────────────────────────┤
│ [稠密块2] [零位块2]               │
│ 32×32     32×32                   │
│ 非零权重           全零             │
└──────────────────────────────────┘

结果：标准矩阵乘法引擎，仅计算稠密子块
性能：标准 FP16 带宽的 2x（50% 计算跳过）
```

**实际加速**：
- 在 V100/A100 上，稀疏引擎比稠密引擎加速 1.5-2x
- 稀疏权重不增加显存占用（零值不占带宽）

## 3. 知识蒸馏（Knowledge Distillation）

### 3.1 三种蒸馏方式

#### 3.1.1 黑盒蒸馏（Black-box Distillation）

**流程**：
```
Teacher 大模型生成数据 → Student 小模型微调
   ↓
生成训练数据（prompt → completion）
   ↓
Student 在数据上 SFT
   ↓
精度恢复：80-90% of 原始教师
```

**代表性工作**：
- **Alpaca**：Vicuna 风格，用开源模型蒸馏 Llama
- **Lima**：1000 条数据即可匹配 LoRA 微调

**数据生成技巧**：
- 使用高置信度样本（Teacher 概率 > 0.9）
- 多样性采样（避免重复分布）
- 困难样本优先（高熵 Teacher 输出）

#### 3.1.2 白盒蒸馏（Soft Label Distillation）

**原理**：对齐 Teacher 的 logits 分布，而非仅硬标签。

```
损失函数：KL(P_teacher || P_student)

P_teacher(T, Y) = softmax(Temperature × Z_T)[Y]
P_student(T, Y) = softmax(Temperature × Z_S)[Y]

温度缩放：T=3-10（软化分布）
loss = -sum(P_teacher × log(P_student))

等价：||Z_T - Z_S||^2 (均方误差近似)
```

**温度 T 的作用**：
| T 值 | 分布软化程度 | 蒸馏收益 |
|------|--------------|----------|
| 1.0 | 无软化 | 仅训练硬标签 |
| 3.0 | 适度软化 | 标准蒸馏 |
| 10.0 | 高软化 | 蒸馏关系知识 |

**精度收益**：
- 黑盒蒸馏：Student 达 Teacher 的 80-85%
- 白盒蒸馏：Student 达 Teacher 的 90-95%（关系知识保留）

#### 3.1.3 特征蒸馏（Feature Matching）

**原理**：对齐 Teacher 的中间层表示。

```
loss = λ1 * KL_logits + λ2 * KL_hidden

KL_hidden = ||h_T(i) - h_S(i)||_2^2
其中 i ∈ {attention, ffn, MLP}

优势：
- 保留中间表示的语义
- Student 学到 Teacher 的特征提取能力
- 精度优于单纯白盒蒸馏
```

### 3.2 LIMA 原则：数据质量 > 数量

**Lima 实验结论**（Dai et al., 2022）：

| 数据量 | 质量 | 精度（相对于 Teacher） |
|--------|------|----------------------|
| 1000   | 低   | 65%                  |
| 10,000 | 低   | 70%                  |
| 1000   | 高   | 78%                  |
| 10,000 | 高   | 85%                  |

**高质量数据标准**：
1. **多样性**：不同 domain，避免过拟合
2. **Teacher 置信度**：高熵样本优先
3. **Prompt 覆盖度**：多任务类型
4. **去重**：避免重复样本

### 3.3 组合压缩管道

```
最优压缩流水线：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1: 蒸馏（Teacher 框架）
  - Teacher: Llama-70B
  - Student: Llama-13B
  - 蒸馏方式：黑盒 + 白盒混合
  - 精度恢复：85-90%

Step 2: 剪枝（Wanda/SparseGPT）
  - Wanda 剪枝到 30% 稀疏
  - 精度损失：<2%
  - 总精度：83-88% of Teacher

Step 3: 量化（AWQ/GPTQ）
  - AWQ 量化到 INT4
  - GPTQ 量化到 INT4/INT8
  - 精度损失：<0.5%

最终结果：
  - 精度：78-85% of Original Teacher
  - 内存：70B 原模型 4GB, 13B 量化 + 稀疏 0.75GB
  - 压缩比：~5x
  - 推理速度：3-4x（量化 + 稀疏引擎）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 4. MoE 路由优化（Mixture of Experts）

### 4.1 MoE 的推理挑战

**Mixtral 8×7B 架构解析**：
- 8 个专家层（总参数 47B 权重）
- 每前向激活 2 个专家
- **专家内存需求**：47B 参数全部驻留内存

```
推理时间 = 所有专家前向 / 每专家并行度 + 路由开销
         = O(总专家数/批处理) + O(sparsity log(专家))

关键矛盾：
- 参数效率 = 47B / 24B 激活（2 个专家）
- 内存占用 = 47B（全量加载）
- 加速比 = 2（每个 forward 验证 2 个 token）
```

**路由不均衡问题**：
- 部分专家过载（利用率 >120%）
- 部分专家闲置（利用率 <5%）
- 导致实际吞吐低于理论 2x

### 4.2 Expert Balancing 损失函数

#### 传统的 Load Balancing Loss

```
loss_lb = α × sum_k N_k / N + β × KL(P_k || target)

N_k = expert k 的样本数
N = 总样本数
P_k = 专家 k 的激活概率分布

局限性：
- 最小化激活频率，但不考虑梯度
- 可能移除高价值专家
```

#### Z-loss：零中心激活平衡

```
Z-loss = sum_k ((N_k - N/target)^2) / N^2

目标：||N||_2 = N/√M（二阶矩平衡）
优势：
- 惩罚方差而非均值
- 保持专家利用率接近
- 对异常值更鲁棒
```

#### Sinkhorn 平衡

```
sinkhorn_loss = KL(softmax(αN) || uniform)

等价于：
assign_i = softmax(α × expert_scores[i])

优势：
- 软分配（softmax）而非硬分配
- 梯度流畅
- 自动负载均衡
```

**参数调优**：
| Loss | α 范围 | 平衡指标 | 精度损失 |
|------|--------|----------|----------|
| Z-loss | 1-10 | 0.85-0.95 CV | 0-1% |
| Sinkhorn | 0.5-5 | 0.9-0.98 CV | 1-2% |

### 4.3 MegaBlocks：Dropless 融合

**问题**：MoE 层的每个专家需独立 dropout，浪费计算。

**解决方案**：共享 dropout 掩码。

```
传统 MoE 层：
  For k in experts:
    h_k = MLP_k(dropout(x))  # 每个专家独立 dropout

MegaBlocks：
  mask = dropout(x)
  For k in experts:
    h_k = MLP_k(mask * x)  # 共享 dropout
    merged = sum_k h_k  # 无 dropout 开销
```

**优势**：
- 消除 MoE 层的 dropout 计算
- 激活值融合更平滑
- 精度提升 0.5-1%（对比标准 MoE）

## 5. 投机解码（Speculative Decoding）

### 5.1 加速原理详解

**标准自回归解码**：
```
每个 token 需要 1 次 forward：
token_1 ← Forward(Target)
token_2 ← Forward(Target, token_1)
token_3 ← Forward(Target, token_1, token_2)
...
总时间 = N × T_forward（N 个 token, T 为 forward 时间）
```

**投机解码流程**：
```
Step 1: Draft Model 生成 K 个候选（并行，免费）
       d_1, d_2, ..., d_K ← Forward(Draft)

Step 2: Target Model 并行验证 K 个候选
       验证概率 p_i = p_target(d_i | token_0)

Step 3: 接受/拒绝候选
       Accept if d_i ~ Target 分布
       加速比 = 1 / Acceptance_Rate
```

**接受率公式**：
```
AR = (1/K) × sum_{i=1}^K min(p_draft(d_i), p_target(d_i)) / p_target(d_i)

理想情况（p_draft = p_target）：AR = 1
实际加速比 = 1 + (K-1) × AR
            ≈ K × AR（当 AR 高时）
```

### 5.2 影响因素分析

**接受率与分布匹配**：
| 模型对 | 分布差异 | 接受率 | 加速比 |
|--------|----------|--------|--------|
| Draft = Target 早期 | >1.5 层 | ~0.6-0.8 | 1.5-2.0× |
| Draft = 小模型 7B | 较大 | ~0.3-0.5 | 1.2-1.5× |
| Draft = 1B 小模型 | 大 | ~0.1-0.2 | 1.05-1.1× |

**任务难度影响**：
- 简单任务（填空）：接受率高 >0.7，加速比接近 K
- 复杂任务（推理）：接受率低 <0.3，加速比下降
- 创意写作：接受率中等 0.4-0.5

### 5.3 常见实现方式

#### Self-Speculative：投机层

```
架构：
┌────────────────────┐
│ Target LLM（全层）  │
└────────────────────┘
        ↓
┌────────────────────┐
│ Draft（前 N 层）    │  ← 用早期层作为草稿
│ 例：12 层模型用前 4 层 │
└────────────────────┘

优势：
- 无需额外模型
- 草稿质量高（同分布）
- 内存效率高
```

#### Medusa：多 head 并行

```
架构：
Target LLM + [M 个 Medusa Head]

每个 head：
  - 独立前馈网络（2-4 层 MLP）
  - 共享输入 hidden
  - 并发输出 K 个候选

参数增加：
  Total_params = BaseParams + M × Small_MLP_params
  例：Llama-7B + 4 heads = +0.05B 参数
```

**加速比**：
| K (Medusa heads) | 接受率 | 实际加速 |
|------------------|--------|----------|
| K=2 | 0.7 | 2.4× |
| K=4 | 0.55 | 3.1× |
| K=8 | 0.45 | 3.6× |

#### Eagle：隐状态作为草稿

```
架构：
┌─────────────────────────────────┐
│ Input → Target Hidden State      │
│          ↓                       │
│   (作为草稿模型的输入)          │
│          ↓                       │
│   Target Early Layers (Draft)    │
│          ↓                       │
│   候选 token 验证 → 接受/拒绝    │
└─────────────────────────────────┘

原理：
  - 草稿模型不显式参数化
  - 重用 Target 的 hidden state
  - 减少内存带宽（不重复传输）

优势：
  - 无需额外参数
  - 草稿质量 > Medusa
  - 加速比接近 3-3.5×
```

### 5.4 实际性能

**基准测试**（40K context, 8K 温度）：

| 模型 | 方法 | 接受率 | 吞吐 (token/s) | 加速比 |
|------|------|--------|----------------|--------|
| Llama-7B | Standard | - | 28 | 1.0× |
| Llama-7B | Eagle K=4 | 0.52 | 102 | 3.6× |
| Llama-7B | Medusa K=4 | 0.55 | 98 | 3.5× |
| Mixtral-8x7B | Standard | - | 45 | 1.0× |
| Mixtral-8x7B | Self-spec | 0.38 | 125 | 2.8× |

**内存节省**：
```
在推理框架：
- 标准解码：4×每 token 内存带宽（自回归）
- 投机解码：3×每 token 带宽（并行验证）

例：Llama-7B 推理 32B tokens
  标准：~200GB 带宽
  投机：~150GB 带宽
  节省：~25% 显存带宽
```

```
最终统计（以Mixtral-8x7B 为例）：

| 内存占用 | 71GB | 6.5GB | -91% |
| 推理吞吐 | 50 token/s | 200 token/s | +300% |
| 精度（MMLU） | 67.0 | 58.5 | -8.5 |
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 6.2 精度损失与压缩率权衡

**实验数据**（基于 Llama-70B）：

| 压缩阶段 | 方法 | 压缩率 | 精度损失 |
|----------|------|--------|----------|
| 初始 | FP16 | 100% | 0% |
| 蒸馏到 13B | 黑盒 | 5.4× | 12-15% |
| +剪枝 30% | Wanda | 6.5× | 17-20% |
| +量化 INT4 | AWQ | 7.5× | 18-22% |
| +非结构化稀疏 50% | 混合 | 15× | 22-26% |
| 边界 | 3-4 bits/param | 10× | >40%（不推荐） |

**关键观察**：
- **前 3-4×**：精度损失低（<10%）
- **4-6×**：梯度损失（10-20%）
- **>6×**：精度急剧下降（>20%）
- **10×+**：仅保留基本能力（3-4 bits/参量）

### 6.3 LLM 压缩的实际边界

**理论下限**：
- **香农定理**：信息熵下限 H ≈ 1-2 bits/token
- **实际下限**：3-4 bits/param（~10x 压缩）

**物理限制**：
```
每 token 的带宽限制：
├── 显存带宽：~1TB/s (H100)
├── 模型权重：~40B params × 4 bits = 160GB
├── 激活大小：~24B × 4 bits = 96GB
└── 每 1s 处理 tokens: (1TB/s) / (160GB+96GB) ≈ 4.5K tokens/s

量化后：
├── INT4 权重：带宽减少 2x
├── 稀疏权重：计算减少 1.5-2x
└── 投机解码：减少 串行 转发次数
```

**实际边界**：
| bits/param | 压缩比 | 精度（MMLU） | 推荐场景 |
|------------|--------|--------------|----------|
| 16 (FP16) | 1x | 67.0 | 生产环境 |
| 8 (INT8) | 2x | 65.5 | 边缘部署 |
| 4 (INT4) | 4x | 62.0 | 移动设备 |
| 2 (混合) | 8x | 55.0 | 快速推理 |
| 1 (极端) | 16x | 40.0 | 原型探索 |

**结论**：
- **生产推荐**：FP16/INT8 + 结构化剪枝
- **极限制**：INT4 + 非结构化稀疏 + 投机解码
- **精度红线**：3-4 bits/param 后显著损失

## 附录：对比表格

### 压缩方法速查

| 方法 | 压缩率 | 精度损失 | 推理加速 | 部署难度 |
|------|--------|----------|----------|----------|
| **结构化剪枝** | 30-50% 参数 | <2% | 1-2× | 低 |
| **非结构化稀疏** | 50-90% 参数 | <1% | 1.5-2× | 高（需硬件） |
| **知识蒸馏** | 8-10× 大小 | 10-20% | 1× | 低 |
| **MoE 路由优化** | 2-4× 吞吐 | <2% | 2-3× | 中 |
| **投机解码** | 1× 大小 | 0% | 2-3.5× | 低 |
| **AWQ 量化** | 2-4× 内存 | <1% | 1× | 低 |

### 最佳实践总结

1. **生产部署**：
   - `蒸馏 → 结构化剪枝 → INT8/FP8 量化 → vLLM 推理`
   - 精度损失 <5%，内存减少 70-80%

2. **极限制**：
   - `黑盒蒸馏 → Wanda 剪枝 → INT4 → TensorRT 稀疏`
   - 内存减少 90%+，加速 3-4×

3. **边缘设备**：
   - `量化 → 剪枝 → 投机解码`
   - 优先用投机解码加速（无需额外硬件）

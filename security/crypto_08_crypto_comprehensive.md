# 密码学综合实战与前沿主题

## 1. 散列函数深入

### 1.1 SHA-256：Merkle-Damgård 构造

SHA-256 基于 **Merkle-Damgård** 构造，核心思路：

```
消息 → 填充（padding）→ 分块（512-bit blocks）→ 迭代压缩
                                   ↓
                           初始向量 IV (8×32-bit)
                                   ↓
                 Block₁ → 压缩函数 f → 中间状态 → Block₂ → f → ... → 最终哈希
```

**填充规则：**
1. 末尾加 `1` bit
2. 加 `0` bits 直到长度 ≡ 448 mod 512
3. 追加原始消息长度的 64-bit big-endian 表示

**压缩函数 f（64 轮）：**
```
输入：当前 256-bit 状态 (A₀B₀C₀D₀E₀F₀G₀H₀) + 512-bit 消息块
输出：新的 256-bit 状态

每轮使用：
- 6 个逻辑函数：Ch, Maj, Σ₀, Σ₁, σ₀, σ₁
- 8 个工作变量 A-H
- 64 个常数 K₀...K₆₃（前 64 个质数的立方根小数部分）
- 消息调度 Wₜ：前 16 轮直接取消息字，后 48 轮由前导字 σ₀/σ₁ 计算
```

**核心轮函数：**
```
T₁ = H + Σ₁(E) + Ch(E,F,G) + Kₜ + Wₜ
T₂ = Σ₀(A) + Maj(A,B,C)
H = G; G = F; F = E; E = D + T₁
D = C; C = B; B = A; A = T₁ + T₂
```

### 1.2 SHA-3 (Keccak)：海绵结构

与 Merkle-Damgård 完全不同的 **Sponge Construction**：

```
                ┌─────────────────────────────────────┐
吸收阶段：   消息块₁ → 消息块₂ → ... → 消息块ₙ →   挤压阶段：输出块₁ → 输出块₂ → ...
                XOR          XOR         XOR          ↑            ↑
                ↓             ↓           ↓           └──── 反复应用 f ────┘
           ┌────┴────┐  ┌────┴────┐     ┌────┴────┐
           │state 1600│→│state 1600│→...→│state 1600│────→ ... →
           └─────────┘  └─────────┘     └─────────┘
                 f(置换)     f(置换)        f(置换)       f(置换) ...
```

- **状态大小**：1600 bits (5×5×64 bit words)
- **海绵容量**：c bits（不可直接访问的内部容量）
- **比特率**：r bits（每轮吸收/挤压的块大小），r + c = 1600
- **Keccak-f[1600] 置换**：24 轮，每轮包含 θ, ρ, π, χ, ι 五步

**安全性参数（SHA-3）：**
| 算法 | 输出长度 | 容量 c | 比特率 r | 安全级别 |
|------|---------|--------|---------|---------|
| SHA3-256 | 256 | 512 | 1088 | 128-bit |
| SHA3-512 | 512 | 1024 | 576 | 256-bit |

### 1.3 HMAC（基于哈希的消息认证码）

```
HMAC(K, m) = H((K' ⊕ opad) || H((K' ⊕ ipad) || m))

其中：
- K' = 密钥（若 > 块长则先哈希，否则原样）
- ipad = 0x36 重复块长次（内填充）
- opad = 0x5c 重复块长次（外填充）
- 双重哈希防止长度扩展攻击
```

### 1.4 PBKDF2（密码存储）

```
DK = PBKDF2(PRF, Password, Salt, c, dkLen)

其中：
- PRF = HMAC-SHA256（通常是）
- Salt = 随机生成的盐（16+ bytes）
- c = 迭代次数（2024年推荐 ≥ 600,000）
- dkLen = 输出密钥长度

原理：DK = T₁ || T₂ || ... || Tₙ
      Tᵢ = F(Password, Salt, i, c)
      F = U₁ ⊕ U₂ ⊕ ... ⊕ U_c
      U₁ = PRF(Password, Salt || INT(i))
      U₂ = PRF(Password, U₁)
      ...以此类推
```

**现代替代方案（更推荐）：**
- **bcrypt**：Blowfish 密码，内置盐，抗 GPU/FPGA
- **scrypt**：内存困难（memory-hard），阻止 ASIC 并行
- **Argon2**（2015 年密码哈希竞赛冠军）：三种变体 Argon2d/i/id

### 1.5 生日攻击

**核心原理**：找碰撞只需 `2^(n/2)` 次尝试（而非 `2^n`）

```
问题：n 个球随机放入 N 个箱子，存在碰撞的概率 ≈ 50% 需要 √N 个球

对于 n-bit 哈希：找一对碰撞只需要 ≈ 2^(n/2) 次计算
  - SHA-256 (256-bit)：目标 2^128 次（目前不可行）
  - SHA-1 (160-bit)：目标 2^80 次（2017 年 Google 成功碰撞）
  - MD5 (128-bit)：目标 2^64 次（2004 年攻破）
```

## 2. 后量子密码学总览

### 2.1 量子威胁

Shor 算法可在多项式时间内破解：
- **RSA**（大整数分解）
- **ECDH / ECDSA**（椭圆曲线离散对数）
- **DSA**（有限域离散对数）

Grover 算法将对称密钥强度减半：
- AES-128 → 量子 2^64（仍然安全，优于 Shor 威胁）

### 2.2 NIST 最终标准（2024）——正式发布

| 标准 | 协议 | 基础数学问题 | 公钥大小 | 签名大小 | 特点 |
|------|------|------------|---------|---------|------|
| **ML-KEM** (FIPS 203) | KEM | 格上的 Module LWE | 800-1568 B | — | 基础 KEM 置换 |
| **ML-DSA** (FIPS 204) | 签名 | 格上的 Module LWE | 1312-2592 B | 2420-4595 B | 原 Dilithium |
| **SLH-DSA** (FIPS 205) | 签名 | 哈希碰撞(SPHINCS+) | 32-64 B | ~17-49 KB | 保守安全，小公钥大签名 |
| **FN-DSA** (FIPS 206) | 签名 | 格上 NTRU | 897-2304 B | 666-1280 B | 最紧凑签名 |

### 2.3 格密码（Lattice-Based Crypto）

**核心困难问题：**
- **SIS** (Short Integer Solution)：找到短向量
- **LWE** (Learning With Errors)：带误差解线性方程组
- **Module LWE/SIS**：在环上的模块版本（ML-KEM/ML-DSA 使用）

**ML-KEM (Kyber) 核心流程：**

```
密钥生成：
  1. 随机种子 ρ, σ
  2. A ← ExpandA(ρ)  （均匀随机矩阵）
  3. (s, e) ← SampleCBD(σ)  （小误差向量，中心二项分布）
  4. t = As + e
  5. 公钥 = (t, ρ)，私钥 = s

封装 (Encaps)：
  1. 解析公钥 (t, ρ)，重算 A
  2. 生成随机 (s', e', e'')
  3. u = Aᵀs' + e'
  4. v = tᵀs' + e'' + Compress(m)
  5. 返回 (K, c=(u, v))

解封装 (Decaps)：
  1. m' = Decompress(v - sᵀu)
  2. K' = KDF(m' || c)
```

### 2.4 哈希签名（Hash-Based Signatures）

**SPHINCS+（SLH-DSA）：**
- 最保守的选择，仅依赖哈希函数的抗碰撞性
- **缺点**：签名大（~17-49 KB），签名慢
- **优点**：安全性假设最弱，量子抗性最可信

原理：Merkle 树 + 一次性签名（WOTS+ / FORS）

```
私钥：大量随机种子（对应树中叶子的私钥）
签名：验证路径 + OTS 签名 → 接收方能从叶子证实到根公钥
```

### 2.5 其他后量子方向

| 类型 | 代表算法 | 优缺点 |
|------|---------|--------|
| **格密码** | ML-KEM, ML-DSA, FN-DSA | 高效、平衡，NIST 首选 |
| **哈希签名** | SLH-DSA (SPHINCS+) | 最保守安全，大签名 |
| **多变量密码** | Rainbow, GeMSS | 签名很短，公钥大（NIST 第4轮后未入选） |
| **编码密码** | Classic McEliece | 极小密文，但公钥极大（~1MB），入选第4轮 |
| **超奇异同源** | SIKE | 密钥最小，但 2022 年被代数攻击破解（弃用） |
| **ISOGENY** | CSIDH | 后量子密钥交换，仍在研究 |

## 3. 可验证延迟函数（VDF）

### 3.1 定义与性质

**VDF** 是一个函数 `f: X → Y`，满足：
1. **顺序性**：必须串行计算，无法并行加速
2. **高效验证**：结果可被快速验证（远快于计算）
3. **唯一性**：给定输入有唯一输出

**形式化定义：** 三元组 `(Setup, Eval, Verify)`

### 3.2 VDF 应用场景

**随机数信标（Randomness Beacon）：**
```
1. 参与者提交对随机种子的承诺
2. 所有承诺发布后，计算 VDF(种子) → 随机输出
3. VDF 的延迟确保：在提交结束前，无人能预测结果
4. 所有参与者均可验证（开源验证）
```

**共识协议防抢先（MEV 防护）：**
```
在区块链中，交易排序权需通过 VDF 决定：
- 验证者生成随机数 → 计算 VDF → 期间不可预测排序
- 防止 MEV 机器人"抢跑"普通交易
```

**可验证的延迟加密：**
```
发送方：使用 VDF(t) 作为密钥加密，设定延迟时间 t
接收方：必须串行计算 VDF(t) 才能解密
任何人：可用开放验证密钥验证解密密钥的正确性
```

### 3.3 Wesolowski VDF

基于 **群上的重复平方**（Repeated Squaring）：

**Setup(λ, T)**：生成 RSA 群 `(N, g)`，其中 `N = pq`（未知阶）
  - 隐藏 N 的阶（即 φ(N)），使重复平方不可加速

**Eval(N, g, T)**：
1. 计算 `y = g^(2^T) mod N`（串行重复平方 T 次）
2. 生成证明 π：
   - 随机挑战 `l ← Hash(g, y, T)`
   - 计算 `π = g^(⌊2^T / l⌋) mod N`（即 g^(2^T mod l) 前取整除法）

**Verify(N, g, y, T, π)**：
1. 计算 `l = Hash(g, y, T)`
2. 验证 `π^l · g^(2^T mod l) ≡ y (mod N)`
   - 即：`π^l · g^(r) == y` 其中 r = 2^T mod l
   - 如果正确，π 的 l 次幂乘以余数次幂等于 y

**安全性**：基于自适应随机谕言模型 + RSA 假设

### 3.4 Pietrzak VDF

类似 Wesolowski 但使用递归证明结构：

**核心思想**：使用二分法将 T 步计算转换为 log T 层的验证链

```
对于 T = T₁ + T₂:
  计算中间状态 y₁ = g^(2^T₁)
  则 y = y₁^(2^T₂) = g^(2^(T₁+T₂))

递归验证：
  挑战 r ← Hash(g, y₁, T₁)
  验证 (g^r · y₁)^(2^T₂) == y₁^r · y
```

**对比 Wesolowski vs Pietrzak：**

| 特性 | Wesolowski | Pietrzak |
|------|-----------|----------|
| 证明大小 | O(1) - 单个群元素 | O(log T) |
| 验证时间 | O(log T) 模乘 | O(log T) 双线性对 |
| 安全性假设 | RSA + ROM | RSA + ROM |
| 适用场景 | 小证明优先 | 平衡证明/验证 |

## 4. BLS 签名（Boneh-Lynn-Shacham）

### 4.1 双线性对（Pairing）

**定义**：三个群 G₁, G₂, Gₜ，双线性映射 `e: G₁ × G₂ → Gₜ`

**核心性质：**
```
∀ a, b ∈ ℤ, g₁ ∈ G₁, g₂ ∈ G₂:
  e(g₁^a, g₂^b) = e(g₁, g₂)^ab

也即：e(a·P, b·Q) = e(P, Q)^ab  （加法群写法）
```

**常用配对类型：**
- **BLS12-381**：G₁ (48 B) + G₂ (96 B)，128-bit 安全
- **BN254**：Barreto-Naehrig 曲线，约 100-bit 安全
- **BLS48**：更高安全

### 4.2 BLS 签名方案

**密钥生成：**
- 私钥 `sk = x`（随机标量）
- 公钥 `pk = g₂^x`（G₂ 中的元素）

**签名：**
- `σ = H(m)^x`（将消息哈希到 G₁，再用私钥标量乘）

**验证：**
- 验证 `e(σ, g₂) == e(H(m), pk)`
- 即：`e(H(m)^x, g₂) = e(H(m), g₂)^x = e(H(m), g₂^x)`

### 4.3 聚合签名

**BLS 最强大的特性**：多个签名可以聚合成一个！

**基本聚合：**
```
给定 n 个签名 σᵢ，分别对应消息 mᵢ：
  聚合签名 σ_agg = σ₁ · σ₂ · ... · σₙ = H(m₁)^x₁ · H(m₂)^x₂ · ... · H(mₙ)^xₙ

验证：e(σ_agg, g₂) == ∏ e(H(mᵢ), pkᵢ)
```
只需 **1 个聚合签名 + n 个公钥 + n 个消息**，验证需要 n 个配对，远小于 n 个单独验证。

**多重签名（同消息聚合）：**
```
对同一消息 m，n 个签名者：
  σ_agg = ∏ H(m)^{xᵢ} = H(m)^{∑xᵢ}
  
验证：e(σ_agg, g₂) == e(H(m), ∏ pkᵢ)
```
只需 **1 个配对** 验证！3 个元素（聚合签名 + 聚合公钥 + 消息）。

### 4.4 Eth2.0 信标链中的 BLS

**为什么用 BLS？**
- 验证者数量巨大（≥ 32 ETH 成为验证者，人数 ~50 万）
- 每个 epoch 需要收集所有验证者的投票（见证）
- BLS 聚合将 **50 万签名 → 1 个签名**（96 bytes）

**Eth2.0 具体使用：**
- 曲线：**BLS12-381**
- 每个验证者对信标头签名作为见证
- 区块提议者将见证聚合成单一签名
- 聚合后大小恒定（96 bytes），与验证者数量无关

**Rogue Key 攻击防御：** 要求签名者证明知道私钥（PoPK），或使用 "proof-of-possession"

### 4.5 BLS vs ECDSA 签名大小对比

| 特性 | BLS (BLS12-381) | ECDSA (secp256k1) | Schnorr (secp256k1) |
|-----|----------------|-------------------|-------------------|
| 单个签名 | 48 B (G₁) | 64-72 B | 64 B |
| 聚合 n 个签名 | 48 B | n × 64 B | 64 B (需交互) |
| 验证 n 个签名 | n 个配对 | n 个验证 | 批验证 |
| 确定性 | ✅ | ❌ (需随机k) | ✅ |

### 5.3 简化 SHA-256 实现

```python
# 核心思路：用 Python 实现 SHA-256 压缩函数的简化版本
# 只保留算法骨架，便于理解内部结构

# SHA-256 常量（前 64 个质数的立方根小数部分前 32-bit）
K = [0x428a2f98, 0x71374491, ..., 0xc67178f2]

# 初始化向量
IV = [0x6a09e667, 0xbb67ae85, 0x3c6ef372, 0xa54ff53a,
      0x510e527f, 0x9b05688c, 0x1f83d9ab, 0x5be0cd19]

# 压缩函数核心：Ch, Maj, Σ₀, Σ₁, σ₀, σ₁
def Ch(x, y, z): return (x & y) ^ (~x & z)
def Maj(x, y, z): return (x & y) ^ (x & z) ^ (y & z)
def ROTR(x, n): return (x >> n) | (x << (32 - n)) & 0xffffffff
def Σ0(x): return ROTR(x, 2) ^ ROTR(x, 13) ^ ROTR(x, 22)
def Σ1(x): return ROTR(x, 6) ^ ROTR(x, 11) ^ ROTR(x, 25)
def σ0(x): return ROTR(x, 7) ^ ROTR(x, 18) ^ (x >> 3)
def σ1(x): return ROTR(x, 17) ^ ROTR(x, 19) ^ (x >> 10)
```

### 5.4 ECDH + AES-GCM + Ed25519 握手流程

完整握手代码在配套 Python 文件中，核心流程：

```python
# === 服务端 ===
# 1. 生成长期身份密钥 (Ed25519)
sk_sign, pk_sign = generate_ed25519_keypair()

# 2. 临时 ECDH 密钥对
sk_eph, pk_eph = generate_x25519_keypair()

# 3. 发送 ServerHello (pk_eph, pk_sign), 收到 ClientHello (pk_client_eph)

# 4. ECDH 计算共享秘密
shared_secret = x25519(sk_eph, pk_client_eph)

# 5. 用 HKDF 派生会话密钥
session_key = hkdf_expand(shared_secret, b"session-key", 32)
hmac_key = hkdf_expand(shared_secret, b"hmac-key", 32)

# 6. 签名握手摘要（身份认证）
handshake_hash = sha256(pk_eph + pk_client_eph + pk_sign)
signature = ed25519_sign(sk_sign, handshake_hash)

# 7. 安全通道：AES-256-GCM
#    每条消息: Nonce(12B) || Ciphertext || Tag(16B)
```

```bash
# ===== HMAC + PBKDF2 演示 =====
# 密码: "my_secure_password"
# 盐: a8f3...9c2d
# HMAC: 4b6d...f81e
# PBKDF2(1000次): 7c2a...e4d1
# PBKDF2(100000次): f9b8...3a2c
# 
# ===== 生日攻击演示 =====
# 8-bit 哈希 (n=8): 需要 2^(8/2) = 16 次, 实际找到碰撞: 12 次
# 16-bit 哈希 (n=16): 需要 2^(16/2) = 256 次, 实际找到碰撞: 203 次
# 
# ===== VDF 概念演示 =====
# VDF(T=8): y = g^(2^8), 串行计算: 8 步
# Wesolowski 验证: ✓ (1 个证明元素)
# Pietrzak 验证: ✓ (log₂8=3 层证明)
```

## 6. 密码套件速查表

### 6.1 对称加密

| 算法 | 密钥长度 | 模式 | 特点 |
|------|---------|------|------|
| AES | 128/192/256 | GCM (首选), CBC, CTR | 标准 AES-NI 硬件加速 |
| ChaCha20 | 256 | Poly1305 (AEAD) | 无硬件加速时更快 |
| XChaCha20 | 256 | Poly1305 | 192-bit nonce，支持随机 nonce |

### 6.2 密钥交换

| 算法 | 安全强度 | 量子安全 | 性能特点 |
|------|---------|---------|---------|
| X25519 (Curve25519) | ~128-bit | ❌ | 最快，常数时间 |
| X448 | ~224-bit | ❌ | 更安全 |
| ML-KEM-512 | ~128-bit | ✅ | 后量子 |
| ML-KEM-768 | ~192-bit | ✅ | 推荐（AES-192 同级） |
| ML-KEM-1024 | ~256-bit | ✅ | 最高安全 |

### 6.3 签名算法

| 算法 | 签名大小 | 公钥大小 | 量子安全 | 特点 |
|------|---------|---------|---------|------|
| Ed25519 | 64 B | 32 B | ❌ | 现代首选 |
| ECDSA (P-256) | 64-72 B | 32-65 B | ❌ | 广泛兼容 |
| BLS (BLS12-381) | 48 B | 48-96 B | ❌ | 聚合签名 |
| ML-DSA-65 | 3309 B | 1952 B | ✅ | 后量子 |
| SLH-DSA-128s | 7856 B | 32 B | ✅ | 保守安全 |

### 6.4 散列函数

| 算法 | 输出 | 安全级别 | 结构 |
|------|------|---------|------|
| SHA-256 | 256 | 128 | Merkle-Damgård |
| SHA-512 | 512 | 256 | Merkle-Damgård |
| SHA3-256 | 256 | 128 | Sponge (Keccak) |
| BLAKE2b | 任意 | 128-256 | HAIFA, 比 SHA-3 更快 |
| BLAKE3 | 任意 | 128 | 树形结构, 并行化 |

## 核心问题

```
你在网上输入密码 → 怎么保证中间没有人能看到？
你下载一个文件 → 怎么保证它没有被篡改过？
```

## 对称加密

```python
# 加密和解密用同一个"密钥"

# 就好像:
# 你有一个保险箱，用钥匙Z锁上
# 寄给对方，对方用同一把钥匙Z打开

# 代表算法:
# AES (Advanced Encryption Standard) — 当前的对称加密标准
# DES (Data Encryption Standard) — 旧标准，已不安全
# ChaCha20 — 移动端流行（比AES快）

# 问题: 密钥怎么安全地传给对方？
# 加密通信前，需要先安全地交换密钥
# → 这就是非对称加密要解决的问题
```

## 非对称加密

```python
# 加密和解密用不同的"密钥对"
# 公钥(Public Key): 公开的，谁都可以有
# 私钥(Private Key): 只有自己有

# 公钥加密 → 只有私钥能解密
# 私钥签名 → 只有公钥能验证

# 代表算法:
# RSA (Rivest–Shamir–Adleman) — 最经典，但越来越慢
# ECC (椭圆曲线密码学) — 更高效，替代RSA中
# Ed25519 — 现代签名算法，速度快且安全

# 工作流程:
# 1. 你用我的公钥加密消息
# 2. 只有我的私钥能解密
# 3. 中间人即使拿到公钥，也无法解密
```

## 哈希函数

```python
# 不是"加密"——而是"指纹"
#
# 输入任意长度 → 固定长度输出
# 且不可逆（无法从指纹反推原文）

# 代表:
# SHA-256 (Secure Hash Algorithm) — 256位输出
# MD5 (Message Digest 5) — 已破解，不要用

# 应用:
# - 密码存储: 存hash不存原文
# - 文件校验: 下载后检查hash是否一致
# - 区块链: 每个区块包含前一个区块的hash

# 注意: 密码不能直接存hash
# 要用 bcrypt/argon2 等"慢哈希"算法
```

## 数字签名

```python
# 目的: 证明"这个文件是你发的"

# 流程:
# 1. 对文件取hash
# 2. 用私钥对hash加密 → 得到"签名"
# 3. 发送文件 + 签名
# 4. 接收方用公钥解密签名 → 得到hash
# 5. 对接收到的文件重新取hash → 对比

# 如果hash一致 → 文件没被篡改，确认是你发的
```

## 数字证书（PKI）

```python
# 问题: 你怎么知道"这个公钥真的是百度的"？
# 答: 证书颁发机构(CA)来担保

# 证书包含:
# - 网站的公钥
# - 域名信息
# - CA的签名

# 浏览器信任CA → CA担保网站 → 网站给你看证书
# 所以你访问百度时, 浏览器自动验证证书

# 知名CA: DigiCert, Let's Encrypt（免费）, GlobalSign
```

## 对比

| 技术 | 用途 | 典型场景 |
|------|------|---------|
| AES | 对称加密 | 文件/传输加密 |
| RSA/ECC | 非对称加密 | 密钥交换/签名 |
| SHA-256 | 哈希 | 校验/指纹 |
| bcrypt | 慢哈希 | 密码存储 |
| 数字证书 | 身份验证 | HTTPS/代码签名 |

## 今日收获
- 对称加密(AES) = 一把钥匙开锁 → 快
- 非对称加密(RSA/ECC) = 公钥锁私钥开 → 安全
- 哈希 = 数据指纹（不可逆）
- 数字签名 = 私钥加密hash → 证明身份
- HTTPS = 非对称交换密钥 → 对称加密通信

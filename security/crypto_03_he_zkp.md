## 1. 同态加密 (Homomorphic Encryption, HE)

### 1.1 基本概念

**同态加密** 允许在**密文**上直接进行运算，解密后结果与在**明文**上做相同运算一致。

```
          明文域                密文域
        ┌─────────┐          ┌─────────┐
        │  m1 + m2 │  ←──→  │ E(m1)⊕E(m2) │
        │  m1 × m2 │  ←──→  │ E(m1)⊗E(m2) │
        └─────────┘          └─────────┘

E(m1) ⊕ E(m2) = E(m1 + m2)    ← 加法同态
E(m1) ⊗ E(m2) = E(m1 × m2)    ← 乘法同态
```

HE 按能力分为三个等级：

| 类型 | 支持运算 | 代表方案 | 特点 |
|------|---------|---------|------|
| **PHE** (部分同态) | 加法 **或** 乘法（一种） | RSA, Paillier, ElGamal | 效率最高，功能有限 |
| **LHE** (层次同态) | 加法和乘法（有限深度） | BGN, BV, BGV(Leveled) | 支持一定深度的电路 |
| **FHE** (全同态) | 任意加法和乘法（无限深度） | Gentry09, BGV, CKKS | 功能最强，开销巨大 |

### 1.2 RSA 乘法同态 (PHE)

RSA 加密本身就是乘法同态的：

```
加密: E(m) = m^e mod N
同态性: E(m1) · E(m2) = (m1^e)(m2^e) = (m1·m2)^e = E(m1·m2) (mod N)
```

**注意**：RSA 只有乘法同态，没有加法同态。

### 1.3 Paillier 加法同态 (PHE) ⭐ 核心实现

Paillier 于 1999 年提出，基于复合剩余类困难假设。

#### 密钥生成

```
1. 选择大素数 p, q，计算 N = p·q, λ = lcm(p-1, q-1)
2. 选择 g ∈ ℤ*_{N²}，使得 gcd(L(g^λ mod N²), N) = 1
   其中 L(x) = (x-1)/N
3. 公钥 pk = (N, g)，私钥 sk = (λ, μ)
   其中 μ = (L(g^λ mod N²))^{-1} mod N
```

#### 加密

```
c = g^m · r^N mod N²   其中 r ∈ ℤ*_N 是随机数
```

#### 解密

```
m = L(c^λ mod N²) · μ mod N
```

#### 加法同态性

```
E(m1) · E(m2) = (g^{m1}·r1^N)(g^{m2}·r2^N) mod N²
              = g^{m1+m2}·(r1·r2)^N mod N²
              = E(m1 + m2)
```

同时支持标量乘法:
```
E(m)^k = g^{m·k}·(r^k)^N = E(m·k) mod N²
```

#### 安全性

- 基于 **Decisional Composite Residuosity Assumption (DCRA)**
- 语义安全（IND-CPA）：相同明文每次加密密文不同（因随机数 r）

### 1.4 层次同态 (LHE)

#### BGN 方案 (Boneh-Goh-Nissim, 2005)

- 支持**任意多次加法 + 一次乘法**
- 使用双线性配对（pairing）实现"一次乘法"
- 应用：单层乘法电路的计算

#### Leveled BGV (Brakerski-Gentry-Vaikuntanathan, 2011)

- 支持预设深度的加法和乘法电路
- 基于 **Learning With Errors (LWE)** 困难问题
- 随着电路深度增加，密文大小增长
- 不使用 bootstrapping，而是通过**参数调节**（modulus switching）控制噪声

### 1.5 全同态 (FHE) —— Gentry 的 Bootstrapping

#### 核心思想

Gentry 在 2009 年首次提出了 FHE 的构造方法：

```
每个同态运算会在密文中引入"噪声"
┌─────────────────────────────────────────────────────┐
│  初始密文:  E(m)            噪声 = ε                 │
│  加法后:    E(m1+m2)        噪声 ≈ ε1 + ε2          │
│  乘法后:    E(m1·m2)        噪声 ≈ ε1 × ε2 (增长快) │
│  多次运算后: 噪声超过阈值 → 解密失败！               │
└─────────────────────────────────────────────────────┘

Gentry 的 key insight：如果能"刷新"密文，降低噪声，就能无限运算！
```

#### Bootstrapping 过程

```
Bootstrapping = "在密文上运行解密电路"

步骤:
1. 加密私钥: 预先公开 E(sk)
2. 对"噪声已高"的密文 c = E(m):
   - 计算 c' = Eval(Decrypt, c, E(sk))
   - 即: 在密文上运行解密算法
   
结果: c' 仍然是 E(m)，但噪声被重置到较低水平！
```

```
┌────────────────────────────────────────────────┐
│                Bootstrapping 示意               │
│                                                │
│   c = E(m)  ──── 噪声高  ────► 解密电路(密文)  │
│                                  │             │
│                     E(sk) ──────►│             │
│                                  ▼             │
│                     c' = E(m) 噪声低 ✓        │
└────────────────────────────────────────────────┘
```

#### 为什么 Bootstrapping 是突破

在 Gentry 之前，人们认为 FHE 不可能，因为：
- 乘法运算总是成倍放大噪声
- 声学论证表明噪声会不可逆地增长

Gentry 的贡献在于证明了：**如果方案可以评估自己的解密电路（bootstrappable），那么它就是全同态的**。

#### 现代 FHE 方案

| 方案 | 年份 | 基础困难问题 | 特点 |
|------|------|------------|------|
| Gentry09 | 2009 | Ideal Lattice | 开创性，效率低 |
| BGV | 2011 | LWE/RLWE | Leveled + Bootstrapping |
| FV | 2012 | RLWE | 更简洁的 noise 管理 |
| CKKS | 2017 | RLWE | 支持浮点数近似计算 |
| TFHE | 2016-2018 | LWE | 快速 Bootstrapping (<1s) |
| FHEW | 2014-2020 | LWE | 快速门级 Bootstrapping |

## 2. 零知识证明深入

### 2.1 zk-SNARKs 的 R1CS/QAP/SRS 流程

#### 核心流程总览

```
程序 → 算术电路 → R1CS → QAP → 椭圆曲线配对验证
                                  ↑
                              可信设置(SRS)
```

#### 步骤1：程序转换为算术电路

```
// 以 "我知道 x 使得 x³ + x + 5 = 35" 为例
// 即证明 x = 3

电路表示:
  sym_1 = x * x        // x²
  y     = sym_1 * x    // x³
  sym_2 = y + x        // x³ + x
  out   = sym_2 + 5    // x³ + x + 5

变量向量: v = [one, x, out, sym_1, y, sym_2]
```

#### 步骤2：R1CS (Rank-1 Constraint System)

R1CS 将每个电路门转换为形如 `<A, v> · <B, v> = <C, v>` 的约束。

```
对于 sym_1 = x * x:
  A = [0, 1, 0, 0, 0, 0]    // A·v = x
  B = [0, 1, 0, 0, 0, 0]    // B·v = x
  C = [0, 0, 0, 1, 0, 0]    // C·v = sym_1
  验证: x * x == sym_1   ✓

对于 y = sym_1 * x:
  A = [0, 0, 0, 1, 0, 0]    // A·v = sym_1
  B = [0, 1, 0, 0, 0, 0]    // B·v = x
  C = [0, 0, 0, 0, 1, 0]    // C·v = y
  验证: sym_1 * x == y    ✓

对于 sym_2 = y + x (加法门 → 用乘法表示: 1*(y+x) = sym_2):
  A = [0, 1, 0, 0, 1, 0]    // A·v = x + y
  B = [1, 0, 0, 0, 0, 0]    // B·v = 1
  C = [0, 0, 0, 0, 0, 1]    // C·v = sym_2

对于 out = sym_2 + 5:
  A = [5, 0, 0, 0, 0, 1]    // A·v = 5 + sym_2
  B = [1, 0, 0, 0, 0, 0]    // B·v = 1
  C = [0, 0, 1, 0, 0, 0]    // C·v = out
```

#### 步骤3：QAP (Quadratic Arithmetic Program)

将 R1CS 的逐点约束转换为**多项式**形式。

```
基本思路：使用拉格朗日插值
- 在 r=1 处编码第一个约束
- 在 r=2 处编码第二个约束
- ...

得到三个多项式 A(x), B(x), C(x)
使得: A(x)·B(x) - C(x) = 0  当 x ∈ {1, 2, 3, 4}

等价于存在多项式 H(x):
  A(x)·B(x) - C(x) = Z(x)·H(x)
其中 Z(x) = (x-1)(x-2)(x-3)(x-4) 称为"目标多项式"
```

**检查**：验证者只需在随机点 t 检查 `A(t)·B(t) = C(t) + Z(t)·H(t)`

如果证明者在 t 处的赋值成立，概率论证表明约束在所有点都成立（Schwartz-Zippel 引理）。

#### 步骤4：SRS (Structured Reference String) 可信设置

```
┌────────────────────────────────────────────────────┐
│                  可信设置流程                        │
│                                                    │
│  1. 多方参与生成 SRS                                │
│  2. 每方贡献自己的随机数                            │
│  3. 每方销毁自己的随机数 ("toxic waste")             │
│  4. 只有所有人都诚实，设置才安全                     │
│                                                    │
│  SRS 中包含:                                       │
│  - G, αG, α²G, ..., α^dG (在椭圆曲线上)           │
│  - 用于评估多项式承诺                               │
│                                                    │
│  ⚠️ "有毒废料"若泄露 → 可伪造证明！                 │
└────────────────────────────────────────────────────┘
```

**Ceremony** (仪式)：Zcash 的 Powers of Tau 仪式通过 80+ 个参与方，只要其中一人诚实销毁随机数，系统就安全。

#### 验证过程 (Groth16)

```
证明 π = (A, B, C)   其中 A, B, C 是椭圆曲线群元素
证明大小: ~200 字节（3个群元素）

验证: e(A, B) = e(α, β) + e(C, δ) + e(其他公开项)
      ↑ 椭圆曲线双线性配对
      
验证时间: 几毫秒（常数时间）
```

### 2.2 zk-STARKs —— 透明设置

#### 与 SNARKs 的对比

| 特性 | zk-SNARKs | zk-STARKs |
|------|-----------|-----------|
| **可信设置** | ✅ 需要 SRS | ❌ **不需要**（透明） |
| **证明大小** | ~200 字节 | ~100-200 KB |
| **验证时间** | 几毫秒 | 几十毫秒 |
| **证明时间** | 较慢 | 较慢 |
| **抗量子** | ❌（椭圆曲线） | ✅（哈希函数） |
| **扩展性** | 验证者复杂度 O(log²n) | 验证者复杂度 O(log²n) |

#### STARKs 的核心技术

```
STARK = Scalable Transparent ARgument of Knowledge

关键技术:
1. IOP (Interactive Oracle Proof)
   - 证明者提交 Oracle（函数）
   - 验证者随机挑战
   - 通过 Fiat-Shamir 转为非交互

2. 代数化: 将计算正确性编码为多项式除法
   对随机点求值进行低度测试( proximity testing)

3. 低度测试 (Low-Degree Testing)
   - 使用 FRI 协议 (Fast Reed-Solomon IOP of Proximity)
   - 递归地检查某函数是否接近低度多项式
```

#### FRI 协议示意

```
原始多项式:    f(x)   degree ≤ d
在域 D 上采样: f(ω⁰), f(ω¹), ..., f(ω^{|D|-1})

FRI 递归折叠:
  f₀(x) = f(x)                      # 原始函数
  f₁(x) = f₀_even(x²) + α·f₀_odd(x²)  # 随机折叠，度数减半
  f₂(x) = f₁_even(x²) + α·f₁_odd(x²)  # 继续折叠
  ...
  f_k(x) ≈ 常数                       # 最终

α 是验证者选择的随机数
如果 f 是低度多项式，折叠后的多项式仍是低度的
```

### 2.3 Bulletproofs —— 短证明

Bulletproofs (Bünz et al., 2018) 是另一种无需可信设置的零知识证明方案。

#### 核心特性

```
特点:
1. ❌ 无需可信设置（像 STARKs）
2. ✅ 证明大小: O(log n) —— 对数级！
3. ✅ 支持范围证明（range proofs）：证明 x ∈ [0, 2^n] 不透露 x
4. ❌ 验证时间: O(n) —— 线性
```

#### 与 SNARKs/STARKs 对比

```
证明大小示意图 (n = 2²⁰ 约束):

SNARKs:      ┃━━━━━━━┃   ~200 字节 (常数)
Bulletproofs:┃━━━━━━━━━━━━━━━━━━┃   ~1.3 KB (O(log n))
STARKs:      ┃━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┃   ~200 KB

Bulletproofs 是 "中等大小证明，无需可信设置" 的 sweet spot
```

#### 核心思想：内积论证 (Inner Product Argument)

```
目标: 证明 <a, b> = c，不透露 a 和 b

递归折叠:
  a = [a_lo || a_hi]    b = [b_lo || b_hi]
  c_L = <a_lo, b_hi>    c_R = <a_hi, b_lo>
  
  折叠后:
  a' = a_lo + x·a_hi    (x 是验证者选择的随机挑战)
  b' = b_lo + x^{-1}·b_hi
  
  尺寸减半，递归 log n 轮
```

#### 应用：机密交易 (Confidential Transactions)

```
Monero 使用 Bulletproofs 实现范围证明：

交易输入: 5 XMR
交易输出: 3 XMR + 2 XMR

证明: 3 ∈ [0, 2⁶⁴]  AND  2 ∈ [0, 2⁶⁴]
      同时证明: 5 = 3 + 2 (平衡)

传统方案: 每个范围证明需要 64 个 pedersen 承诺 → 64 KB
Bulletproofs: 整个证明 ~1.3 KB   (节省 98%!)
```

### 2.4 零知识证明方案选择指南

```
你的应用场景是什么？
│
├── 需要最小证明大小 + 可接受可信设置？
│   └── zk-SNARKs (Groth16)  ← 以太坊、Zcash
│
├── 需要透明设置 + 抗量子性？  
│   ├── 证明大小不重要 → zk-STARKs  ← Starkware
│   └── 证明大小受限   → Bulletproofs  ← Monero
│
└── 需要可更新可信设置？
    └── PLONK (Universal Setup)  ← 可复用同一 SRS
```

## 3. 应用：隐私交易与 zk-Rollup

### 3.1 隐私交易

```
                   隐私交易流程
                   
普通交易:
  Alice → 发送 10 ETH → Bob
  全网络可见: 发送方、接收方、金额

隐私交易 (Zcash 风格):
  ┌─────────────────────────────────────┐
  │  Alice: 创建 Shielded Transaction   │
  │                                      │
  │  步骤:                               │
  │  1. 承诺: cm = Commit(金额, 随机数)   │
  │  2. 证明:                             │
  │     - 我知道某个 cm 对应 >0 的金额    │
  │     - 交易余额平衡                    │
  │  3. 提交: (cm, 证明, 零知识更新Merkle树)│
  │                                      │
  │  验证者: 检查证明 ✓                   │
  │  观察者: 看不到金额、发送方、接收方    │
  └─────────────────────────────────────┘
```

### 3.2 zk-Rollup 中的证明生成

```
┌─────────────────────────────────────────────────────────┐
│                    zk-Rollup 架构                        │
│                                                         │
│  用户1 ────┐                                            │
│  用户2 ────┤                                            │
│  用户3 ────┼──► L2 定序器 ──► 批量交易 ──► 证明生成器   │
│  用户4 ────┤                              │             │
│  用户5 ────┘                              ▼             │
│                                    zk-SNARK 证明 π      │
│                                           │             │
│                                           ▼             │
│  L1 (以太坊): 验证单个证明 = 验证数千笔交易 ✓           │
│               状态更新 + gas 大幅降低                   │
└─────────────────────────────────────────────────────────┘
```

#### zk-Rollup 证明生成流程

```
1. 批处理:
   将 L2 上的 N 笔交易打包为一个批次

2. 电路构造:
   电路验证批次中每笔交易:
   - 签名正确 (交易由合法用户签名)
   - 账户余额足够
   - 状态转换正确 (Merkle 证明)
   - 无双花 (nonce 递增)

3. 证明生成:
   为整个批次生成单个 zk-SNARK 证明

4. L1 验证:
   以太坊合约在几毫秒内验证证明
   更新 L2 状态根
```

#### 知名 zk-Rollup 项目

| 项目 | ZKP 方案 | 特点 |
|------|---------|------|
| zkSync | PLONK + Redshift | 通用 EVM 兼容 |
| StarkNet | STARK | Cairo 专用语言，高吞吐 |
| Scroll | Groth16 + PLONK | EVM 字节码级兼容 |
| Polygon zkEVM | Groth16 | EVM 等效 |
| Aztec | PLONK + UltraPLONK | 隐私优先的 L2 |

#### 性能对比

```
                         每笔交易 L1 gas 成本
                          
          普通 L1 交易 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 21,000 gas
```

## 5. 总结

### 同态加密

```
PHE  ── RSA (乘法) / Paillier (加法)  ── 效率高，功能单一
  │
  ▼
LHE  ── BGN (一次乘法) / Leveled BGV ── 有限深度
  │
  ▼
FHE  ── Gentry Bootstrapping ── 无限运算，开销巨大
        BGV / CKKS / TFHE  ── 实用优化
```

### 零知识证明

```
                   zk-SNARK
                   ├─ 小证明 (200B)
需要可信设置? ────  ├─ 快速验证
                   └─ 需可信设置仪式
                   
                   zk-STARK
                   ├─ 透明 (无设置)
无需可信设置? ────  ├─ 抗量子
                   └─ 大证明 (200KB)
                   
                   Bulletproofs
                   ├─ 透明
                   └─ O(log n) 证明大小
```

### 关键词速查

| 术语 | 含义 |
|------|------|
| **PHE** | 只能做加法或只能做乘法的同态加密 |
| **LHE** | 支持有限深度加法和乘法 |

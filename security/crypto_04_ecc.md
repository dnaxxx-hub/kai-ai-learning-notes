## 1. 椭圆曲线数学基础

### 1.1 Weierstrass 标准形

椭圆曲线的一般形式是 **Weierstrass 方程**：

$$E: y^2 = x^3 + ax + b$$

其中 $4a^3 + 27b^2 \neq 0$（保证曲线"光滑"，没有尖点和自交点）。

**为什么叫"椭圆"曲线？** 名称来自椭圆周长计算中的椭圆积分，并非因为曲线形状像椭圆。

关键性质：
- **关于 x 轴对称**：如果 $(x, y)$ 在曲线上，则 $(x, -y)$ 也在曲线上
- **无奇点**：判别式 $\Delta = 4a^3 + 27b^2 \neq 0$

### 1.2 实数域上的点加运算

这是 ECC 的核心运算。点加定义了一个阿贝尔群。

#### 定义：无穷远点 O

引入一个"无穷远点" $O$ 作为**单位元**，相当于加法中的 0：
- $P + O = O + P = P$（任何点加无穷远点不变）

#### 连线法则：P + Q（两点不同）

给定曲线上两个不同点 $P = (x_1, y_1)$ 和 $Q = (x_2, y_2)$：

1. **连线**：过 $P$ 和 $Q$ 画一条直线
2. **求第三交点**：直线与曲线相交于第三点 $R'$
3. **取对称点**：$R'$ 关于 x 轴的对称点即是 $P + Q$

**代数公式**（斜率法）：

$$
\lambda = \frac{y_2 - y_1}{x_2 - x_1}
$$

$$
x_3 = \lambda^2 - x_1 - x_2
$$

$$
y_3 = \lambda(x_1 - x_3) - y_1
$$

**验证**：将直线方程 $y = \lambda(x - x_1) + y_1$ 代入曲线，得到三次方程，三个根就是 $x_1, x_2, x_3$。

#### 切线法则：P + P（倍点）

点加自身时，连线的几何意义退化为**切线**：

$$
\lambda = \frac{3x_1^2 + a}{2y_1}
$$

然后同一点加公式：
$$
x_3 = \lambda^2 - 2x_1
$$
$$
y_3 = \lambda(x_1 - x_3) - y_1
$$

#### 特殊情况

- 如果 $P = -Q$（即 $y_1 = -y_2$），则 $P + Q = O$
- 如果 $P = O$，则 $P + Q = Q$
- 如果 $y_1 = 0$，则 $P + P = O$（切线垂直）

### 1.3 群结构

椭圆曲线上的点加上无穷远点 $O$，构成一个**加法阿贝尔群**：

| 性质 | 说明 |
|------|------|
| **封闭性** | 任意两点相加结果仍在曲线上 |
| **结合律** | $(P+Q)+R = P+(Q+R)$ |
| **单位元** | $P + O = P$ |
| **逆元** | $-(x, y) = (x, -y)$ |
| **交换律** | $P+Q = Q+P$ |

### 1.4 标量乘法

**标量乘法**（Scalar Multiplication）定义为点重复相加：

$$k \cdot G = \underbrace{G + G + \cdots + G}_{k \text{ 次}}$$

例如：
- $3G = G + G + G$
- $2G = G + G$（倍点）
- $1G = G$

### 1.5 离散对数问题（ECDLP）

**问题**：已知 $Q = k \cdot G$ 和基点 $G$，求标量 $k$。

这就是**椭圆曲线离散对数问题**（ECDLP），是 ECC 安全性的根本保证。

**为什么难？**
- 正向（标量乘法）：可以用 Double-and-Add 在 $O(\log k)$ 步内完成
- 逆向（离散对数）：目前没有亚指数级算法（对于好的曲线）
- 经典算法：Pollard's Rho 需要 $O(\sqrt{n})$ 步，对于 256 位曲线不可行

**对比 RSA**：
- RSA 依赖大整数分解（有亚指数算法，如数域筛法）
- ECC 依赖 ECDLP（目前只有指数级算法）
- 因此 **ECC 256 位 ≈ RSA 3072 位**（同安全级别，但 ECC 密钥短得多）

## 2. 有限域上的椭圆曲线

### 2.1 从实数到有限域

实数域上的点加有几何直觉，但**计算机无法精确表示实数**（浮点误差）。

解决方案：把椭圆曲线定义在**素数域 GF(p)** 上。

### 2.2 素数域 GF(p)

域 GF(p) 的元素是 $\{0, 1, 2, \ldots, p-1\}$，所有运算模 $p$：

- 加法：$(a + b) \bmod p$
- 乘法：$(a \times b) \bmod p$
- 逆元：$a^{-1}$ 满足 $a \cdot a^{-1} \equiv 1 \pmod{p}$，用**扩展欧几里得算法**计算

**扩展欧几里得算法**求逆元：

```python
def modinv(a, p):
    """返回 a 在模 p 下的逆元（a 和 p 互质）"""
    if a == 0:
        return 0
    lm, hm = 1, 0
    low, high = a % p, p
    while low > 1:
        ratio = high // low
        nm, new = hm - lm * ratio, high - low * ratio
        lm, low, hm, high = nm, new, lm, low
    return lm % p
```

### 2.3 GF(p) 上的点加公式

关键是**用代数代替几何**，所有运算模 p：

**点加 P + Q（P ≠ Q）**：
$$\lambda = (y_2 - y_1) \cdot (x_2 - x_1)^{-1} \bmod p$$
$$x_3 = (\lambda^2 - x_1 - x_2) \bmod p$$
$$y_3 = (\lambda(x_1 - x_3) - y_1) \bmod p$$

**倍点（P + P）**：
$$\lambda = (3x_1^2 + a) \cdot (2y_1)^{-1} \bmod p$$
$$x_3 = (\lambda^2 - 2x_1) \bmod p$$
$$y_3 = (\lambda(x_1 - x_3) - y_1) \bmod p$$

### 2.4 secp256k1 —— Bitcoin 使用的曲线

secp256k1 是比特币和以太坊使用的标准曲线：

| 参数 | 值 |
|------|-----|
| 曲线方程 | $y^2 = x^3 + 7$ **(a=0, b=7)** |
| 素数 p | $2^{256} - 2^{32} - 2^9 - 2^8 - 2^7 - 2^6 - 2^4 - 1$ |
| 阶 n | $2^{256} - 432420386565659656852420866394968145599$ |
| 基点 G | `(0x79BE667E..., 0x483ADA77...)` |
| 位数 | 256 位 |

p 的具体值：
```
p = FFFFFFFF FFFFFFFF FFFFFFFF FFFFFFFF FFFFFFFF FFFFFFFF FFFFFFFE FFFFFC2F
```

**为什么用 $y^2 = x^3 + 7$？**
- $a = 0$ 使得倍点运算更快（$3x^2 + a = 3x^2$）
- 特定参数选择使安全性有保障

### 2.5 点的压缩表示

在 GF(p) 上，给定 $x$，$y = \pm \sqrt{x^3 + 7} \bmod p$。

由于 $y^2$ 是平方，$y$ 和 $-y$ 是同一值的正负形式。可以用 1 比特指示 $y$ 的奇偶：

```
压缩形式： 02 + x (y为偶数)  
           03 + x (y为奇数)
完整形式： 04 + x + y
```

压缩后：256 位密钥只需 33 字节（32 字节 x + 1 字节奇偶标记）。完整形式需 65 字节。

## 3. Double-and-Add 标量乘法

### 3.1 算法原理

"倍点-加法"（Double-and-Add）是计算 $k \cdot G$ 的标准算法。

**核心思想**：将 $k$ 写为二进制，利用倍点和点加组合：

$$k \cdot G = \sum_{i=0}^{n-1} b_i \cdot 2^i \cdot G$$

其中 $b_i$ 是 $k$ 的二进制位。

**例子**：$k = 13 = 1101_2 = 8 + 4 + 1$

```
G      → 倍点 → 2G      → 倍点 → 4G      → 倍点 → 8G
                                              ↓
结果 = G + 4G + 8G = 13G
```

### 3.2 算法实现

```
输入：k (整数), P (椭圆曲线上的点)
输出：k·P

初始化：R = O (无穷远点)
对于 i 从 0 到 bit_length(k)-1：
    如果 k 的第 i 位为 1：
        R = R + P
    P = 2P   (倍点)
返回 R
```

**效率**：每比特一次倍点 + 约一半比特一次点加。256 位密钥约需 256 次倍点 + 128 次点加。

### 3.3 常数时间实现

朴素 Double-and-Add 的**执行时间取决于 k 中 1 的个数**，存在侧信道泄露风险。

**常数时间版本**：始终执行点加，但只在需要时保留结果：

```
R0 = O  (结果缓存)
R1 = P  (当前倍点值)
对于 i 从 255 到 0：
    如果 k 的第 i 位为 1：
        R0 = R0 + R1  (实际执行)
    R1 = 2*R1
    否则：
        R0 = R0 + R1  (伪执行，结果丢弃)
```

更常用的方法是 **Montgomery Ladder**，自然常数时间：

```
R0 = O
R1 = P
对于 i 从 n-1 到 0：
    如果 bit_i == 0:
        R1 = R0 + R1
        R0 = 2*R0
    否则:
        R0 = R0 + R1
        R1 = 2*R1
返回 R0
```

## 4. ECDH 密钥交换

### 4.1 协议流程

ECDH（Elliptic Curve Diffie-Hellman）是 Diffie-Hellman 密钥交换的椭圆曲线版本：

```
Alice                           Bob
  |                               |
  |  生成私钥 a，公钥 A = a·G     |
  |  生成私钥 b，公钥 B = b·G     |
  |                               |
  |──── A = a·G ────────────────→|
  |←─── B = b·G ─────────────────|
  |                               |
  |  共享密钥 S = a·B = a·b·G    |
  |                  共享密钥 S = b·A = b·a·G  |
```

**数学原理**：
$$S_{\text{Alice}} = a \cdot B = a \cdot (b \cdot G) = ab \cdot G$$
$$S_{\text{Bob}} = b \cdot A = b \cdot (a \cdot G) = ab \cdot G$$

**安全保证**：窃听者看到 $A = a \cdot G$ 和 $B = b \cdot G$，但 ECDLP 保证他无法求出 $a$ 或 $b$，因此无法计算出 $ab \cdot G$。

### 4.2 实际使用

实际中，ECDH 的共享密钥不是直接用点坐标，而是用 **KDF（密钥派生函数）** 处理：

```
共享密钥 = KDF(x_coordinate_of_ab·G)
```

常用 KDF：HKDF、SHA-256（直接哈希点坐标）

### 4.3 安全性考虑

- **临时密钥 (ECDHE)**：每次会话生成新的临时密钥对，提供**前向安全性**（即使长期密钥泄露，过去会话安全）
- **公钥验证**：确保收到的公钥确实在曲线上（否则可能被降级攻击）
- **DH 素数的检查**：验证公钥阶是否为 n

## 5. ECDSA 数字签名

### 5.1 参数定义

| 参数 | 含义 |
|------|------|
| $G$ | 基点（系统公开参数） |
| $n$ | 基点 $G$ 的阶（$n \cdot G = O$） |
| $d$ | 私钥（随机整数，$1 \leq d < n$） |
| $Q = d \cdot G$ | 公钥（椭圆曲线上的点） |
| $m$ | 待签名消息 |
| $z$ | 消息哈希（SHA-256 输出的前 n 位） |

### 5.2 签名算法

**输入**：私钥 $d$，消息 $m$  
**输出**：签名 $(r, s)$

```
1. 计算消息哈希 z = HASH(m)
2. 随机选取临时密钥 k (1 ≤ k < n)
3. 计算 R = k · G，取 r = R.x mod n
   (如果 r == 0，回到步骤 2)
4. 计算 s = k⁻¹(z + r · d) mod n
   (如果 s == 0，回到步骤 2)
5. 返回签名 (r, s)
```

**注意**：
- $k$ **必须**每次签名重新随机生成（和私钥同等重要！）
- 如果 $k$ 泄露，私钥 $d$ 可直接求出：$d = (sk - z) / r \bmod n$
- 如果两次签名用了同一个 $k$，私钥也会泄露（PlayStation 3 的史诗级漏洞）

### 5.3 验证算法

**输入**：公钥 $Q$，消息 $m$，签名 $(r, s)$  
**输出**：签名是否有效

```
1. 检查 r, s 是否在 [1, n-1] 范围内
2. 计算消息哈希 z = HASH(m)
3. 计算 u₁ = z · s⁻¹ mod n
4. 计算 u₂ = r · s⁻¹ mod n
5. 计算 R' = u₁ · G + u₂ · Q
6. 如果 R' == O，拒绝签名
7. 如果 R'.x ≡ r (mod n)，接受签名
8. 否则拒绝签名
```

### 5.4 正确性证明

验证算法的核心是证明 $R' = R$：

$$R' = u_1 \cdot G + u_2 \cdot Q$$
$$= (z \cdot s^{-1}) \cdot G + (r \cdot s^{-1}) \cdot (d \cdot G)$$
$$= s^{-1}(z + r \cdot d) \cdot G$$
$$= s^{-1}(s \cdot k) \cdot G \quad (\because s = k^{-1}(z + r \cdot d), \ \text{所以} \ s \cdot k = z + r \cdot d)$$
$$= k \cdot G = R$$

因此 $R'.x \equiv R.x = r$。

### 5.5 公钥恢复

ECDSA 可以从签名 $(r, s)$ 和消息 $m$ 恢复出可能的公钥：

```
1. 计算 z = HASH(m)
2. 从 r 恢复 R (r 是 R.x, 需要反解出 y)
3. 公钥 Q = r⁻¹(s · R - z · G)
```

```
证明：从签名公式
  s = k⁻¹(z + r·d) mod n
  → k·s = z + r·d
  → r·d = k·s - z
  → d·G = r⁻¹(s·k·G - z·G)
  → Q = r⁻¹(s·R - z·G)  ✓
```

注意：由于从 $r$ 恢复 $R$ 时 $y$ 有两种可能，所以恢复出的公钥可能有两个候选。但以太坊等系统利用 $v$ 参数（恢复 ID）来精确选择。

### 5.6 k 的重要性 —— Sony 的教训

2010 年，Sony PlayStation 3 使用 ECDSA 签名固件，但 **每次使用相同的 k**。

攻击者只需拿到两个签名即可提取私钥：

```
s₁ = k⁻¹(z₁ + r·d) mod n
s₂ = k⁻¹(z₂ + r·d) mod n

s₁ - s₂ = k⁻¹(z₁ - z₂) mod n
k = (z₁ - z₂) / (s₁ - s₂) mod n
d = (s₁·k - z₁) / r mod n
```

后果：PS3 被完全破解，所有游戏都可运行盗版。这个教训告诉我们：**k 就是不可重复使用的私钥**。

## 6. Ed25519

### 6.1 Edwards 曲线

Ed25519 使用 **Edwards 曲线**：

$$x^2 + y^2 = 1 + d \cdot x^2 \cdot y^2$$

对比 Weierstrass 曲线 $y^2 = x^3 + ax + b$：

| 特性 | Ed25519 | secp256k1 |
|------|---------|-----------|
| 曲线形式 | Edwards | Weierstrass |
| 点加公式 | 统一公式（无分支） | 需要区分 P=Q 和 P≠Q |
| 常数时间 | 天生 | 需要特殊处理 |
| 签名大小 | 64 字节 | 70-72 字节 |
| 性能 | 更快 | 较慢 |
| 侧信道抵抗 | 更好 | 一般 |
| 安全性争议 | 少（NSA参数明确） | 有（Koblitz曲线争议） |

### 6.2 点加公式

Edwards 曲线的点加公式极其优雅，**不需要区分"点加"和"倍点"**：

$$(x_1, y_1) + (x_2, y_2) = \left(\frac{x_1y_2 + y_1x_2}{1 + dx_1x_2y_1y_2}, \frac{y_1y_2 - x_1x_2}{1 - dx_1x_2y_1y_2}\right)$$

- **统一公式**：同样的公式用于 $P+Q$ 和 $P+P$
- **无分支**：不需要 if 判断，天然常数时间
- **完备加法**：对曲线上所有点有效（没有"无穷远点"的特殊处理）

### 6.3 Ed25519 参数

| 参数 | 值 |
|------|-----|
| 曲线 | $x^2 + y^2 = 1 + d \cdot x^2 \cdot y^2$ |
| $d$ | $-121665/121666 \bmod p$ |
| $p$ | $2^{255} - 19$ |
| 基点 $B$ | 压缩形式 `5866666666666666666666666666666666666666666666666666666666666666` |
| 阶 $n$ | $2^{252} + 27742317777372353535851937790883648493$ |

### 6.4 Ed25519 签名（EdDSA）

Ed25519 是 **EdDSA**（Edwards-curve Digital Signature Algorithm）的具体实例，使用 RFC 8032。

**与 ECDSA 的关键区别**：

1. **确定性签名**：随机数 $k$ 不随机生成，而是从**私钥 + 消息哈希**派生
   - 这意味着**同一消息使用同一私钥总是产生相同签名**
   - 避免了 Sony PS3 式的 $k$ 重用漏洞

2. **一次性密钥**：
   - $k = \text{HASH}(d \parallel m)$
   - 即使随机数生成器有问题，签名仍然安全

3. **批量验证**：多个 Ed25519 签名可以一次批量验证，比逐个验证快得多

### 6.5 为什么 Ed25519 更好？

| 特性 | Ed25519 | ECDSA (secp256k1) |
|------|---------|-------------------|
| **性能** | ≈125K 签名/秒 | ≈60K 签名/秒 |
| **签名大小** | 64 字节 | 70-72 字节 |
| **公钥大小** | 32 字节 | 33 或 65 字节 |
| **常数时间** | 天生（统一公式） | 需额外编码 |
| **k 的随机性** | 确定性（无 RNG 依赖） | 依赖安全随机数 |
| **实现复杂度** | 低 | 中 |
| **侧信道抵抗** | 优秀 | 一般 |
| **使用范围** | SSH, TLS 1.3, 信号协议 | 比特币, 以太坊 |

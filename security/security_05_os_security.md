## 缓冲区溢出（Buffer Overflow）

### 原理

```python
# C语言里最经典的漏洞 = 不检查边界

void vulnerable(char *input) {
    char buffer[64];          // 64字节的缓冲区
    strcpy(buffer, input);    // 如果input超过64字节 → 溢出！
}
```

```
内存布局:
┌──────────────┐ 高地址
│  返回地址    │ ← 溢出数据会覆盖这里！
├──────────────┤
│  上一帧指针  │
├──────────────┤
│  局部变量    │ 
├──────────────┤
│  缓冲区[64]  │ ← 输入从这里开始
└──────────────┘ 低地址

攻击: 填超过64字节 → 覆盖返回地址 → 跳到攻击者代码
```

### 防御

```python
# 现代防御机制:

# 1. ASLR (地址空间布局随机化)
#    每次运行，内存地址随机 → 攻击者无法预测地址

# 2. 栈Canary
#    在缓冲区和返回地址之间放一个"哨兵值"
#    如果溢出覆盖了Canary → 程序检测到异常 → 终止

# 3. DEP/NX (数据执行保护)
#    栈上不能执行代码 → 溢出也没法执行shellcode

# 4. 安全的函数
#    strcpy → strncpy（指定最大长度）
#    gets → fgets
```

## 提权（Privilege Escalation）

```python
# 从"普通用户"变成"管理员/root"

# 水平提权: 用户A → 窃取用户B的数据
# 垂直提权: 普通用户 → 获取管理员权限

# 常见方式:
# - 利用操作系统漏洞 → 内核提权
# - SUID文件（以文件所有者权限运行的二进制）
# - sudo配置错误
# - 不安全的服务配置（如Docker不加限制）
```

## 沙箱（Sandbox）

```python
# 限制程序能做什么

# 浏览器沙箱: JS不能读本地文件
# 容器沙箱: Docker限制进程/网络/文件系统
# 移动沙箱: App不能访问其他App的数据

# 关键机制:
# - 最小权限: 只给需要的权限
# - 命名空间: 隔离进程视图
# - Seccomp: 限制系统调用
# - AppArmor/SELinux: 强制访问控制
```

## 常见操作系统漏洞

```python
# Dirty COW (CVE-2016-5195):
# Linux内核的竞争条件漏洞 → 提权至root
# 存在于Linux内核9年（2007-2016）

# EternalBlue (MS17-010):
# Windows SMB协议漏洞
# 被WannaCry勒索病毒利用(2017) → 全球数十万台电脑中招

# Spectre/Meltdown (2018):
# CPU设计漏洞 → 利用"推测执行"读取内核内存
# 影响几乎所有现代处理器（Intel/AMD/ARM）
```

## 今日收获
- 缓冲区溢出 = 输入超过缓冲区 → 覆盖返回地址
- ASLR/Canary/DEP = 现代系统的"安全三件套"
- 提权 = 从普通变成管理员
- 沙箱 = 限制程序"能做什么不能做什么"
- 著名漏洞：Dirty COW / EternalBlue / Spectre

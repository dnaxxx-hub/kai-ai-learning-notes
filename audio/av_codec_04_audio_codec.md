# 第4课：音频编解码 — PCM、MP3、AAC、Opus、心理声学模型、MDCT

## 1. 概述

音频编解码与视频编解码有相似的核心逻辑——利用**人类感知特性**去除冗余数据。但音频的物理基础和数学模型完全不同。

本课将覆盖：
- **PCM 数字音频基础**（采样率、位深、声道）
- **心理声学模型**（人耳如何"听"——这是所有音频压缩的核心）
- **时频变换**（从 DFT 到 MDCT，为什么 MDCT 是音频编码的基石）
- **主流编码器对比**（MP3 / AAC / Opus）

## 2. PCM 数字音频

### 2.1 采样与量化

PCM（Pulse Code Modulation）是最基本的数字音频表示方式：

```
模拟波形:
  ~/\  /\  ~~/\/\  /~~/\  /\
 /  \/  \/  /    \/  /  \/  \
         ↓ 采样（每 T 秒一个点）

采样点:  ●   ●   ●   ●   ●   ●   ●   ●
          ↑ 量化到最近的值

数字 PCM 序列:
  值:  [128, 200, 245, 128, 50, 10, 70, 128]
  比特: 8-bit per sample
```

### 2.2 PCM 数据量计算

```
原始 PCM 数据率 = 采样率 × 位深 × 声道数

CD 音频:  44100 × 16 × 2 = 1,411,200 bps ≈ 1.4 Mbps
24-bit/96kHz: 96000 × 24 × 2 = 4,608,000 bps ≈ 4.6 Mbps

一部 90 分钟 CD 音频: 1.4M × 5400 ≈ 7.6 Gb ≈ 950 MB
```

### 2.3 常见 PCM 格式

| 参数 | 电话 | CD | 高解析度 | Dolby Atmos |
|------|------|----|---------|------------|
| 采样率 | 8 kHz | 44.1 kHz | 96 kHz | 48 kHz |
| 位深 | 8 bit | 16 bit | 24 bit | 24 bit |
| 声道 | 1 (Mono) | 2 (Stereo) | 2 (Stereo) | 7.1.4 (12声道) |
| 码率 | 64 kbps | 1,411 kbps | 4,608 kbps | 13,824 kbps |

## 3. 心理声学模型（Psychoacoustic Model）

这是**所有有损音频压缩**的理论基础。人耳有诸多"缺陷"，利用这些缺陷可以在人察觉不到的范围内丢弃大量数据。

### 3.1 听觉阈值（Absolute Threshold of Hearing）

人耳对不同频率的敏感度不同：

```
响度 (dB SPL)
  120 ┤                                      痛阈
      │                          ████
   80 ┤                ████       正常说话
      │          ██
   40 ┤       ██         ↑
      │     ██        人耳最敏感区
   20 ┤   ██           (2kHz–5kHz)
      │  ██
    0 ┤ ██ ── 听觉阈值（0 dB HL 的基准）
      │ ─┴─┴─┴─┴─┴─┴─┴─┴─→ 频率
        20  50 100 200 500 1k 2k 5k 10k 20k Hz
```

**编码洞察**：低于听觉阈值的频率成分可以被完全丢弃，人耳无法察觉。

### 3.2 掩蔽效应（Masking）

这是更强大的"铲除"工具。**一个强信号会使附近频率的弱信号变得不可闻**。

**频率掩蔽（频域掩蔽）**：
```
能量
  ↑
  │   ████ ← 强掩蔽音（1kHz 纯音）
  │   ████
  │ ████████ ← 向上掩蔽
  │ ██████████
  │ ████████████
  │ ████████████████
  │ ██████████████████　← 掩蔽阈值
  │ ░░░░░░░░░░░░░░░░░░░░  ← 下方的弱信号被掩蔽（可丢弃）
  └──────────────────→ 频率
      ↑        ↑
   被掩蔽区   被掩蔽区
   (频率略低)  (频率更高)
```

**时间掩蔽（时域掩蔽）**：
```
信号强度
  ↑
  │  ████████████████ ← 强信号（如响板声）
  │     ██████████████
  │        ████████████
  │░░░░░░░        ░░░░░░░░ ← 前后被掩蔽区
  │░░░░░░░░       ░░░░░░░░░
  └──────────────────────→ 时间
     ↑ 前掩蔽        ↑ 后掩蔽
    (~20ms)         (~100ms)
```

### 3.3 心理声学模型的应用

```
感知编码器的工作流程:
1. 对输入音频做 FFT → 得到频域能量分布
2. 计算听觉阈值 + 掩蔽阈值 → 得到"感知重要性"曲线
3. 低于阈值的频率分量 → 分配零或极少的 bit
4. 高于阈值的频率分量 → 精细量化

最终: 有限的 bit 都分配给人耳能听到的部分
      听不到的部分 → 丢弃 → 压缩
```

### 3.4 比特分配（Bit Allocation）

```
量化噪声形状控制:

无心理声学模型:
  噪声:  ██▓▓▓▓████▓▓████████  ← 均匀量化噪声

有心理声学模型:
  信号:  ████████░░░░████░░░░██
  噪声:  ▓▓▓▓▓▓▓▓░░░░▓▓░░░░▓▓  ← 噪声集中在掩蔽区下
  感知:  ✗听不到  ✓能听到  ✗听不到

结果: 同样的整体量化噪声，感知质量大幅提升
```

## 4. 时频变换：从 DFT 到 MDCT

### 4.1 为什么需要时频变换？

音频信号在时域中看起来随机，但频域中有清晰的谐波结构：

```
时域（随时间变化的振幅）:
  /\  /\  /\  /\  /\  /\  /\  /\
 /  \/  \/  \/  \/  \/  \/  \/  \
    ↑ 看起来混乱

频域（对 FFT 后的能量分布）:
  能量
   ██
   ██   ██
   ██   ██   ██
   ██   ██   ██   ██   ██
   └─┬─└─┬─└─┬─└─┬─└─┬─└─┬──→ 频率
  基频  2次谐波 3次谐波...
    ↑ 能量集中，便于心理声学分析
```

### 4.2 短时傅里叶变换（STFT）的问题

DFT/FFT 将信号分成帧处理，但帧边界会产生**频谱泄漏**。为解决这个问题，使用**窗函数**：

```
矩形窗（不推荐）:         汉宁窗/Hann（推荐）:
┌──────────────────┐     ┌──────────────────┐
│██████████████████│     │    ██████████    │
│                  │     │  ██          ██  │
│                  │     │██              ██│
└──────────────────┘     └──────────────────┘
    边界突变 → 伪影         平滑下降 → 减少泄漏
```

但加窗后，相邻帧的边界区域在**编码器中会产生混叠伪影**（Aliasing）。MDCT 解决这个问题。

### 4.3 MDCT（Modified Discrete Cosine Transform）

MDCT 是**所有现代音频编码器的心脏**（MP3, AAC, Opus, Vorbis 都用它）。

**关键特性**：
1. **重叠 50%**：相邻帧重叠一半
2. **临界采样**：N 个输入 → N/2 个 MDCT 系数
3. **时域混叠消除（TDAC）**：重叠区域通过加窗叠加抵消混叠

```
帧结构（重叠 50%）:
帧 0: ┌────────────────────┐
       │                                      │
帧 1:       ┌────────────────────┐
             │                                      │
帧 2:             ┌────────────────────┐
                   │                                      │
       ├──────────┼──────────┼──────────┼──────────┼───→
       0         N/2         N        3N/2        2N   样本

编码过程:
  帧 k → MDCT → N/2 个系数 → 量化 → 编码
  帧 k+1 → MDCT → N/2 个系数 → 量化 → 编码

解码过程:
  帧 k MDCT⁻¹ → 加窗 → 前 N/2 样本
  帧 k+1 MDCT⁻¹ → 加窗 → 后 N/2 样本
  重叠相加 → 完美重建原始信号（无混叠）
```

### 4.4 MDCT vs DCT（视频中的 DCT）

```
视频 DCT:              音频 MDCT:
  ┌──────────┐           ┌──────────┐
  │ 8×8 块   │           │ 帧长 1024│
  │ 无重叠    │           │ 重叠 50% │
  │ 每块独立  │           │ 端点相接  │
  │ DCT-II   │           │ DCT-IV   │
  └──────────┘           └──────────┘

关键区别:
- DCT 用于视频 → 块之间不重叠，用环路滤波处理块效应
- MDCT 用于音频 → 重叠 50%，完美重建，无需帧间平滑
```

### 4.5 窗函数切换（Block Switching）

音频信号的时变特性差异巨大：

```
平稳信号（如持续音）:
────────────────────────────────────
→ 长窗（如 2048 样本）→ 高频率分辨率，适合压缩

瞬态信号（如打击乐）:
██                      ██  ██
  ██    ██  ██          ██
────────────────────────────────────
→ 短窗（如 256 样本）→ 高时间分辨率，减少"预回声"
```

**预回声（Pre-echo）**：在瞬态信号（如响板的"嗒"）之前出现模糊噪声，是短窗要解决的问题。

```
瞬态信号:         ▏ ← 打击瞬间

长窗解码:  ░░░░░░░░░█████████
           ↑ 预回声（可闻的模糊噪声）

短窗解码:    ███████
           几乎无预回声
```

## 5. 三大音频编码器对比

### 5.1 MP3（MPEG-1 Audio Layer III）

```
MP3 编码器结构:
PCM输入 → 滤波器组(32路PQF) → MDCT → 量化 → 哈夫曼编码 → 比特流打包
              ↑                            ↑
          心理声学模型                    迭代优化
         (FFT 分析)                    (噪声分配控制)

比特率:  32–320 kbps（CBR/VBR）
帧大小: 1152 样本
采样率: 32/44.1/48 kHz
```

### 5.2 AAC（Advanced Audio Coding）

```
AAC 相比 MP3 的改进:
  ┌─── PQF 滤波器组 → 混叠问题
  ├─── MDCT 直接处理 1024/960 样本 → 更高频域分辨率
  ├─── 更强的心理声学模型
  ├─── 更多的预测/编码工具（TNS, PNS, SBR, PS）
  └─── 支持更多声道（5.1, 7.1）

比特率:  8–529 kbps（更灵活）
帧大小: 1024/960 样本（长窗）
         128/120 样本（短窗，8× 短帧）
```

**AAC 的增强工具**：
- **TNS (Temporal Noise Shaping)**：在时域中塑造量化噪声形状
- **PNS (Perceptual Noise Substitution)**：噪声类信号用随机噪声替换
- **SBR (Spectral Band Replication)**：复制低频到高频（HE-AAC）
- **PS (Parametric Stereo)**：用参数表示立体声信息（HE-AAC v2）

```
HE-AAC 架构（SBR + PS）:
┌──────────┐  ┌──────────────┐  ┌──────────┐
│ 核心 AAC │  │ SBR 解码器   │  │ PS 解码器 │
│ (低带宽) │→│ (重建高频)   │→│ (立体声)  │→ 全频立体声输出
└──────────┘  └──────────────┘  └──────────┘

HE-AAC v2 在 48 kbps 下即可提供优质的立体声
```

### 5.3 Opus — 现代全能编码器

Opus 是 IETF 标准（RFC 6716），**开源、免专利费**，由 Skype SILK + Xiph CELT 合并而成：

```
Opus 混合架构:
┌───────────────── Opus ─────────────────┐
│                                         │
│  ┌──────────┐    ┌──────────┐           │
│  │  SILK    │    │  CELT    │           │
│  │(语音优化) │    │(音乐通用) │           │
│  │ 8-40kHz  │    │ 8-48kHz  │           │
│  │ LP分析合成│    │ MDCT+PVQ │           │
│  └──────────┘    └──────────┘           │
│       │               │                  │
│       └──────┬────────┘                  │
│              ↓                           │
│    ┌─────────────────┐                  │
│    │ 模式切换/混合器  │ ← 按内容类型自动切换│
│    └─────────────────┘                  │
└─────────────────────────────────────────┘

比特率: 6–510 kbps
采样率: 8–48 kHz
帧大小: 2.5–60 ms（极低的延迟）
延迟: 低至 5 ms（与 WebRTC 搭配）
```

### 5.4 编码器对比表

| 特性 | MP3 | AAC | Opus |
|------|-----|-----|------|
| 发布年份 | 1993 | 1997 | 2012 |
| 专利 | 需授权（已过期大部分） | 需授权 | **免专利费** |
| 采样率 | 32/44.1/48 kHz | 8–96 kHz | 8–48 kHz |
| 帧长 | 1152 样本 | 1024/960 样本 | 2.5–60 ms 可变 |
| 延迟 | >100 ms | >50 ms | **5–60 ms** |
| 编码效率(128kbps) | 良好 | 优秀 | **最佳** |
| 低码率(<64kbps) | 差 | HE-AAC 良好 | **优秀** |
| 语音编码 | 一般 | 一般 | **优秀**（SILK 模式） |
| 声道支持 | 最多 2 声道 | 最多 48 声道 | 最多 255 声道 |

## 6. Opus 在现代应用中的地位

```
WebRTC 强制要求: Opus

流媒体:              YouTube → Opus (WebM)
                    Spotify → Ogg Vorbis (类似 Opus)
                    主流 → AAC (MP4)

实时通信:           Zoom, Teams, Discord → Opus
                    WhatsApp → Opus
                    微信 → SILK (Opus 的前身)

语音助手:           Alexa, Siri → Opus

推荐使用原则:
  < 64 kbps:    Opus >> AAC > MP3
  64–128 kbps:  Opus ≥ AAC > MP3
  > 128 kbps:   AAC ≥ Opus > MP3
  实时通信:      Opus（唯一选择，低延迟+高质量）
```

## 7. 本课小结

| 概念 | 核心要点 |
|------|---------|
| PCM | 数字音频的原始格式，数据量与采样率×位深×声道数成正比 |
| 听觉阈值 | 人耳对不同频率的敏感度不同，低于阈值可丢弃 |
| 掩蔽效应 | 强信号掩蔽附近频率的弱信号，是丢弃数据的理论基础 |
| 心理声学模型 | 计算掩蔽阈值，指导比特分配 |
| MDCT | 时频变换的核心，重叠 50% + TDAC 实现完美重建 |
| 窗切换 | 长窗用于平稳信号，短窗用于瞬态信号（防预回声） |
| MP3 | 1993 经典但已落后，专利过期但编码效率不如现代格式 |
| AAC | 通用标准，ITunes/YouTube/MP4 首选 |
| Opus | 现代全能，开源免专利，低延迟高音质，WebRTC 标配 |

# 第1课：音视频基础 — 采样、量化、色彩空间、帧率、码率、容器格式

## 1. 概述

在进入音视频编解码的深度世界之前，我们必须先筑牢地基。本课覆盖所有音视频工程师必须掌握的核心概念：**模拟信号的数字化**（采样与量化）、**色彩空间**（YUV vs RGB）、**时间维度**（帧率、码率）以及**封装格式**（容器）。

理解这些概念是理解后续所有编码器、流媒体协议的前提。

---

## 2. 模拟 → 数字：采样与量化

自然界的声音和光线都是**连续的模拟信号**。计算机无法直接处理连续量，必须将其转化为**离散的数字信号**。

### 2.1 采样（Sampling）

采样是以固定的时间间隔对模拟信号进行测量。

```
模拟信号:  ~~~~/\/\/\~~~~/\/\/\~~~~/\/\/\~~~~
                |   |   |   |   |   |   |
采样点:         ●   ●   ●   ●   ●   ●   ●
时间轴:         t0  t1  t2  t3  t4  t5  t6
```

**奈奎斯特采样定理（Nyquist Theorem）**：采样频率必须 ≥ 信号最高频率的 2 倍，才能无失真地重建原始信号。

- **音频示例**：人耳可听范围 20Hz–20kHz → CD 采样率 44.1kHz（> 40kHz ✓）
- **视频示例**：采样率即帧率 FPS（Frames Per Second）

### 2.2 量化（Quantization）

量化是将采样得到的连续幅值映射到有限个离散级别。

```
幅值
  ↑
  |  模拟值: 3.14159...
  |      ↓
  |  量化值: 3  (假设整数量化)
  |      ↓
  |  二进制: 011
  └────────────────→ 时间
```

**量化位数（Bit Depth）**：
- 8-bit → 256 级（2^8），常用于旧格式
- 10-bit → 1024 级，HDR 视频标配
- 16-bit → 65536 级，CD 音频标准
- 24-bit → 1677 万级，Hi-Res 音频

量化位数越高，动态范围越大，但数据量也越大。

### 2.3 量化噪声

量化必然引入误差，称为**量化噪声**。量化噪声的功率与量化步长 Δ 的关系为：

```
噪声功率 = Δ² / 12
```

这意味着每增加 1 bit 量化精度，信噪比 SNR 提升约 6dB。

## 3. 色彩空间：RGB 与 YUV

### 3.1 RGB 色彩模型

RGB 是最直观的色彩表示方式：每个像素由 R（红）、G（绿）、B（蓝）三个分量组成。

```
  像素矩阵（RGB888）
  ┌─────┬─────┬─────┐
  │R G B│R G B│R G B│  ← 每个像素 24 bit（3 字节）
  ├─────┼─────┼─────┤
  │R G B│R G B│R G B│
  ├─────┼─────┼─────┤
  │R G B│R G B│R G B│
  └─────┴─────┴─────┘
```

**问题**：RGB 三个分量携带相同量的信息，但人眼对亮度更敏感，对色度不敏感。RGB 没有利用这个特性。

### 3.2 YUV 色彩模型

YUV 将亮度（Luma, Y）和色度（Chroma, U/V）分离：

```
YUV 分解
  ┌──────┐  ┌──────┐  ┌──────┐
  │  Y   │  │  U   │  │  V   │
  │亮度  │  │色度蓝│  │色度红│
  │(高分辨率)│  │(低分辨率)│  │(低分辨率)│
  └──────┘  └──────┘  └──────┘
```

**RGB → YUV 变换**（BT.601 标准）：

```
Y  =  0.299R + 0.587G + 0.114B
U  = -0.147R - 0.289G + 0.436B  (= Cb)
V  =  0.615R - 0.515G - 0.100B  (= Cr)
```

### 3.3 色度子采样（Chroma Subsampling）

利用人眼对色度不敏感的特性，降低 U/V 的分辨率：

```
4:4:4         4:2:2         4:2:0
YUVYUVYUV     YUVYUVYUV     YY YY YY
YUVYUVYUV     YUVYUVYUV     YY YY YY   ← UV 在水平和
YUVYUVYUV     YUVYUVYUV     UVUV UVUV     垂直方向都减半
```

| 格式 | 压缩比（相对 RGB） | 常见用途 |
|------|-------------------|---------|
| 4:4:4 | 1:1（无压缩） | 专业制作、屏幕录制 |
| 4:2:2 | 2:3 | 广播级视频 |
| **4:2:0** | **1:2** | **流媒体、蓝光、H.264/H.265 默认** |

**YUV 4:2:0 存储布局**（NV12 格式，最常用）：

```
[YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY]   ← 全部 Y 像素
[UVUVUVUVUVUVUVUVUVUVUVUVUVUVUVUV]  ← 交错 UV，每 2×2 块共享一对 UV
```

> **为什么 YUV 4:2:0 是王者？** 它将原始数据量减半，而人眼几乎察觉不到色度信息的损失。这是视频编码的第一个"免费午餐"。

## 4. 帧率（Frame Rate / FPS）

帧率是每秒显示的图像帧数，单位 fps（Frames Per Second）。

```
时间轴: ----●----●----●----●----●----
          帧1   帧2   帧3   帧4   帧5
          |<-- 1/fps 秒 -->|
```

**常见帧率**：

| 帧率 | 别名 | 用途 |
|------|------|------|
| 24 fps | 电影帧率 | 电影、Netflix 内容 |
| 25 fps | PAL | 欧洲电视标准 |
| 29.97 fps | NTSC | 北美电视标准 |
| 30 fps | — | 网络视频、直播 |
| 48/50/60 fps | 高帧率 | 体育、游戏、HFR 电影 |
| 120/240 fps | 超高速 | 慢动作摄影 |

**帧率选择的影响**：
- 高帧率 → 运动更流畅，但数据量线性增加
- 低帧率 → 节省带宽，但可能出现运动模糊/卡顿

## 5. 码率（Bitrate）

码率是每秒传输/存储的数据量，单位 bps（bits per second）。

### 5.1 码率类型

```
码率类型
  ├── CBR（恒定码率）：全程码率固定 → 适合直播、实时传输
  │     [━━━━━━━━━━━━━━━━━━]
  └── VBR（可变码率）：按场景复杂度动态分配 → 适合存储
        [══╲━━━━╱╲━━╱╲══╱╲═]
       简单场景省码率 → 复杂场景多给码率
```

### 5.2 码率与体积的关系

```
文件体积 = 码率 × 时长

示例：2小时电影，10 Mbps
体积 = 10,000,000 bps × 7200 s = 72 Gb = 9 GB
```

### 5.3 典型码率参考

| 分辨率 | 码率范围（H.264） | 码率范围（H.265） |
|--------|------------------|------------------|
| 480p | 0.5–1.5 Mbps | 0.3–1.0 Mbps |
| 720p | 1.5–4 Mbps | 1.0–2.5 Mbps |
| 1080p | 4–8 Mbps | 2.5–5 Mbps |
| 4K (2160p) | 15–35 Mbps | 10–20 Mbps |

## 6. 容器格式（Container Format）

容器格式是"打包"视频流、音频流、字幕、元数据的文件格式。

```
容器文件（如 MP4）
  ┌─────────────────────────────────────┐
  │ 文件头（File Header）                │
  │  ├─ moov box（元数据：时长、分辨率等） │
  │  └─ ftyp box（兼容性标志）            │
  ├─────────────────────────────────────┤
  │ 视频轨道（Video Track）              │
  │  ├─ H.264/H.265 编码流              │
  │  └─ 帧索引（关键帧位置）              │
  ├─────────────────────────────────────┤
  │ 音频轨道（Audio Track）              │
  │  ├─ AAC/MP3/Opus 编码流             │
  │  └─ 采样率、声道信息                 │
  ├─────────────────────────────────────┤
  │ 字幕轨道（可选）                     │
  │  └─ SRT/VTT 文本或图形字幕           │
  └─────────────────────────────────────┘
```

### 常见容器对比

| 容器 | 扩展名 | 优点 | 缺点 |
|------|--------|------|------|
| **MP4** | .mp4 | 最广泛兼容、基于 ISOBMFF 标准 | 不支持字幕流（需内嵌） |
| **MKV** | .mkv | 功能最全（任意编码、多字幕、章节） | 兼容性不及 MP4 |
| **AVI** | .avi | 老旧但简单 | 不支持现代特性 |
| **TS** | .ts | 流媒体传输、抗丢包 | 文件冗余大 |
| **FLV** | .flv | RTMP 直播常用 | 功能有限 |
| **WebM** | .webm | 开放格式、VP9/Opus | 兼容性一般 |

### MP4 的逻辑结构（ISOBMFF）

```
MP4 文件 = 一系列 Box（又称 Atom）组成的树状结构

ftyp ── 文件类型（File Type Box）
  |
moov ── 元数据（Movie Box）
  ├─ trak 1 ── 视频轨道
  │   ├─ tkhd (轨道头)
  │   ├─ mdia
  │   │   ├─ mdhd (媒体头)
  │   │   ├─ hdlr (处理器类型)
  │   │   └─ minf → stbl → stsd/stsz/stco/stss...
  │   └─      (stbl = Sample Table，关键帧索引)
  └─ trak 2 ── 音频轨道
       └─ ...
  |
mdat ── 媒体数据（Media Data Box，音视频帧实际数据）
```

> **关键帧索引（stss box）**：容器需要知道哪些帧是关键帧（I帧），才能支持随机定位（快进/后退）。

## 7. 音视频基本流程

```
   ┌──────────┐    ┌──────────┐    ┌──────────┐
   │ 采集设备  │───→│ 模数转换  │───→│ 编码器   │
   │(摄像头/麦) │    │(ADC芯片)  │    │(H.264等) │
   └──────────┘    └──────────┘    └─────┬────┘
                                         │
   ┌──────────┐    ┌──────────┐          │
   │ 播放/渲染 │←───│ 解码器   │←───┐    │
   │(屏幕/喇叭) │    │(解码)    │    │    │
   └──────────┘    └──────────┘    │    │
                                   │    │
                              ┌────┴────┴────┐
                              │   容器封装    │
                              │   (MP4/MKV)  │
                              └──────────────┘
```

## 8. 关键公式速查

| 公式 | 含义 |
|------|------|
| `数据量 = 宽 × 高 × 位深度 × 帧率 × 时长` | 未压缩视频原始大小 |
| `码率 = 文件体积 / 时长` | 平均码率计算 |
| `SNR (dB) = 6.02 × n + 1.76` | n-bit 量化理论信噪比 |
| `采样率 ≥ 2 × 最大频率` | 奈奎斯特采样定理 |
| `YUV 4:2:0 大小 = W × H × 1.5 字节` | 相对 RGB24 = W×H×3，节省 50% |

# 第3课：H.264 / H.265 / AV1 — 编码结构、率失真优化与码率控制

## 1. 概述

本课深入三个主流视频编码标准的核心。H.264/AVC（2003）至今仍是应用最广的编码器；H.265/HEVC（2013）在同等质量下比 H.264 节省 40-50% 码率；AV1（2018）是开放、免专利费的后起之秀。

我们将对比它们的编码结构差异（GOP/Slice/MB/CU/TU/PU）、率失真优化（RDO）算法和码率控制机制。

---

## 2. 编码结构对比

### 2.1 宏观结构 — GOP（Group of Pictures）

**GOP 是所有编码标准共有的概念**，但具体实现不同。

```
H.264 典型 GOP:
IDR  B  B  P  B  B  P  B  B  P  IDR
 ├─── 封闭 GOP ───┤  ├─── 开放 GOP ──┤
 无参考跨边界         可参考前一 GOP 的帧
```

**GOP 长度对编码的影响**：
- **短 GOP（如 12 帧）**：随机定位快，但 I 帧多，压缩率低
- **长 GOP（如 250 帧）**：压缩率高，但随机定位慢

**场景切换检测**：编码器检测到场景变化时，自动插入 IDR 帧（Instantaneous Decoder Refresh），切断与之前帧的所有引用。

### 2.2 帧内编码单元对比

这是三种标准最核心的区别：

```
H.264 (Macroblock 宏块):
  ┌────────────────────────────┐
  │ 16×16 MB                  │
  │  ┌────┬────┬────┬────┐    │
  │  │ 4×4 │ 4×4 │ 4×4 │ 4×4 │    ← 最小 4×4
  │  ├────┼────┼────┼────┤    │
  │  │ 4×4 │ 4×4 │ 4×4 │ 4×4 │
  │  ├────┼────┼────┼────┤    │
  │  │ 4×4 │ 4×4 │ 4×4 │ 4×4 │
  │  ├────┼────┼────┼────┤    │
  │  │ 4×4 │ 4×4 │ 4×4 │ 4×4 │
  │  └────┴────┴────┴────┘    │
  └────────────────────────────┘
  
  分区模式: 16×16, 16×8, 8×16, 8×8, 8×4, 4×8, 4×4
  帧内预测: 4×4(9种) / 16×16(4种)
```

```
H.265 (CTU/CU/PU/TU 四叉树):
  ┌────────────────────────────┐
  │ 64×64 CTU (Coding Tree Unit)  │
  │  ┌────────┬────┬──┬──┬──┐  │
  │  │        │ CU │  │  │  │  │  ← 递归分裂
  │  │  CU    ├────┴──┴──┤  │  │     64→32→16→8
  │  │        │          │  │  │
  │  ├────────┤   CU     ├──┤  │
  │  │        │          │  │  │
  │  │  CU    ├──────────┤  │  │
  │  │        │          │  │  │
  │  └────────┴──────────┴──┴──┘  │
  └────────────────────────────┘
  
  CTU 最大 64×64（可配置为 128×128）
  CU = Coding Unit（编码单元）
  PU = Prediction Unit（预测单元）
  TU = Transform Unit（变换单元）
  PU 和 TU 独立于 CU，自由度更高
```

```
AV1 (超块 + 递归分区):
  ┌────────────────────────────┐
  │ 128×128 Superblock        │
  │  ┌────┬────┬──┬──┬──┬──┐  │
  │  │    │    │  │  │  │  │  │  ← 灵活的矩形分区
  │  │    │    │  │  │  │  │  │     4:1 / 1:4 矩形
  │  ├────┼────┼──┴──┤  │  │  │     也支持
  │  │    │    │     │  │  │  │
  │  ├────┼────┤     │  │  │  │
  │  │    │    ├─────┤  │  │  │
  │  └────┴────┴─────┴──┴──┴──┘  │
  └────────────────────────────┘
  
  Superblock 最大 128×128
  支持 PARTITION_NONE, PARTITION_VERT, PARTITION_HORIZ
  以及多种组合分区
```

### 2.3 编码结构演进对比表

| 特性 | H.264 | H.265/HEVC | AV1 |
|------|-------|------------|-----|
| 最大块大小 | 16×16 | 64×64 | 128×128 |
| 分区方式 | MB + 子分区 | 四叉树递归 | 四叉树 + 矩形 |
| 最小块 | 4×4 | 8×8 / 4×4 | 4×4 |
| 预测/变换分离 | 否（PU=TU） | 是（CU/PU/TU 独立） | 是 |
| 帧内预测模式 | 9 (4×4) + 4 (16×16) | 35 (33角度+DC+Planar) | 56种 |
| 运动补偿精度 | 1/4 像素 | 1/4 像素 + DCT-IF | 1/8 像素（部分） |
| 变换类型 | DCT 4×4/8×8 | DCT/DST 4×4~32×32 | DCT/ADST/Flipadst |
| 熵编码 | CABAC/CAVLC | CABAC | 多符号算术编码 |

## 3. Slice、Tile 与并行编码

### 3.1 Slice（片）

Slice 是将一帧划分为多个独立的编码区域，每个 Slice 可独立解码：

```
一帧划分为多个 Slice（常用于低延迟 / 丢包恢复）:
┌───┬───┬───┐
│ S │ S │ S │  ← 每个 Slice 有独立的熵编码状态
│ 0 │ 1 │ 2 │    一个 Slice 丢失不影响其他 Slice
├───┼───┼───┤
│ S │ S │ S │
│ 3 │ 4 │ 5 │
├───┼───┼───┤
│ S │ S │ S │
│ 6 │ 7 │ 8 │
└───┴───┴───┘
```

**Slice 的代价**：Slice 边界不能跨块预测，会带来 1-5% 的编码效率损失。

### 3.2 Tile（瓦片）— H.265/AV1

Tile 是比 Slice 更高效的并行单元：

```
Tile 划分（H.265/AV1）:
┌─────────────┬─────────────┐
│             │             │
│   Tile 0     │   Tile 1    │  ← 每个 Tile 包含
│             │             │     完整的 CTU 行
│   ──────────┼─────────────┤
│   Tile 行边界│             │
├─────────────┼─────────────┤
│             │             │
│   Tile 2     │   Tile 3    │
│             │             │
└─────────────┴─────────────┘

Tile 边界禁止帧内预测跨越 → 多线程编码
```

### 3.3 Wavefront Parallel Processing（WPP）

H.265 引入 WPP，Slice 内的并行方式：

```
CTU 行 0: ┌─→─→─→─→─→─→─→─┐  ← 开始编码
CTU 行 1: ┌───┐→─→─→─→─→─→─┤  ← 延迟 2 CTU 后开始
CTU 行 2: ┌───┐───┐→─→─→─→─┤  ← 进一步延迟
...
           ↑ 上下文依赖关系允许 2 CTU 延迟后并行
```

WPP 在保持编码效率的同时提供多核加速，比 Tile 更受推荐。

## 4. 率失真优化（Rate-Distortion Optimization, RDO）

### 4.1 基本概念

编码器面临的根本权衡：**码率越低，失真越大**。

```
质量 (PSNR / SSIM)
  ↑
  │         ● ← 无损 (QP=0, 码率极高)
  │        ·
  │       ·
  │      ·  ● ← 良好折中点 (RDO 目标)
  │     ·
  │    ·  ● ← 低码率 (高 QP)
  │   ·
  │  ·
  │ · ● ← 极低码率 (严重失真)
  └────────────────────→ 码率 (kbps)
```

**率失真函数**：给定失真 D，存在理论最小码率 R(D)。

### 4.2 RD 代价函数

编码器为每个编码决策计算 RD 代价：

```
J = D + λ × R

其中:
  J  = RD Cost（越小越好）
  D  = 失真 (Distortion, 如 MSE / SSD / SAD)
  R  = 码率 (Rate, 编码该块所需的 bits)
  λ  = 拉格朗日乘子 (Lagrange Multiplier)
```

**λ 的选择**：λ 随 QP 变化

```
H.264/HEVC 中 λ 与 QP 的关系:
λ = 0.85 × 2^((QP - 12) / 3)

QP 低 → λ 小 → 更重视质量（低失真）
QP 高 → λ 大 → 更重视码率节省
```

### 4.3 RDO 的实际应用

编码器做模式决策时的过程：

```
对于每个编码块:

          ┌──────────────────────┐
          │ 遍历所有候选模式      │
          │ ┌────────────────┐   │
          │ │ 帧内预测 × N 模式 │   │
          │ │ 帧间预测 × M 模式 │   │
          │ │ 运动矢量 × K 候选 │   │
          │ │ 分区大小 × T 种   │   │
          │ └────────────────┘   │
          │          ↓            │
          │ 计算每个模式的        │
          │ J = D + λR            │
          │          ↓            │
          │ 选择 J 最小的模式     │
          └──────────────────────┘
```

### 4.4 H.265 的 RDO 层级

```
Level 0: CU 分裂决策（四叉树）
  ├─ 64×64 vs 2×32×32
  │   ├─ 32×32 vs 4×16×16
  │   │   ├─ 16×16 vs 4×8×8
  │   │   └─ ...
  │   └─ ...
  └─ ...

Level 1: 预测模式选择（帧内/帧间/Skip/Direct）
Level 2: PU 分区形状
Level 3: 运动矢量候选（Merge/MVP/AMVP）
Level 4: 变换类型（DCT/DST）
Level 5: 量化参数微调
```

完整的 RDO 计算量极大。实际编码器使用**快速算法**提前剪枝候选。

## 5. 码率控制（Rate Control）

### 5.1 控制目标

码率控制决定**每个区域分配多少码率**，以在给定目标码率下获得最佳质量。

```
码率控制的三级分配:
┌────────────────────────────────────┐
│ 全局级 (Global):  整段视频的总码率  │  → VBR/CBR/CRF
├────────────────────────────────────┤
│ GOP级 (GOP):     各 GOP 的码率分配  │  → 场景复杂度
├────────────────────────────────────┤
│ 帧级 (Frame):    各帧的 QP 决策     │  → I/P/B 帧权重
├────────────────────────────────────┤
│ 块级 (Block):    各块的 QP 微调     │  → 视觉显著性
└────────────────────────────────────┘
```

### 5.2 三种经典码率控制模式

**CBR（恒定码率）**：
```
码率
  ───────┬───┬───┬───┬───┬───┬─── 目标码率 R
        │   │   │   │   │   │
缓冲占用: ▓▓░░░░░░  → 调整 QP 维持恒定输出
        不足则降低 QP（高质量）
        超额则升高 QP（降低质量）
```

**VBR（可变码率）**：
```
码率
    ██        ██
  ██  ██    ██  ██    ██  ← 复杂场景高码率
  ██  ██  ██  ██  ██  ██
  ██  ████████████████████
       └─ 简单场景低码率 ─┘
```

**CRF（恒定质量）— x264/x265 独创**：
```
CRF = 恒定 QP 偏移
  CRF 18 → 视觉无损（适合存档）
  CRF 23 → 默认（良好平衡）
  CRF 28 → 高压缩（适合流媒体）
  CRF 35 → 极高压缩（明显失真）

CRF 模式的优点：一次编码，不用设目标码率
              质量恒定的同时自动适应场景复杂度
```

### 5.3 缓冲区管理（VBV/HRD）

```
编码器输出 → [VBV Buffer] → 恒定码率输出
              ↑  满则降质     ↓
          编码器调整QP    解码器读取

VBV (Video Buffering Verifier): 确保码流不溢出/不下溢
├─ 缓冲区过满 → 升高 QP（降低码率）
├─ 缓冲区过低 → 降低 QP（提高码率）
└─ 缓冲区模型决定最大/最小瞬时码率
```

### 5.4 实际码率控制算法对比

| 算法 | 编码器 | 特点 |
|------|--------|------|
| ABR (Average Bitrate) | x264/x265 | 目标平均码率，自动分配 |
| CBR (Constant Bitrate) | 硬件编码器 | 直播、实时通信必备 |
| CRF (Constant Rate Factor) | x264/x265 | 一次通过、质量恒定 |
| 2-Pass VBR | 所有 | 精确控制，需要预先分析 |
| CQP (Constant QP) | 调试用 | 固定 QP，不加码率控制逻辑 |

## 6. H.264 ↔ H.265 ↔ AV1 编码效率对比

```
编码效率（同等主观质量下所需码率）:

H.264 (High Profile)    ════════════════════ 100% (基准)
H.265 (Main Profile)    ════════════════     ≈ 55-65%
AV1 (All Intra)         ═════════════        ≈ 50-60%
AV1 (Random Access)     ══════════           ≈ 40-50%

经验法则:
  H.265 比 H.264 约省 50% 码率
  AV1  比 H.265 约省 20-30% 码率
  但 AV1 编码复杂度比 H.265 高 5-10 倍
```

### 编码速度对比

```
编码器      速度 (相对)     适用场景
H.264 (x264)   1× (基准)      实时编码、直播、旧设备
H.265 (x265)   2-5×           离线编码、4K 发布
H.265 (NVENC)  10-50×         实时直播、游戏录屏
AV1 (libaom)   50-500×        离线制作、OOF 压制
AV1 (SVT-AV1)  20-100×        开源高速 AV1 实现
AV1 (AVE)      2-5×           硬件 AV1 编码（非常快）
```

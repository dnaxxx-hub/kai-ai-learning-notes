# 知识图谱与语义检索 — 从线性列表到关联网络

> 学习时间：2026-05-12 13:44
> 定位：方向3 — 让231条桥接知识变成真正可遍历的关联网络

## 现状问题

- 知识桥：扁平JSON列表，知识A和知识B互不知道对方存在
- MEMORY.md：按时间线+主题分类，但没有跨条目链接
- 学习笔记：169个独立文件，唯一的关联靠关键词搜索

## 轻量图谱方案

### 目标：不引入重型数据库，在文件系统层面建立关联

**方案：简单的关联文件 + 心跳遍历**

### 数据结构
```
memory/knowledge_graph/
├── nodes.json       — 所有知识点节点（ID + 名称 + 摘要）
├── edges.json       — 关联边（source → target + 关联类型）
└── recent_path.md   — 最近遍历的路径（"2条6跳"）
```

### 关联类型
| 类型 | 含义 | 示例 |
|------|------|------|
| prerequisite | 前置知识 | "线性代数"→"PCA" |
| extension | 自然延伸 | "CNN"→"ResNet" |
| application | 应用关系 | "Transformer"→"BERT" |
| contrast | 对比关系 | "B+树"↔"LSM树" |
| cross_domain | 跨域桥接 | "RL"→"量化交易Agent" |

### 自驱动遍历
- 每次心跳从目前节点出发，走1步到相邻节点
- 记录路径日志（"从A→B→C，2条边"）
- 这形成自然的探索循环：不需要刻意安排学习顺序

### 与现有系统集成
- 知识桥注册时，自动检查已有节点，添加关联边
- 好学笔记写完时，自动解析关联关系
- 心跳巡检时输出"当前知识路径建议"

## 最小可行实现
1. 建 `memory/knowledge_graph/` 目录
2. 从笔记文件名和知识桥标题自动提取节点
3. 从已有的"方向"分配推断初始关联
4. 心跳时做1次知识路径遍历

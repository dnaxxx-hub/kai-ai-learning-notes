# 推荐系统 #1：召回→排序→重排工业化链路

> 工业级推荐系统的三段论：从海量候选到精准投放，每一步都在做信息筛选与平衡。

---

## 引言

推荐系统是互联网产品的核心引擎之一——短视频 Feed、电商商品推荐、新闻信息流、YouTube 视频推荐，无不依赖推荐系统将信息与人匹配。工业推荐系统采用经典的 **三段式流水线架构**：

```
百亿候选 → 召回(M→千级) → 排序(千→百级) → 重排(百→展示) → 用户
```

- **召回（Retrieval）**：从百万/亿级物品池中快速筛选出数百到数千个候选，追求高召回率和高吞吐。
- **排序（Ranking）**：对召回结果做精细打分，用复杂模型（DNN、CrossNet、Attention）精确预估点击率/转化率。
- **重排（Re-ranking）**：根据业务规则调整最终展示列表——多样性、打散、广告插入、上下文去重。

本文是推荐系统系列第一篇，覆盖从全景认知到各阶段核心技术，每节包含：原理 → 公式 → 工业实现 → 优缺点。

## 第一章：推荐系统全景

### 1.1 推荐 vs 搜索

| 维度 | 推荐 | 搜索 |
|------|------|------|
| 用户意图 | 模糊/无明确意图 | 明确查询意图 |
| 输入 | 用户画像+行为序列+上下文 | 查询词（Query） |
| 核心指标 | 留存、时长、多样性 | 相关性、精确率 |
| 候选量级 | 百万~十亿 | 十万~千万（索引过滤后） |
| 漏斗 | 召回→排序→重排 | 倒排索引→精排 |

**核心差异**：搜索是"找已知"，推荐是"发现未知"。推荐需要主动探索用户潜在兴趣，因此冷启动和多样性天然比搜索更重要。

### 1.2 推荐系统核心指标

**在线指标（业务层）**：
- **CTR（Click-Through Rate）**：曝光→点击率，预估目标是 pCTR
- **CVR（Conversion Rate）**：点击→转化率，预估目标是 pCVR
- **停留时长、完播率、互动率**：内容型推荐的核心
- **GMV（商品交易总额）**：电商场景

**离线指标（模型层）**：
- **AUC（Area Under ROC Curve）**：排序能力，随机正样本排在负样本前面的概率。AUC=0.5 表示随机，1.0 完美。工业通常 0.75~0.85
- **NDCG（Normalized Discounted Cumulative Gain）**：考虑排序位置的加权指标，适合 Top-K 评估
- **HitRate / Recall**：召回阶段核心指标，衡量候选池覆盖真实正样本的比例
- **Precision@K**：推荐列表前 K 个中有多少是用户感兴趣的

### 1.3 冷启动问题

| 类型 | 问题 | 常见解法 |
|------|------|----------|
| **新用户** | 无历史行为 → 无法计算用户向量 | 人口统计学属性（年龄/性别/地域），热门推荐，冷启探索策略（ε-greedy、Thompson Sampling） |
| **新物品** | 无交互记录 → 无法预估 CTR | 内容特征（标题/图像/标签）替代协同信号，基于内容的推荐（Content-based） |
| **系统冷启动** | 全新平台无数据 | 专家规则+人工运营，逐步收集用户数据后切换到模型 |

### 1.4 数据与特征工程基础

推荐系统的输入特征大致分为四类：

1. **用户特征**：User ID、年龄、性别、地域、历史行为序列（最近点击的 N 个 Item ID）、统计特征（近 7 天点击率）
2. **物品特征**：Item ID、类目、标签、标题向量、发布时间、价格（电商）
3. **上下文特征**：时间（星期几、是否节假日）、设备（iOS/Android）、网络（WiFi/4G）
4. **交叉特征**：用户×物品组合特征，如"用户偏好的类目 × 物品类目"

**特征处理关键点**：
- **离散特征** → One-Hot / Embedding（大规模 ID 化特征使用 Embedding 降维）
- **连续特征** → 分桶离散化（Bucketize）或 Z-Score 标准化
- **时序特征** → 窗口统计（7天/30天滑动）、衰减加权
- **特征交叉** → 手工交叉（Wide）、自动交叉（FM/CrossNet）

## 第二章：召回（Retrieval）

召回的核心目标是从全量候选池（百万~十亿级）中快速筛选出数百~数千个最相关的物品。它追求 **高召回率 × 低延迟**。

### 2.1 协同过滤（Collaborative Filtering）

**原理**：利用"用户-物品交互矩阵"中的协同信号，相似用户喜欢相似的物品。

#### User-CF（基于用户的协同过滤）

找到与目标用户最相似的 K 个用户，将他们喜欢的物品推荐给目标。

相似度计算（余弦相似度）：
```
sim(u, v) = (r_u · r_v) / (||r_u|| × ||r_v||)
```
其中 r_u 是用户 u 的交互向量。

预测评分：
```
pred(u, i) = Σ_{v ∈ N(u)} sim(u, v) × r_{vi} / Σ_{v ∈ N(u)} |sim(u, v)|
```

**工业实现**：离线计算用户相似度矩阵（Item-to-Item 缓存），线上查找 Top-K 近邻的交互物品。Amazon 早期就用 Item-CF("买了也买了")。

**优缺点**：
- ✅ 简单、可解释（"因为你认识的某人喜欢它"）
- ❌ 稀疏矩阵下效果差，可扩展性 O(N²)，冷启动失效

#### Item-CF（基于物品的协同过滤）

核心假设：**用户会喜欢与过去喜欢的物品相似的物品**。

```
sim(i, j) = (r_i · r_j) / (||r_i|| × ||r_j||)
```

**优于 User-CF**：
- 物品数通常远少于用户数，矩阵更稳定
- 物品相似度更新频率低于用户相似度
- 适合离线预计算，线上 O(1) 查表

**工业经典**：Amazon"买了 A 的人也买了 B"，YouTube 早期推荐。

### 2.2 矩阵分解（Matrix Factorization）

**原理**：将用户-物品交互矩阵分解为两个低秩矩阵的乘积，用隐向量（Latent Factor）表示用户和物品。

#### SVD（奇异值分解）

$$
R_{m×n} ≈ U_{m×k} Σ_{k×k} V_{k×n}^T
$$

R 为用户-物品矩阵（m 个用户，n 个物品），分解后的 U 为用户隐向量矩阵，V 为物品隐向量矩阵。

**问题**：原始 SVD 要求矩阵稠密，工业交互矩阵极度稀疏 → 用 FunkSVD 或 ALS。

#### FunkSVD（隐式分解）

最小化观测交互的 MSE：
$$
\min_{p, q} Σ_{(u,i) ∈ R} (r_{ui} - p_u · q_i)^2 + λ(||p_u||² + ||q_i||²)
$$

其中 p_u 是用户 u 的 k 维隐向量，q_i 是物品 i 的 k 维隐向量。

#### ALS（Alternating Least Squares，隐式反馈专用）

针对隐式反馈（点击、浏览、收藏等0/1信号），引入置信度权重：
$$
\min Σ_{u,i} c_{ui}(p_{ui} - x_u^T y_i)^2 + λ(Σ||x_u||² + Σ||y_i||²)
$$
其中 c_{ui} = 1 + α r_{ui}（正反馈赋予更高置信度），p_{ui} = 1 if r_{ui} > 0 else 0

**工业实现**：Spark MLlib ALS 是经典实现，适合大规模分布式训练。

**优缺点**：
- ✅ 比 CF 更抗稀疏，隐向量可做特征输入
- ❌ 无法利用用户/物品属性特征（冷启动受限）；离线预测

### 2.3 双塔模型（DSSM / Two-Tower Model）

**原理**：用户侧和物品侧各用一个 DNN 编码，将用户和物品映射到同一隐空间，内积/余弦为匹配分数。

```
u_emb = UserTower(user_features)
i_emb = ItemTower(item_features)
score(u, i) = <u_emb, i_emb>
```

**训练**：Sampled Softmax 或 NCE Loss（负采样），每个正样本搭配 N 个负样本。

```
L = -log( exp(<u_emb, i_pos>) / (exp(<u_emb, i_pos>) + Σ_{j=1}^{N} exp(<u_emb, i_neg_j>)))
```

**工业实现**：
- **离线**：训练双塔，计算所有物品向量（T+1 更新）。
- **在线**：用户塔实时计算用户向量 → 到向量检索库（FAISS/HNSW）查询 Top-K 最邻近物品向量。

**优缺点**：
- ✅ 用户/物品侧可加入任意特征（属性、上下文），缓解冷启动；线上推理快（用户向量实时算，物品向量离线预计算，近似最近邻检索）
- ❌ 双塔交互过于简单（最后一步才内积），表达能力弱于排序模型

### 2.4 图召回（Graph-based Retrieval）

**原理**：将用户和物品视为图的节点，交互为边，利用图结构学习节点表示。

#### Node2Vec

随机游走生成节点序列，用 Word2Vec（Skip-gram）学习 Embedding。引入 p/q 参数控制 BFS/DFS 采样偏好：
- p 小 → 偏向 BFS（局部结构），q 小 → 偏向 DFS（同质社区）

#### GraphSAGE

归纳式（Inductive）学习，通过聚合邻居节点信息生成节点表示：
```
h_v^{(k)} = σ(W · AGG({h_v^{(k-1)}} ∪ {h_u^{(k-1)}, ∀u ∈ N(v)}))
```
AGG 可以是 Mean / Pooling / LSTM。

**工业实现**：PinSage（Pinterest）在 30 亿图上的图卷积实现，使用随机游走生成训练样本。

**优缺点**：
- ✅ 能捕获高阶协同信号（二度、三度关联），冷启动可通过邻居聚合缓解
- ❌ 训练成本高，大规模图存储维护复杂

### 2.5 多路召回与粗排

工业场景不会只用一路召回，而是 **多路并发**：

| 召回通路 | 候选量级 | 特点 |
|----------|----------|------|
| 协同过滤（Item-CF） | 千~万 | 依赖交互信号 |
| 双塔向量召回 | 千~万 | 可加入属性特征 |
| 图召回 | 百~千 | 高阶关联 |
| 热门召回 | 百 | 兜底 + 冷启动 |
| 同城召回（LBS） | 百~千 | 地理位置 |
| 语义召回（标签/标题） | 百~千 | 内容相似 |

**多路融合策略**：
1. **Score 融合**：简单加权分 / 学习一个 Lightweight 排序模型（粗排）对齐各路分数。
2. **截断 TOP N**：每路取 Top-K，合并去重后送入排序阶段，通常总候选控制在 500~2000。

**粗排（Pre-ranking）**：介于召回和精排之间，用一个轻量模型（如双塔/小 MLP）在几千候选上粗筛，减少精排压力。

### 2.6 向量检索（FAISS / HNSW）

当双塔等产出稠密向量后，需要在海量物品向量中快速找到 Top-K 最近邻，这就是 **近似最近邻检索（ANN）**。

#### FAISS（Facebook）

- **IVF（Inverted File Index）**：K-means 聚类划分空间，检索时只搜索最近簇
- **PQ（Product Quantization）**：向量拆分子空间量化压缩，内存压缩 4~32 倍
- **IVF+PQ**：组合使用，工业最常见

#### HNSW（Hierarchical Navigable Small World）

分层跳表结构 + 小世界图：
- 最高层稀疏连接，快速定位区域
- 低层密集连接，精确找到最近邻
- 搜索复杂度 O(log N)，内存消耗较大

**优缺点**：
- ✅ FAISS：训练快、压缩率高、支持 GPU（百万级检索 <10ms）
- ✅ HNSW：搜索精度高、速度快（千万级 1~5ms）
- ❌ HNSW 建图慢、内存大；FAISS 召回率受量化粒度影响

## 第三章：排序（Ranking）

排序阶段对召回结果逐条精细打分，目标是预估用户对物品的点击/转化/时长等指标的概率。主流采用 **CTR/CVR 预估模型**。

### 3.1 Logistic Regression（Wide Model）

**原理**：在线性模型基础上套 Sigmoid，输出 [0,1] 概率。

$$
pCTR = σ(w · x + b) = 1 / (1 + e^{-(w·x + b)})
$$

其中 x 是特征向量（One-Hot 编码后的稀疏向量），w 是权重。

**工业实现**：Google 2013 年之前在广告系统广泛使用，使用 FTRL（Follow The Regularized Leader）在线学习。

**优缺点**：
- ✅ 可解释性极强（权重直接反映特征重要性），训练快，分布式中易扩展
- ❌ 表达能力有限，无法自动学习特征交叉——需要大量人工特征工程（如 `user_city × item_category`）

### 3.2 FM / FFM（Factorization Machine）

#### FM（二阶特征交叉）

在 LR 基础上加入所有二阶特征交叉项的隐向量内积：

$$
\hat{y}(x) = w_0 + Σ_{i=1}^n w_i x_i + Σ_{i=1}^n Σ_{j=i+1}^n ⟨v_i, v_j⟩ x_i x_j
$$

其中 v_i 是特征 i 的 k 维隐向量。二阶项复杂度从 O(n²) 优化到 O(kn)——通过矩阵分解技巧。

**为什么 FM 比 LR 强**：可以学到稀疏特征之间的相关性。例如"用户在北京"×"物品类别=火锅"——即使训练集中这条交叉样本极少，FM 也能通过各自的隐向量计算相似度。

#### FFM（Field-aware FM）

每个特征对不同 Field 学习不同的隐向量。例如"用户地域"对"物品类目"和"用户年龄段"的隐向量不同：
$$
⟨v_{i, f_j}, v_{j, f_i}⟩ x_i x_j
$$

**优缺点**：
- ✅ FM：自动二阶交叉，防止过拟合（隐向量共享参数）；FFM：交叉建模更精细
- ❌ FFM 参数量 O(n×f×k)，训练慢；FM/FFM 只到二阶交叉，无法更高阶

### 3.3 Wide & Deep（Google 2016）

**架构**：Wide 线性模型（记忆） + Deep 神经网络（泛化），联合训练。

```
Wide: y = w^T[x, φ(x)]          # 手工交叉特征组合
Deep: a^{(l+1)} = σ(W^{(l)}a^{(l)} + b^{(l)})  # Embedding + MLP
Final: pCTR = σ(y_wide + y_deep + b)
```

**工业实现**：Google Play 应用推荐系统首次提出，Wide 部分用 FTRL+L1 学习稀疏特征，Deep 部分用 AdaGrad。

**优缺点**：
- ✅ Wide 记住高频模式（如"安装了浏览器→推荐浏览器"），Deep 泛化到未见组合
- ❌ Wide 侧需要手工设计交叉特征，Wide+Deep 两组参数分开优化较繁琐

### 3.4 DeepFM（Huawei 2017）

**架构**：用 FM 替代 W&D 中的 Wide 部分——FM 自动做二阶交叉，Deep 做高阶交叉。

```
y = sigmoid(y_FM + y_DNN)
y_FM = <w, x> + Σ_i Σ_{j>i} <v_i, v_j> x_i x_j
y_DNN = MLP(concat(e_1, e_2, ..., e_n))
```

**关键设计**：FM 和 Deep **共享**底层的 Embedding 向量，合起来端到端训练。

**优缺点**：
- ✅ 无需手工特征交叉（FM 自动 + Deep 高阶），共享 Embedding 减少参数量，工业界广泛采用
- ❌ 仍然是固定阶交叉（FM 二阶 + DNN 隐式高阶），注意力不可控

### 3.5 DIN（Deep Interest Network，Alibaba 2018）

**核心创新**：用户历史行为序列中不同物品对候选物品的影响权重不同——**注意力机制**。

```
v_U(A) = Σ_{j=1}^N a(v_j, v_A) · v_j
a(v_j, v_A) = exp(MLP(concat(v_j, v_A, v_j⊙v_A))) / Σ_k exp(MLP(concat(v_k, v_A, v_k⊙v_A)))
```

其中 v_j 是用户历史行为的物品 Embedding，v_A 是候选物品 Embedding，注意力权重由一个小 MLP 学习。

**通俗理解**：要判断用户是否会点击"MacBook Pro"，系统会关注用户历史中的"MacBook Air"和"iPhone"（权重大），而忽略"牙膏"。

**工业实现**：阿里展示广告系统，使用 Mini-Batch Aware Regularization + Dice Activation。

**优缺点**：
- ✅ 对用户行为序列建模极强，注意力天然可解释（可视化为权重热力图）
- ❌ 长序列计算量大（需优化：DIN 的序列长度通常限制在 50~200）

### 3.6 多目标排序（Multi-Task Learning）

**问题**：用户行为链路：曝光→点击→收藏/加购→支付。单目标 CTR 模型只优化"点击"，忽略后续转化。

主流多目标框架：

#### MMOE（Multi-gate Mixture-of-Experts，Google 2018）

```
shared_experts = [Expert_1(x), Expert_2(x), ..., Expert_k(x)]
for task t:
    gate_t(x) = Softmax(W_t · x)
    tower_input_t = Σ_i gate_t(x)_i · Expert_i(x)
    y_t = Tower_t(tower_input_t)
```

每个任务有自己的门控（Gate），从共享的 Expert 集合中选择性地提取信息。

#### PLE（Progressive Layered Extraction，Tencent 2020）

MMOE 的改进：引入"任务专属 Expert" + "共享 Expert"分层的架构，缓解任务之间的负迁移（Seesaw Phenomenon）。

**工业实现**：
- 电商：通常同时预估 CTR + CVR（曝光→点击→转化）
- 短视频：CTR + 完播率 + 互动率 + 关注率
- 多目标加权：`score = w₁×pCTR + w₂×pFinishRate + w₃×pShare`

**优缺点**：
- ✅ 单模型同时优化多目标，共享底层表示增强泛化
- ❌ 任务间冲突（如"点击率高的标题党" vs "停留时长长的优质内容"），调参复杂（Expert 数量、Loss 权重）

## 第四章：重排（Re-ranking）

排序模型输出的是"单点最优"——每条物品独立打分。但最终展示列表需要**整体最优**：多样性、去重、上下文互影响。

### 4.1 MMR 算法（Maximal Marginal Relevance）

**公式**：在相关性（Relevance）和多样性（Diversity）之间做最大化边际收益。

```
MMR = argmax_{i ∈ R\S} [ λ · Rel(i) - (1-λ) · max_{j ∈ S} sim(i, j) ]
```

- **S**：已选入最终列表的物品
- **R**：剩余候选
- **λ**：多样性强度控制参数（λ=1 只有相关性，λ=0 只有多样性）
- **sim(i, j)**：物品 i 和 j 的相似度（可用类目/标签/向量余弦）

**工作过程**：贪心逐位置选取，每步选一个让"相关性减去与已选列表最大相似度"最大的物品。

**优缺点**：
- ✅ 效果直观可控（λ 可调），计算效率高（O(K²)）
- ❌ 贪心顺序依赖，无法全局最优；相似度定义依赖特征质量

### 4.2 打散策略（滑动窗口去重）

工业中最简单有效的方法之一：

```
窗口大小 W（如 5），滑动向前。
第 i 个位置展示时，与它前面 W 个物品比较：
- 如果类目重复 → 跳过，尝试下一个候选
- 如连续跳过 M 次仍找不到 → 放弃去重要求，取第一个
```

**变体**：
- **硬打散**：相邻 N 个不能同类别（新闻场景：连续两条体育新闻可以，但三条不行）
- **软打散**：带惩罚系数的重排，同一作者/来源的物品相邻时降低分数

### 4.3 上下文感知重排

**问题**：排序模型假设物品间独立，但实际展示列表中物品互有影响。

**DLCM（Deep Listwise Context Model）**：用一个 GRU/RoBERTa 编码已选列表的上下文，影响下一个物品的选取决策。

**DPP（Determinantal Point Process）**：基于核矩阵的行列式建模——同时考虑每个物品的质量和物品间相似度（多样性越高，核矩阵行列式越大）。

$$
P(S) = det(K_S) / det(K + I)
$$

其中 K 是核矩阵（Quality × Diversity），选择使行列式最大的物品集合 S。

### 4.4 业务规则插入

重排也是"策略插入"的最后机会：
- **广告穿插**：每 N 个物品之间插入一条广告，广告按照收益排序
- **强运营策略**：置顶某条内容、固定位置轮播
- **频控**：同一用户近期看过的内容降权或去重
- **合规过滤**：屏蔽敏感内容、版权物品

## 第五章：在线 A/B 测试

模型离线 AUC 涨了，不代表线上业务指标一定涨。**A/B 测试（分桶实验）**是验证推荐系统效果的唯一金标准。

### 5.1 流量分桶

**核心原则**：实验组和对照组的流量必须是同质的、不互相干扰的。

#### Hash 分桶

```
bucket_id = hash(user_id + experiment_id) % N
```

- 每个用户根据 User ID 和实验 ID 的哈希值，被均匀分配到 N 个桶之一
- **优点**：同用户始终进同一桶，体验一致
- **缺点**：Hash 碰撞会导致实验间污染（同一用户在不同实验中被分配到不同变体，容易产生互相干扰）

#### 分层实验

Google 提出的分层实验框架（Overlapping Experiment Infrastructure）：
- 每一层划分多个不重叠的实验域
- 同一用户在不同层被重新 Hash 到不同的桶
- **流量正交**：实验 A 在第 1 层跑，实验 B 在第 2 层跑，互不影响

```
流量 100%
├── 层1：推荐算法实验（10% 新模型 vs 90% 基线）
├── 层2：UI界面实验（50% A版 vs 50% B版）
└── 层3：排序权重实验（30% new vs 70% baseline）
```

### 5.2 指标体系

一个完整的 A/B 实验观察体系分为三层：

| 层级 | 类型 | 示例指标 | 说明 |
|------|------|----------|------|
| **核心指标** | 北极星指标 | 留存率、人均时长、GMV | 决策依据——哪个变体好就上哪个 |
| **护栏指标** | 不可后退 | 广告收入、活跃用户数 | 即使核心指标涨了，护栏指标降了也不行 |
| **稀释指标** | 检查副作用 | CTR↑但CVR↓、时长↑但分享↓ | 防止模型"作弊"——如为了时长推荐长视频但用户不看 |

**常见陷阱**：
- **Novelty Effect（新奇效应）**：新模型刚上线，用户因为新鲜感点击率上升，一周后回落
- **Primacy Effect（首因效应）**：老用户不习惯新推荐样式，初期指标下降，习惯后回升
- **Sample Ratio Mismatch（SRM）**：实验组和对照组的人数比例偏离预期（如 10:10 变成 9:11），说明分桶有偏

### 5.3 实验周期

**最小周期**：7 天（覆盖一周为周期的用户行为波动）
- 周一至周日用户行为差异巨大（工作日 vs 周末）
- 至少覆盖一个完整自然周

**新奇效应衰减曲线**：
```
第1天：指标大涨（好奇点击）
第3天：回落
第7天：稳定，与真实效果一致
```

**经验准则**：
- 小变化（权重微调）：观察 7~14 天
- 大变化（新模型架构）：观察 14~28 天
- 如果实验组和对照组差异小（<0.5%），需要更长时间和更大流量

## 第六章：离线评估

在投入线上流量前，首先要离线验证模型的有效性。但离线评估和线上效果之间的"Gap"是推荐系统最大的坑之一。

### 6.1 离线指标 vs 在线指标偏差

| 离线能做 | 离线不能做 |
|----------|-----------|
| AUC、NDCG（排序能力） | 用户体验（留存、满意度） |
| HitRate、Recall（召回率） | 多样性、新鲜感 |
| MSE、LogLoss（预估准确度） | 长期回报（LTV） |
| 训练损失收敛 | 系统反馈循环（推荐→用户行为→影响下次训练） |

**根本原因**：离线数据是"看过→点过"的被曝光偏置数据，并不是随机样本。线上实际展示的内容比离线数据中多得多。

### 6.2 时间序列切分（防止 Data Leakage）

**常见错误**：随机切分训练集和测试集。

**正确做法**：按时间顺序切分——用前 T 天的数据训练，预测第 T+1 天的行为。

```
训练集: Day 1~Day 7 → 验证集: Day 8~Day 9 → 测试集: Day 10~Day 11
```

**为什么时间切分**：
- 随机切分会泄漏未来信息（用明天的点击信号预测今天的行为）
- 推荐系统是时序依赖的（热门物品每天变化，用户兴趣漂移）
- 时间切分更接近线上场景（用历史预测未来）

### 6.3 离线 Replay 评估

**Replay（回放评估）**：模拟线上实时推荐环境，用线上日志"回放"来评估模型效果。

```
算法:
1. 用历史数据训练模型 M
2. 按时间顺序逐一回放曝光日志
3. 对每次曝光，检查 M 的 Top-K 推荐列表中是否包含用户实际点击的物品
4. 计算 HitRate、MAP、NDCG
```

**优势**：
- 更接近线上环境（随时间推移改变候选集和用户状态）
- 对时间敏感的指标敏感（如热点追踪能力）

**局限**：
- 仍然无法模拟用户对推荐结果的反向影响（推荐→用户看→改变行为→影响下次推荐）
- 无法评估多样性、新颖性等体验指标

### 总结：推荐系统评估方法论

```
┌─────────────────────────────┐
│      离线评估（快速迭代）      │
│  AUC / NDCG / HitRate / Replay │
│  方向性验证，不保证线上涨       │
└──────────┬──────────────────┘
           ↓
┌─────────────────────────────┐
│     小流量 A/B 测试（验证）    │
│  核心指标 + 护栏 + 稀释        │
│  最小周期 7 天（新奇效应消退）  │
└──────────┬──────────────────┘
           ↓
┌─────────────────────────────┐
│    全量上线（持续监控）        │
│  留存 / 时长 / GMV / 满意度    │
│  + 长期 LTV 评估              │
└─────────────────────────────┘
```

## 总结

推荐系统的工业化链路是一条**从粗到细的筛选漏斗**：

1. **召回**：从海量候选到千级——追求高召回 × 低延迟。核心手段从传统 CF → 矩阵分解 → 双塔向量检索 → 图召回，多路并行保障覆盖率。
2. **排序**：从千级到百级——追求高精度预估。模型从 LR → FM/FFM → W&D → DeepFM → DIN → MMOE/PLE，越来越精细化建模用户行为和特征交互。
3. **重排**：从百级到展示列表——追求列表整体最优。MMR 平衡相关性与多样性，打散策略保证视觉体验，业务规则做最后兜底。

**关键认知**：
- 没有完美的推荐系统，每一阶段都在做**权衡**：召回 vs 精度、相关 vs 多样、短期点击 vs 长期留存
- **离线涨 ≠ 线上涨**：A/B 测试是一切效果的最终裁判
- **冷启动是底层问题**：新用户/新物品的处理贯穿所有阶段
- **多目标优化是趋势**：单一 CTR 优化已过时，必须考虑完播率、转化率、满意度等多维目标

### 核心子系统概览

| 子系统 | 文件路径 | 核心功能 |
|--------|----------|----------|
| Scheduler | `kernel/sched/` | CFS调度器、实时调度、负载均衡 |
| VFS | `fs/` | 虚拟文件系统、各种具体文件系统 |
| MM | `mm/` | 页分配/回收、缺页处理、mmap、OOM killer |
| Net | `net/` | socket/TCP/IP协议栈、网络过滤 |
| IPC | `ipc/` | System V IPC、pipe、信号 |
| Device Drivers | `drivers/` | 最大目录(~60%代码量) |
| Security | `security/` | LSM钩子、MAC策略 |
| Kernel | `kernel/` | 进程管理、信号、timer、模块 |

```
对比分析:

Minix (微内核):
  • 内核极小 (~4000行 C)
  • 文件系统、驱动、网络都在用户态 (独立进程)
  • 服务崩溃 → 可重启，不影响整个系统
  • 缺点: IPC 开销大，性能差
  • 教学 OS (Tanenbaum 设计)
  • "如果文件系统有bug, 重启文件系统服务就行"

Linux (宏内核):
  • 所有核心子系统都在内核空间
  • 驱动可加载 (LKM)，但加载后在内核空间
  • 性能好: 函数调用直通，无 IPC 开销
  • 风险: 驱动 bug = 内核 oops/panic
  • "即使驱动有bug, 性能和兼容性更重要"

Windows NT (混合内核):
  • 核心 Executive 在 ntoskrnl.exe (宏内核风格)
  • 底层内核 + HAL 负责中断/调度 (微内核风格)
  • 各子系统 (Win32/POSIX) 在用户态
  • 驱动通过 WDM/WDF 框架，含 I/O 管理器
  • "混合 = 宏内核的性能 + 微内核的模块化"
```

## 4. Ring 0-3 特权级 & syscall 入口

```
x86 保护模式下的 4 个特权级 (Rings):

┌────────────────────────────────────────────────────────────┐
│                         特权级环                            │
│                                                            │
│   ┌──────────────────────────────────────────────────┐     │
│   │              Ring 3 (用户态, 最低特权)             │     │
│   │  应用层: app.exe / libc.so / user code             │     │
│   │  限制: 不能执行特权指令, 不能直接访问硬件             │     │
│   │  内存: 只能访问用户空间 (0x0000 0000 - 0x7FFF FFFF) │     │
│   │  CR3: 不同进程不同页表, 完全隔离                     │     │
│   │                                                    │     │
│   │   ┌────────────────────────────────────────┐       │     │
│   │   │          Ring 1 (通常不用)               │       │     │
│   │   └────────────────────────────────────────┘       │     │
│   │                                                    │     │
│   │   ┌────────────────────────────────────────┐       │     │
│   │   │          Ring 2 (通常不用)               │       │     │
│   │   └────────────────────────────────────────┘       │     │
│   │                                                    │     │
│   │   ┌────────────────────────────────────────┐       │     │
│   │   │        Ring 0 (内核态, 最高特权)         │       │     │
│   │   │  Linux 内核 / 驱动 / 中断处理             │       │     │
│   │   │  Windows 内核 / Executive / HAL         │       │     │
│   │   │  特权: 所有指令可执行                     │       │     │
│   │   │  内存: 可访问所有物理内存                  │       │     │
│   │   │  CR3: 内核页表, SWAPPER/System进程        │       │     │
│   │   └────────────────────────────────────────┘       │     │
│   └──────────────────────────────────────────────────┘     │
│                                                            │
│   Ring决定: 某段代码能做什么、访问什么、执行什么指令          │
│   Ring交叉: 通过 syscall(↓) / sysret(↑) 或 中断/异常       │
└────────────────────────────────────────────────────────────┘
```

### syscall 入口流程 (x86_64)

```
用户态 ring 3
    │
    │  syscall 指令
    │  ├─ CPU 从 MSR_LSTAR 加载 RIP (entry_SYSCALL_64)
    │  ├─ 切换 RSP 到内核栈 (MSR_STARCALL)
    │  ├─ 设置 CS = __KERNEL_CS (ring 0)
    │  └─ 保存 RFLAGS 到 R11
    ▼
内核态 ring 0: entry_SYSCALL_64 (arch/x86/entry/entry_64.S)
    │
    │ 1. 切换 GS segment (到内核 percpu)
    │ 2. 在内核栈上构建 pt_regs (保存所有寄存器)
    │ 3. 清零 %r14 (标记来自用户态)
    │ 4. 调用 do_syscall_64():
    │      → cr4 检查
    │      → 按 RAX 索引 sys_call_table[]
    │      → 调用实际函数 (e.g., sys_read)
    │
    │ 5. 返回: syscall_return_slowpath()
    │      → 检查 TIF 标志 (信号/调度/ptrace)
    │      → restore_regs_and_iret 或 sysretq
    │
    │ 6. sysretq 指令:
    │      → RIP = RCX (用户态恢复地址)
    │      → RFLAGS = R11
    │      → CS = __USER_CS (ring 3)
    ▼
用户态 ring 3 继续执行
```

### 特权级隔离

```
┌───────────────────┬──────────────────────────┬──────────────────┐
│      机制         │        ring 0            │     ring 3       │
├───────────────────┼──────────────────────────┼──────────────────┤
│ 段选择子 (CS)     │ __KERNEL_CS (0x10)       │ __USER_CS (0x33) │
│ 页表              │ 所有页可访问              │ 只用户页          │
│ CR3 (页表基址)    │ 可读写                   │ 只读              │
│ I/O 指令 (in/out) │ 可执行                   │ 需要 IOPL        │
│ CLI/STI (中断)    │ 可执行                   │ 不可执行          │
│ HLT (停机)        │ 可执行                   │ 不可执行          │
│ LGDT/LIDT/LTR     │ 可执行                   │ 不可执行          │
│ MSR 访问 (rdmsr)  │ 可执行                   │ 不可执行          │
│ 执行 syscall      │ 响应                     │ 发起 (ring 3)    │
└───────────────────┴──────────────────────────┴──────────────────┘
```

## 总结

```
内核架构的三大流派:
  宏内核 (Linux)    = 单体 + 模块化          → 性能优先
  微内核 (Minix)    = 最小核心 + 用户态服务    → 安全可靠
  混合内核 (NT)     = 核心执行体 + 微内核底层   → 平衡

特权级设计:
  ring 0 ↔ 内核 ↔ 硬件
  ring 3 ↔ 用户 ↔ 应用
  ring 1/2 ↔ 通常不用 (虚拟化等特殊用途)

syscall = ring 3 → ring 0 的唯一合法通道
          所有权限检查集中在这里
```

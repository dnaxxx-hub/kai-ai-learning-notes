# 第1课：CPU流水线 + 分支预测 + 乱序执行

## 1. CPU流水线基础（5级）

### 经典5级流水线：RISC-V / MIPS

| 阶段 | 名称 | 功能 |
|------|------|------|
| **IF** | Instruction Fetch | 从指令缓存取指令，PC自增 |
| **ID** | Instruction Decode | 解码指令，读取寄存器文件 |
| **EX** | Execute | ALU运算或地址计算 |
| **MEM** | Memory Access | 读/写数据内存（仅load/store） |
| **WB** | Write Back | 结果写回寄存器文件 |

**流水线原理**：每条指令在各阶段花1个周期，但不同指令在不同阶段重叠执行。
- 非流水线：N条指令 = 5 × N 周期
- 流水线：N条指令 ≈ 5 + (N-1) 周期（理想CPI≈1）

### 理想与现实
理想情况 CPI = 1，但流水线冒险（Hazard）会打乱节奏。

## 2. 流水线冒险

### 2.1 结构冒险（Structural Hazard）
**原因**：硬件资源冲突（如同一周期同时取指令和读数据，但只有1个存储器）
**解决**：哈佛架构（指令/数据缓存分离）or 资源复制

### 2.2 数据冒险（Data Hazard）⭐ 最重要

**RAW（读后写）** — 真正依赖
```
lw $t0, 0($t1)   # 周期1: IF  2: ID  3: EX  4: MEM  5: WB
add $t2, $t0, $t3  # $t0 在第5周期才写回，add的EX阶段在第3周期
                   # → 需要3个气泡（stall）或转发（forwarding）
```

**WAR（写后读）** — 通常不出现在in-order流水线（统一先读后写）
**WAW（写后写）** — 也不常见于in-order

**解决方法**：
1. **转发/旁路（Forwarding/Bypassing）**：将EX或MEM阶段的结果直接送到EX输入
2. **插入气泡（Stall/Bubble）**：插入NOP指令
3. **编译器调度**：重排指令避免依赖

**load-use 冒险**：转发无法完全解决的场景
```
lw $t0, 0($t1)    # MEM阶段才有数据
add $t2, $t0, $t3  # EX阶段就需要
→ 即使转发也要插入1个气泡
```

### 2.3 控制冒险（Control Hazard）
**原因**：分支/跳转指令改变PC，流水线中的后续指令需要被冲刷

## 3. 分支预测技术

### 3.1 静态预测
- 总是"不跳转"或"向后跳转预测/向前不跳转"
- 准确率约 60-70%

### 3.2 1位饱和计数器
- 1bit 记录上次结果：0=不跳转, 1=跳转
- 内层循环最后一次预测会错（两次错误）

### 3.3 2位饱和计数器 ⭐
```
        taken
   ┌─────────┐
   ▼         │
  强不跳转 ──→ 弱不跳转 ──→ 弱跳转 ──→ 强跳转
   │  not    │  not     │  taken  │
   └─────────┘          └─────────┘
        taken              not       not
```
**特点**：需要连续2次预测错误才翻转，对循环更友好
**准确率**：~90%

### 3.4 BTB（Branch Target Buffer）
- 缓存分支指令地址 → 目标地址
- 即使预测"跳转"，也要知道跳到哪里
- IF阶段查询BTB：命中→直接取目标地址；不命中→顺序执行

### 3.5 TAGE预测器（现代CPU）
- 多个不同长度的历史表（Tagged GEometric）
- 用较长的历史预测难分支，较短的历史预测简单分支
- 准确率 > 97%

---

## 4. 分支预测失败惩罚
- 清空流水线 = IF之后的所有指令被冲刷
- **15-20个周期惩罚**（现代深流水线CPU如Intel Core可达20+级）
- → 预测准确率每提升1%都有巨大的性能意义

---

## 5. 乱序执行（Out-of-Order Execution）

### Tomasulo算法（IBM 360/91, 1967）
**核心思想**：通过寄存器重命名和保留站，让没有数据依赖的指令提前执行

### 三大组件
1. **保留站（Reservation Stations）**：等待操作数的指令队列
2. **公共数据总线（CDB）**：广播结果给所有等待单元
3. **重命名寄存器**：消除WAR/WAW

### 重排序缓冲区（ROB）⭐ 现代CPU关键组件
- **按序发射（In-Order Issue）**：保留程序顺序
- **乱序执行（Out-of-Order Execute）**：数据就绪的指令先执行
- **按序提交（In-Order Commit）**：结果按程序顺序写回 → 精确异常

**ROB条目包含**：
- 指令类型
- 目标寄存器/内存地址
- 值
- 完成标志
- 异常标志

**为什么需要ROB**：
- 精确异常：中断/异常时，已提交的指令结果可见，未提交的仿佛未执行
- 推测执行：分支预测错误时，冲刷ROB中未提交的条目

## 6. 超标量与超线程

### 超标量（Superscalar）
- 每周期发射多条指令（如Intel Core一次发射4-6条）
- 需要更多功能单元（多个ALU、多个FPU）
- 指令调度更复杂

### 超线程（Hyper-Threading / SMT）
- 1个物理核心模拟2个逻辑核心
- 共享执行单元，独享寄存器状态
- 当一个线程发生cache miss，另一个线程利用空闲周期执行
- 提升约 15-30% 的吞吐量

## 总结记忆要点

| 概念 | 一句话 |
|------|--------|
| 流水线 | 指令重叠并行，理想CPI=1 |
| RAW | load-use需插入气泡，其他可用转发 |
| 2位饱和 | 2次错误才翻转 |
| TAGE | 多长度表级联，准率>97% |
| ROB | 按序提交 = 精确异常 |
| 超标量 | 每周期多条 |
| 超线程 | 共享执行单元的双线程 |

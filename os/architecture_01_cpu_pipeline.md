## 1. 经典五级流水线（MIPS 架构）

MIPS 五级流水线是现代 RISC 处理器的经典设计，将一条指令的执行分解为 5 个阶段：

```
┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐
│ IF  │ →  │ ID  │ →  │ EX  │ →  │ MEM │ →  │ WB  │
└─────┘    └─────┘    └─────┘    └─────┘    └─────┘
 取指       译码       执行       访存       写回
```

### 1.1 IF（取指 — Instruction Fetch）
- **功能**：从指令存储器中读取指令
- **输入**：程序计数器（PC）
- **操作**：PC → 指令存储器 → 输出指令
- **更新**：PC += 4（或分支目标地址）
- **硬件**：指令存储器（I-Cache）、PC 寄存器、加法器

### 1.2 ID（译码 — Instruction Decode）
- **功能**：解析指令格式，读取寄存器，生成控制信号
- **操作**：
  - 从指令中提取 opcode、rs、rt、rd、funct、imm 等字段
  - 读取寄存器堆（Register File）：rs → ReadData1, rt → ReadData2
  - 符号扩展立即数
  - 生成 ALU 控制信号、寄存器写使能、存储器控制信号等
- **硬件**：寄存器堆（32 × 32bit）、控制单元、符号扩展器

### 1.3 EX（执行 — Execute）
- **功能**：执行 ALU 运算或地址计算
- **操作**：
  - ALU 运算（算术/逻辑指令）
  - 地址计算（Load/Store 指令）：base + offset
  - 分支条件判断
- **硬件**：ALU、多路选择器（数据转发）

### 1.4 MEM（访存 — Memory Access）
- **功能**：访问数据存储器
- **操作**：
  - Load：从数据存储器读取数据
  - Store：将数据写入数据存储器
  - 其他指令：直通
- **硬件**：数据存储器（D-Cache，通常与 I-Cache 分离）

### 1.5 WB（写回 — Write Back）
- **功能**：将结果写回寄存器堆
- **操作**：
  - ALU 结果写回 rd/rt
  - Load 数据写回 rt
- **硬件**：寄存器堆写端口、多路选择器

### 1.6 流水线寄存器

各级之间由流水线寄存器保存中间状态：

```
IF/ID → ID/EX → EX/MEM → MEM/WB
```

各寄存器保存的内容：
- **IF/ID**：指令本身、PC+4
- **ID/EX**：ReadData1、ReadData2、扩展后的立即数、控制信号、rt/rd 号码
- **EX/MEM**：ALU 结果、WriteData（Store 数据）、控制信号、目标寄存器
- **MEM/WB**：存储器读取结果、ALU 结果、控制信号、目标寄存器

### 1.7 流水线性能分析

```
理想 CPI = 1（每周期完成一条指令）
吞吐量 = 1 / 周期时间
加速比 ≈ 流水线级数（忽略冒险和开销）
```

## 2. 流水线冒险（Pipeline Hazards）

### 2.1 结构冒险（Structural Hazard）

**定义**：硬件资源冲突，两条以上指令同时需要同一硬件资源。

**典型例子**：
- 冯·诺依曼架构中指令和数据共用同一存储器 → IF 和 MEM 同时访存冲突
- MIPS 的解决方案：**分离 I-Cache 和 D-Cache**（哈佛架构）

**解决方案**：
1. 硬件分离（哈佛架构）
2. 插入气泡（降低性能）
3. 专用功能单元

### 2.2 数据冒险（Data Hazard）

**定义**：指令之间存在数据依赖关系，后一条指令需要前一条指令的结果。

#### 三种类型

| 类型 | 全称 | 描述 | 实际是否发生（五级流水线） |
|------|------|------|:---:|
| RAW | Read After Write | 后读前写 | ✅ 最常见 |
| WAR | Write After Read | 后写前读 | ❌ 五级流水线无 |
| WAW | Write After Write | 后写前写 | ❌ 五级流水线无 |

**RAW 示例**：
```assembly
add $2, $3, $4   # WB: 写 $2
sub $5, $2, $6   # 需要用 $2 的值（RAW: $2）
```

**检测条件**：
```
EX 阶段：ID/EX.RegisterRd 与 IF/ID.RegisterRs/Rt 相等
MEM 阶段：EX/MEM.RegisterRd 与 IF/ID.RegisterRs/Rt 相等
```

#### 解决方案一：数据转发（Forwarding / Bypassing）

将 ALU 结果直接从 EX/MEM 或 MEM/WB 流水线寄存器转发回 EX 阶段的 ALU 输入。

```
前一条指令：EX → MEM → WB
                  ↓ 转发
当前指令：      IF → ID → EX → MEM → WB
```

转发路径：
- **EX/MEM → EX**：上一个周期的 ALU 结果直接输入当前 ALU
- **MEM/WB → EX**：上上个周期的结果（或 Load 数据）输入 ALU

**Load-Use 冒险**：Load 指令的结果在 MEM 阶段才有效，"EX/MEM" 转发解决不了，需要插入一个气泡。

```
lw $2, 0($3)     # MEM: 读取数据完成
add $5, $2, $6   # EX: 需要 $2 → 必须插入一个气泡
```

#### 解决方案二：插入气泡（Pipeline Stall）

在流水线中插入 NOP（空操作），直到数据就绪。

**转发单元结构**：
```
             ┌─────────────┐
Rs ─────────→│  转发检测   │
Rt ─────────→│  (Hazard   │──→ 转发MUX选择信号
EX/MEM.Rd ──→│  Detection)│
MEM/WB.Rd ──→│            │
             └─────────────┘
```

### 2.3 控制冒险（Control Hazard）

**定义**：分支指令导致的流水线冲刷（Flush）。

**问题**：分支结果在 EX 阶段才确定，但 IF 阶段已经取入了下一条指令。

#### 静态分支预测

1. **总是不跳转**（Predict Not Taken）：默认继续执行 PC+4 的指令
   - 分支跳转时才冲刷流水线
   - 预测正确率 ~50%

2. **总是跳转**（Predict Taken）：默认执行分支目标
   - 分支不跳转时冲刷
   - 向后分支（循环）正确率高

#### 动态分支预测：2位饱和计数器

```
预测跳转
    ↑
 11(T) ──→ 10(T)    （强跳转 → 弱跳转）
  ↑↓        ↑↓
 01(NT) ←─ 00(NT)   （弱不跳转 → 强不跳转）
    ↓
预测不跳转
```

- 两位：4 种状态（强跳转、弱跳转、弱不跳转、强不跳转）
- 分类错误两次才翻转方向
- 预测正确率 ~90%（典型应用）

#### BTB（Branch Target Buffer）

分支目标缓冲器，缓存分支指令地址 → 分支目标地址的映射。

```
PC → BTB 查表 → 命中则直接跳转（零周期延迟）
```

#### 分支预测失败的代价

MIPS 典型设计：
- 分支决断在 EX 阶段
- 错误预测 → 冲刷 IF、ID 两阶段指令
- **惩罚 = 2 个气泡**

### 2.4 三种冒险对比

| 冒险类型 | 原因 | 解决 | 性能损失 |
|---------|------|------|---------|
| 结构冒险 | 资源冲突 | 硬件分离 | 取决于冲突频率 |
| 数据冒险 | 数据依赖 | 转发 + 气泡 | 1-2 周期（Load-Use） |
| 控制冒险 | 分支跳转 | 分支预测 | 2 周期（错误预测） |

## 3. 缓存原理

### 3.1 缓存层级（Memory Hierarchy）

```
寄存器     ≈ 0.3 ns
    ↓
L1 Cache  ≈ 1 ns    （32KB～64KB，每核私有）
    ↓
L2 Cache  ≈ 4 ns    （256KB～1MB，每核私有或共享）
    ↓
L3 Cache  ≈ 10 ns   （8MB～32MB，多核共享）
    ↓
主存 RAM  ≈ 100 ns  （8GB～512GB）
    ↓
磁盘 SSD  ≈ 100 μs  （256GB～2TB）
```

**局部性原理**：
- **时间局部性**：刚访问的数据很可能再次被访问（循环）
- **空间局部性**：刚访问数据的相邻数据很可能被访问（数组遍历）

### 3.2 缓存行（Cache Line）

基本存储单元，通常 64 字节。

```
| tag | index | offset |
```

- **offset**：缓存行内的字节偏移
- **index**：选择哪一组缓存行
- **tag**：与地址高位比较，判断是否命中

### 3.3 映射方式

#### 直接映射（Direct-Mapped）

每个内存地址映射到唯一的缓存行位置。

```
行号 = (地址 / 行大小) % 缓存行数
```

- ✅ 简单、速度快
- ❌ 冲突率高（不同地址映射到同一行）

#### 组相联（Set-Associative）

n 路组相联：每组有 n 个缓存行。

```
组号 = (地址 / 行大小) % 组数
```

- **2 路组相联**：每组 2 行
- **4 路组相联**：每组 4 行（常见）
- **8 路组相联**：每组 8 行

✅ 冲突率低、硬件复杂度适中

#### 全相联（Fully Associative）

任何内存地址可映射到任何缓存行。

- ✅ 冲突率最低
- ❌ 比较器太多，硬件复杂，速度最慢
- 通常用于 TLB（Translation Lookaside Buffer）

### 3.4 替换策略

| 策略 | 描述 | 实现复杂度 | 性能 |
|------|------|:---------:|:----:|
| LRU | 替换最久未使用的行 | 高（需记录访问顺序） | 最优 |
| 伪 LRU | 用二叉树近似 LRU | 中 | 接近 LRU |
| 随机 | 随机选择替换行 | 低 | 不稳定，但避免最坏情况 |
| FIFO | 替换最早进入的行 | 低 | 可能替换热点数据 |

### 3.5 写策略

#### 写直达（Write-Through）

- 写缓存的同时写入下一级存储器（L2 或 RAM）
- ✅ 一致性维护简单
- ❌ 写带宽大，性能差

#### 写回（Write-Back）

- 只写入缓存，标记为脏（Dirty）
- 替换该行时才写回下一级存储器
- ✅ 写带宽小，性能好
- ❌ 一致性维护复杂

#### 写分配（Write-Allocate）vs 非写分配（No-Write-Allocate）

| | 写命中 | 写缺失 |
|--|--------|--------|
| 写回+写分配 | 更新缓存 | 加载到缓存再更新 |
| 写直达+非写分配 | 更新缓存和内存 | 直接写内存 |

## 4. 缓存一致性（Cache Coherence）

### 4.1 问题来源

多核 CPU 各自有私有缓存（L1），同一数据可能被多个核缓存。如果一个核修改了数据，其他核必须看到最新值。

```
核0 ── L1 ──┐
             ├── L2 → L3 → RAM
核1 ── L1 ──┘
```

### 4.2 MESI 协议

Intel 的缓存一致性协议之一，每个缓存行维护 4 种状态：

#### 状态定义

| 状态 | 含义 | 本核数据 | 内存数据 | 其他核 |
|------|------|:--------:|:--------:|:------:|
| **M** Modified | 已修改，仅本核拥有 | ✅ 最新 | ❌ 过时 | 无副本 |
| **E** Exclusive | 独占，与内存一致 | ✅ 一致 | ✅ 一致 | 无副本 |
| **S** Shared | 共享，与内存一致 | ✅ 一致 | ✅ 一致 | 有副本 |
| **I** Invalid | 失效 | ❌ 无效 | - | - |

#### 状态转换图

```
               ┌──────────────┐
               │              │
               │   Modified   │
               │      (M)     │
               │              │
               └──┬───┬───┬──┘
                  │   │   │
         本地写   │   │   │  其他核写（嗅探）
                  │   │   │
               ┌──┘   │   └──┐
               │      │      │
         ┌─────▼─┐  ┌─▼──┐  ┌▼──────┐
         │Exclus.│  │    │  │Invalid│
         │  (E)  │  │    │  │  (I)  │
         └───┬───┘  │    │  └───┬───┘
             │      └────┘      │
    本地读    │                  │ 其他核读（嗅探+共享）
             │        ┌─────────┘
             │        │
         ┌───▼────────▼──┐
         │   Shared (S)  │
         └────────────────┘
```

#### 总线嗅探（Bus Snooping）

每个缓存控制器监控总线上的事务：

| 嗅探事件 | 当前状态 | 行为 |
|---------|:-------:|------|
| **BusRd**（其他核读） | M → S | 写回内存，共享 |
| **BusRd**（其他核读） | E → S | 共享 |
| **BusRdX**（其他核写） | M → I | 写回内存，失效 |
| **BusRdX**（其他核写） | E → I | 失效 |
| **BusRdX**（其他核写） | S → I | 失效 |
| **BusUpgr**（其他核写） | S → I | 失效（数据已共享） |

### 4.3 伪共享（False Sharing）

**定义**：不同核修改同一缓存行中的不同变量，导致缓存行在核之间反复失效和同步。

```c
// 线程 0 写 x，线程 1 写 y
// x 和 y 在同一个缓存行（64 字节）
struct { int x; int y; } data;

// 线程 0: data.x = 1;  // 使线程 1 的缓存行失效
// 线程 1: data.y = 2;  // 使线程 0 的缓存行失效
// 性能灾难！
```

**解决方案**：缓存行对齐 + 填充（Padding）

```c
struct __attribute__((aligned(64))) {
    int x;
    char pad[60];  // 填充到 64 字节
} data0;

struct __attribute__((aligned(64))) {
    int y;
    char pad[60];
} data1;
```

## 5. Python 模拟：五级流水线与 MESI 协议

> 完整代码见：`code/cpu_pipeline.py`

### 5.1 五级流水线模拟

核心结构：
- **Pipeline** 类：管理 IF/ID/EX/MEM/WB 五个阶段
- **Instruction** 类：指令表示（opcode, rs, rt, rd, imm）
- **RegisterFile** 类：32 个通用寄存器
- 每周期推进一级，各阶段分别处理

**数据冒险处理**：
- 转发（Forwarding）：EX/MEM 和 MEM/WB 的结果直通到 EX 输入
- Load-Use 检测：Load 后紧接使用 → 插入一个气泡
- 寄存器写冲突：正确处理 WB 写入

**分支预测**：
- 2 位饱和计数器实现
- BTB（分支目标缓冲器）：缓存分支地址 → 目标地址
- 预测失败 → 冲刷 IF/ID 两阶段，插入气泡

### 5.2 MESI 缓存一致性模拟

核心结构：
- **MesicCache** 类：每个 CPU 核一个私有缓存
- **Bus** 类：总线嗅探 + 消息传递
- 每个缓存行跟踪状态（M/E/S/I）

**总线事务**：
| 事务 | 触发条件 | 行为 |
|------|---------|------|
| BusRd | 本地读缺失 | 询问其他核，获取数据 |
| BusRdX | 本地写缺失 | 使其他核的副本失效 |
| BusUpgr | 本地写命中（S→M） | 使其他核共享副本失效 |

**状态转换示例**：
```
初始：所有缓存行 Invalid

核0 读 addr0 → 总线 BusRd → 内存提供
              → 核0 缓存行变为 Exclusive(E)

核1 读同一 addr0 → 总线 BusRd → 核0 嗅探到
                  → 核0: E→S（共享）
                  → 核1: 新行 → S

核0 写 addr0 → 检测到 S 状态
              → 总线 BusUpgr → 核1 缓存行 S→I
              → 核0: S→M（Modified）
```

### 5.3 伪共享演示

两个线程写入同一缓存行的不同偏移：
- 未对齐：缓存行竞争 → 每写一次触发一次失效
- 对齐填充：各占独立缓存行 → 无竞争

运行 `cpu_pipeline.py` 查看实际输出对比。

## 小结

| 主题 | 关键点 |
|------|--------|
| 五级流水线 | IF→ID→EX→MEM→WB，每周期推进一级 |
| 数据冒险 | 转发解决大部分 RAW，Load-Use 需插入气泡 |
| 分支预测 | 2 位饱和计数器 + BTB，错误预测冲刷两阶段 |
| 缓存层级 | L1(1ns)→L2(4ns)→L3(10ns)→RAM(100ns) |
| 缓存映射 | 直接映射/组相联/全相联，64B 缓存行 |
| MESI 协议 | M(改)→E(独)→S(共)→I(失)，总线嗅探维护一致性 |
| 伪共享 | 不同核修改同一缓存行的不同变量 → 性能灾难 |

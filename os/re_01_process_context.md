# 体系结构与逆向工程 — 第一课笔记

## 1. 进程 = 现代操作系统的"CPU上下文容器"

### 1.1 EPROCESS 结构体 (Windows 内核)
每个 Windows 进程对应一个 `_EPROCESS` 结构体 (~1000 bytes)，包含：
- PCB (Process Control Block) — 线程调度必须的信息
- 页表目录基址 — 虚拟内存映射
- 句柄表 — 文件/注册表/同步对象
- 安全令牌 — 用户身份和权限
- VAD (Virtual Address Descriptor) 树 — 进程虚拟地址空间描述

### 1.2 用户态可观察的进程属性
```
PID → EPROCESS → 进程环境块(PEB) → 用户态可见
                                   → 内存段列表
                                   → 已加载DLL列表
                                   → 堆信息
```

### 1.3 上下文切换的代价
当 CPU 从一个进程切换到另一个：
1. 保存当前 CPU 寄存器 → 当前进程内核栈
2. 切换 CR3 (页表基址) → 切换地址空间
3. TLB 全部失效 → 后续内存访问都需要重新查页表
4. 加载新进程的寄存器 → 恢复执行

**这就是为什么上下文切换是有成本的**: 即使不涉及磁盘 I/O，TLB flush 就够受的。

## 2. 动手实验输出

### 2.1 当前进程 EPROCESS 等价物
```
name:           python.exe
pid:            {pid}
num_threads:    {线程数}
memory.rss:     {物理内存}
context_switches.voluntary:  主动让出CPU
context_switches.involuntary: 被抢占
```

### 2.2 上下文切换模拟结果
双线程 20000 次切换 ≈ 毫秒级别，每次切换 ~50-200ns
（Windows 调度器时间片 ~20ms，所以实际切换没那么频繁）

## 3. 关键洞察

**CPU 没有"进程"概念** — 它只看到连续指令流。
"进程"是操作系统创造的一个抽象，核心就是：
1. 一个独立的地址空间 (页表)
2. 一组 CPU 寄存器的快照 (上下文)
3. 一组系统资源 (句柄表)

**逆向工程的入口点**: 理解了进程的内存布局，就知道
- 代码段(.text) 在哪里
- 数据段(.data/.rdata) 在哪里
- 堆栈在哪里
- DLL 映射在哪里
→ 调试器/分析工具的每一步操作都在操作这些内存区域

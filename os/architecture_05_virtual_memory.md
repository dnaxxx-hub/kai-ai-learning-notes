## 1. 虚拟内存基础

### 1.1 为什么需要虚拟内存

虚拟内存是操作系统提供的一种内存抽象，让每个进程拥有独立的、连续的地址空间。核心动机有三个：

| 动机 | 说明 |
|------|------|
| **进程隔离** | 进程 A 不能读写进程 B 的地址空间，防止恶意/错误程序破坏其他进程 |
| **按需加载** | 只将真正使用的部分加载到物理内存（Demand Paging），减少内存浪费 |
| **共享内存映射** | 不同进程可以通过虚拟地址映射到同一物理页，实现共享库（如 libc.so） |
| **简化编程** | 程序员看到的是大而连续的空间（如 64 位地址空间），无需关心物理内存碎片 |

**关键洞察**：虚拟内存把"物理内存"和"进程视角的内存"彻底解耦。

### 1.2 MMU（Memory Management Unit）

MMU 是 CPU 中的硬件模块，负责在每条指令的访存操作中将虚拟地址（VA）翻译为物理地址（PA）。

```
┌──────────────┐     VA       ┌─────┐     PA       ┌──────────────┐
│  CPU 核心     │ ─────────→  │ MMU │ ─────────→  │ 物理内存      │
│  (PC/寄存器)  │             └─────┘              │ (DRAM)       │
└──────────────┘    缺页中断 ↑                    └──────────────┘
                           │
                    ┌──────┴──────────┐
                    │  OS 缺页处理程序  │
                    └─────────────────┘
```

- 如果 MMU 找到对应的物理页 → 正常访存
- 如果 MMU 发现页不在内存中 → 触发 **Page Fault**（缺页中断），交给 OS 处理
- MMU 的核心数据结构是 **页表（Page Table）**

### 1.3 地址空间概览（x86-64 典型布局）

```
0x0000000000000000  ┌─────────────────────┐
                    │  用户代码/数据       │  ← 用户态（Ring 3）
                    │  ↓                  │
                    │  堆（Heap）          │
                    │  ↓                  │
                    │  ↑                  │
                    │  栈（Stack）         │
0x00007FFFFFFFFFFF  ├─────────────────────┤
                    │  留空（保护页）      │
0xFFFFFFFF80000000  ├─────────────────────┤
                    │  内核代码/数据       │  ← 内核态（Ring 0）
0xFFFFFFFFFFFFFFFF  └─────────────────────┘
```

- x86-64 地址空间有效位 48 位（高 16 位符号扩展）
- 用户空间：`0x0000000000000000` ~ `0x00007FFFFFFFFFFF`（256 TB）
- 内核空间：`0xFFFF800000000000` ~ `0xFFFFFFFFFFFFFFFF`（256 TB）

## 2. 分页（Paging）

### 2.1 基本概念

分页是虚拟内存最常见实现方式。将虚拟地址和物理地址都划分为固定大小的块：

| 术语 | 说明 | 典型大小 |
|------|------|----------|
| **页（Page）** | 虚拟地址空间的分块 | 4 KB |
| **页帧（Frame）** | 物理地址空间的分块 | 4 KB |
| **页号（VPN）** | Virtual Page Number，虚拟页的编号 | — |
| **帧号（PFN）** | Physical Frame Number，物理帧的编号 | — |
| **页内偏移（Offset）** | 页内的字节偏移 | 12 bit（4KB页） |

**地址翻译公式**：
```
VA = VPN（高位） || Offset（低位）
PA = PFN（高位） || Offset（低位）
```

VPN → PFN 的映射存储在 **页表（Page Table）** 中。

### 2.2 单级页表的问题

如果使用单级页表，以 4KB 页、48 位虚拟地址为例：
- VPN 位数 = 48 - 12 = 36 位 → 2³⁶ 个页表项
- 每个 PTE 8 字节 → 页表大小 = 2³⁶ × 8 = 512 GB

**单个进程的页表就 512 GB**，显然不可行。→ 需要 **多级页表**。

## 3. 多级页表

### 3.1 x86-64 四级页表架构

x86-64 使用四级分页结构（4-level paging），4KB 页：

```
VA (48位):
┌────────┬────────┬────────┬────────┬────────────┐
│  PML4  │  PDPT  │   PD   │   PT   │  Offset    │
│  9 bit │  9 bit │  9 bit │  9 bit │   12 bit   │
└────────┴────────┴────────┴────────┴────────────┘
   47↔39    38↔30    29↔21    20↔12     11↔0
```

**四级页表翻译流程**：

```
                   CR3 寄存器（存 PML4 基地址）
                         │
                    ┌────▼────┐
  VA[47:39] ──────→│  PML4   │ ──→ 下一级页表基地址
                    └─────────┘
                         │
                    ┌────▼────┐
  VA[38:30] ──────→│  PDPT   │ ──→ 下一级页表基地址
                    └─────────┘
                         │
                    ┌────▼────┐
  VA[29:21] ──────→│   PD    │ ──→ 下一级页表基地址
                    └─────────┘
                         │
                    ┌────▼────┐
  VA[20:12] ──────→│   PT    │ ──→ 物理帧号（PFN）
                    └─────────┘
                         │
                    ┌────▼────┐
       Offset ────→│ 物理地址  │
                    └─────────┘
```

**每级页表是一个 4KB 的页**，包含 512 个 8 字节的 PTE（2⁹ = 512）。

**空间节省原理**：如果虚拟地址空间大部分未使用，中间级页表可以不存在（PTE 标记为 Not Present），只需分配实际使用的层级。

### 3.2 四级页表各级功能

| 级别 | 名称 | 索引位 | 作用 |
|------|------|--------|------|
| L4 | PML4（Page Map Level 4） | VA[47:39] | 顶层目录，CR3 指向此表 |
| L3 | PDPT（Page Directory Pointer Table） | VA[38:30] | 页目录指针表 |
| L2 | PD（Page Directory） | VA[29:21] | 页目录，**可指向大页（2MB）** |
| L1 | PT（Page Table） | VA[20:12] | 页表，指向 4KB 物理帧 |

### 3.3 大页（Huge Pages）

x86-64 支持三种页面大小：

| 页大小 | L2 大页 | L3 大页 |
|--------|---------|---------|
| **4 KB** | 标准页，四级页表全部遍历 | — |
| **2 MB** | PD 级 PTE 标记为大页，跳过 PT（省一级） | — |
| **1 GB** | — | PDPT 级 PTE 标记为大页，跳过 PD+PT（省两级） |

```
2MB 大页地址拆分：
┌────────┬────────┬─────────────────────┐
│  PML4  │  PDPT  │   PD (大页PTE)       │
│  9 bit │  9 bit │   21 bit Offset      │ ← 跳过 PT 级
└────────┴────────┴─────────────────────┘

1GB 大页地址拆分：
┌────────┬──────────────────────────────┐
│  PML4  │  PDPT (大页PTE)               │
│  9 bit │    30 bit Offset              │ ← 跳过 PD + PT 级
└────────┴──────────────────────────────┘
```

**PS（Page Size）标志位**：在 PD 或 PDPT 级的 PTE 中，PS=1 表示这是一个大页。

## 4. 页表项（PTE）标志位

每个 PTE 是 8 字节（64 位），包含物理帧号和各种权限/状态位。

```
x86-64 PTE 格式（4KB 页）：
63           52 51    12 11  9  8  7  6  5  4  3  2  1  0
┌──────────────┬─────────┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐
│    NX        │  PFN    │AVL│G│S│0│A│D│I│W│U│R│P│
└──────────────┴─────────┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘
  Execution    Physical    Ignored/SW
  Disable      Frame#      (可用给 OS)
```

### 4.1 关键标志位

| 位 | 名称 | 含义 |
|----|------|------|
| Bit 0 | **P (Present)** | 页是否在物理内存中。0 → 缺页（Page Fault） |
| Bit 1 | **R/W (Read/Write)** | 0 = 只读，1 = 可读写 |
| Bit 2 | **U/S (User/Supervisor)** | 0 = 内核态，1 = 用户态可访问 |
| Bit 3 | PWT (Page Write Through) | 缓存写入策略 |
| Bit 4 | PCD (Page Cache Disable) | 禁用缓存 |
| Bit 5 | **A (Accessed)** | 硬件自动设置：该页被访问过 |
| Bit 6 | **D (Dirty)** | 硬件自动设置：该页被写入过（仅 PT 级 PTE） |
| Bit 7 | PAT/PS | 页属性表 / 大页标志 |
| Bit 8 | **G (Global)** | 全局页（TLB 刷新时不刷掉） |
| Bit 9-11 | Ignored | 可被 OS 用于存储软件状态 |
| Bit 12-51 | **PFN** | 物理帧号（Physical Frame Number） |
| Bit 52-62 | AVL | 可用给 OS |
| Bit 63 | **NX (No Execute)** | 禁止执行（DEP 数据执行保护） |

### 4.2 Accessed 和 Dirty 位的作用

- **Accessed（A 位）**：每次访问该页时 CPU 硬件自动置 1。OS 定期扫描并清零，用于实现 **页面置换算法**（最近使用过 → 不该换出）。
- **Dirty（D 位）**：对该页写入时自动置 1。表示页内容已被修改，换出时需要 **写回磁盘**（否则丢弃即可）。
- **共同作用**：页面置换时，OS 可以决定：
  - Access=0 + Dirty=0 → 既未使用也未修改，优选换出
  - Access=0 + Dirty=1 → 未使用但被修改
  - Access=1 → 正在使用，不换出

## 5. TLB（Translation Lookaside Buffer）

### 5.1 为什么需要 TLB

每次内存访问都要遍历四级页表 → 需要额外 **4 次内存访问**（每级页表一次）。TLB 是 CPU 内部的 **页表项缓存**，保存最近使用的 VPN→PFN 映射。

```
CPU 访问内存流程（无 TLB）：
Load [VA] → 读 PML4 → 读 PDPT → 读 PD → 读 PT → 读 [PA]
            ↑4次额外内存访问

CPU 访问内存流程（有 TLB，命中）：
Load [VA] → TLB 命中 → 读 [PA]
            ↑0次额外内存访问（1 cycle 搞定）
```

**TLB 命中率** 直接影响性能：
- TLB 命中：~1 cycle
- TLB 缺失 → 硬件遍历页表：几十到上百 cycle
- TLB 缺失 + 缺页：数百万 cycle（磁盘 I/O）

### 5.2 TLB 结构

典型的 TLB 是 **全相联（Fully Associative）或组相联（Set Associative）** 的 CAM（Content Addressable Memory）：

```
TLB 项（典型格式）：
┌───────────┬──────────┬──────┬──────┬─────┐
│  VPN      │  PFN     │ ASID │ Flags│ V   │
├───────────┼──────────┼──────┼──────┼─────┤
│ 0x7F0...  │ 0x1000   │  42  │ RWE  │  1  │
│ 0x4A2...  │ 0x2000   │  42  │ RWE  │  1  │
│ 0x3B1...  │ 0x3000   │  17  │ R    │  1  │
└───────────┴──────────┴──────┴──────┴─────┘
```

- **VPN**：虚拟页号
- **PFN**：物理帧号
- **ASID**：Address Space ID（进程标识，避免切换进程时刷新 TLB）
- **Flags**：权限位（R/W/X）
- **V**：有效位

### 5.3 TLB 缺失处理

TLB 缺失有两种处理方式：

| 方式 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| **硬件遍历（Hardware Page Table Walk）** | x86/ARM 有专用硬件状态机 | 透明、快 | 硬件复杂 |
| **软件遍历（Software TLB Fill）** | MIPS 等 RISC 由 OS 处理 | 灵活、硬件简单 | 需要 TLB Miss Handler |

x86-64 使用 **硬件遍历**：MMU 自动执行四级页表遍历，将结果填入 TLB。

### 5.4 TLB 刷新策略

| 场景 | 策略 | 说明 |
|------|------|------|
| **进程切换** | 完整刷新（flush entire TLB） | 旧 TLB 项对当前进程无效 |
| **进程切换（有 ASID）** | 保留 TLB（标记 ASID） | 不刷新，只匹配 ASID |
| **页表修改** | 单页刷新（INVLPG 指令） | 只刷新指定的虚拟地址 |
| **CR3 重载** | 自动刷新（除 Global 页） | 切换页表时 CPU 自动清 TLB |

**ASID 标记**（Address Space ID）：
- 每个进程分配一个唯一 ASID（通常 8-16 位）
- TLB 中的每一项记录所属 ASID
- 进程切换时 **不刷新 TLB**，只切换当前 ASID 寄存器
- 不同 ASID 的 TLB 项互不干扰

### 5.5 大页减少 TLB 压力

大页的其中一个重要好处就是 **减少 TLB 缺失**。

```
一个 64 项 TLB，访问 1 GB 连续内存：
┌─────────────────────────────────────────────────────┐
│ 4KB 页 → TLB 覆盖范围 = 64 × 4KB = 256 KB        │
│ 对 1GB 数据的访问 → TLB 缺失 4,000,000+ 次        │
│                                                     │
│ 2MB 大页 → TLB 覆盖范围 = 64 × 2MB = 128 MB       │
│ 对 1GB 数据的访问 → TLB 缺失 ~7,000 次             │
│                                                     │
│ 1GB 大页 → TLB 覆盖范围 = 64 × 1GB = 64 GB        │
│ 对 1GB 数据的访问 → TLB 缺失 1 次（甚至 0 次）    │
└─────────────────────────────────────────────────────┘
```

**对性能的影响**：对于数据库、大数据、HPC 等工作负载，使用大页可以显著提升性能（TLB 缺失率降低 100x~1000x）。

## 6. 页面置换算法

当物理内存已满，需要换入新页时，必须 **换出某个现有页面**。页面置换算法决定"换出谁"。

### 6.1 FIFO（先进先出）

**原理**：维护一个队列，先进入物理内存的页面最先被换出。

```
物理帧: [A] → [A, B] → [A, B, C] → [B, C, D] → [C, D, E] ...
         空      装入A,B    装入C     换出A,装入D  换出B,装入E
```

**优点**：实现简单
**缺点**：Belady 异常

**Belady 异常**：FIFO 的独特现象——**分配更多物理帧反而导致更多缺页**。

```
引用序列：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5

3 帧（FIFO）：缺页 9 次
4 帧（FIFO）：缺页 10 次 ← 更多帧反而更差！

原因：FIFO 不考虑页面使用频率，可能换出"马上要用"的页面。
```

### 6.2 LRU（Least Recently Used）

**原理**：换出最长时间未被使用的页面。基于 **时间局部性**（刚访问过的页面很可能再次访问）。

**理想 LRU**：记录每个页面最近一次访问的时间戳，换出时间戳最旧的。
- 缺点：每次访存都要更新时间戳，硬件开销巨大。

### 6.3 Clock 算法（LRU 近似实现）

Clock 算法是 LRU 的高效近似，又称 **二次机会（Second Chance）** 算法：

```
                    ┌───┐
              ┌────→│ P0│←──── 时钟指针（hand）
              │     └───┘     │
              │     ┌───┐     │
              │     │ P1│     │
              │     └───┘     │
              │       .       │
              │       .       │
              │       .       │
              │     ┌───┐     │
              │     │ Pn│─────┘
              │     └───┘
              └────────────────── 每次缺页时指针移动
```

**算法步骤**：
1. 维护一个循环链表（所有在物理内存中的页面）
2. 每个页有一个 **使用位（use bit）**，即硬件 PTE 的 Accessed 位
3. 缺页发生时，指针指向下一个页面：
   - 如果当前页 use=1 → 清零 use，**给第二次机会**，继续移动
   - 如果当前页 use=0 → 换出该页
4. OS 定期或 lazily（缺页时）清零 Accessed 位

**效果**：被频繁访问的页面使用位总是 1 → 永远不会被选中换出。与真正的 LRU 效果非常接近，但硬件成本极低（只需 A 位）。

### 6.4 LFU（Least Frequently Used）

**原理**：换出使用频率最低的页面。

| 算法 | 决策依据 | 优点 | 缺点 |
|------|---------|------|------|
| FIFO | 驻留时间 | 简单 | Belady 异常 |
| LRU | 最近使用时间 | 时间局部性好 | 硬件成本高 |
| Clock | 近期的使用位 | 近似 LRU，硬件成本低 | 粒度粗 |
| LFU | 使用频率 | 频率局部性好 | 旧页面可能积累高计数 |
| **工作集** | 当前活跃页面集 | 避免抖动 | 实现复杂 |

### 6.5 工作集模型（Working Set Model）

**抖动（Thrashing）**：频繁缺页导致 CPU 大部分时间在等待磁盘 I/O，系统吞吐量急剧下降。

```
正常状态：CPU 利用率高，偶尔缺页
↓  (进程太多，分配的物理帧太少)
抖动状态：频繁缺页，CPU 大部分空闲（等磁盘），吞吐量暴跌
↓  (OS 检测到抖动)
缓解措施：暂停部分进程，增加活动进程的物理帧数
```

**工作集（Working Set）**：进程在最近 Δ 时间内访问的页面集合。

- **WSS（Working Set Size）**：进程工作集大小
- 当物理内存不足以容纳所有活动进程的工作集时 → **抖动**
- OS 通过监控缺页率来检测工作集变化
- 解决抖动：**交换（Swap Out）整个进程**，释放物理帧给其他进程

## 7. 缺页处理（Page Fault Handler）

### 7.1 缺页中断流程

当 CPU 访问不存在的页（PTE.Present=0）时触发 **缺页中断（Page Fault）**：

```
                  内存访问指令
                       │
              MMU 检查页表 PTE
                       │
             ┌─────────┴──────────┐
             │  PTE.Present == 1? │
             └─────────┬──────────┘
                       │ 否
                       ▼
              CPU 保存现场（压栈 PC、CR等）
                       │
              ┌────────▼──────────┐
              │  进入内核缺页处理程序  │
              └────────┬──────────┘
                       │
            ┌──────────▼──────────┐
            │  判断缺页类型          │
            │  (Invalid / Protection / COW) │
            └──────────┬──────────┘
                       │
            ┌──────────▼──────────┐
            │  找到或创建空闲物理帧  │
            │  (必要时换出旧页)     │
            └──────────┬──────────┘
                       │
            ┌──────────▼──────────┐
            │  从磁盘读入所需页     │
            │  (同步 I/O，进程阻塞) │
            └──────────┬──────────┘
                       │
            ┌──────────▼──────────┐
            │  更新页表（PTE）     │
            │  Present=1, PFN 指向新帧 │
            └──────────┬──────────┘
                       │
            ┌──────────▼──────────┐
            │  恢复进程执行         │
            │  (重新执行触发缺页的指令)│
            └─────────────────────┘
```

### 7.2 三种缺页类型

| 缺页类型 | 原因 | 处理方式 |
|----------|------|----------|
| **Invalid Access**（无效访问） | 访问未映射的地址（如空指针解引用） | 发送 SIGSEGV，终止进程 |
| **Protection Fault**（保护错误） | 写只读页、用户态访问内核页 | 发送 SIGSEGV，或触发 COW |
| **Demand Paging**（请求调页） | PTE.Present=0 但数据在磁盘 | 从磁盘加载页面到物理帧 |
| **Copy-on-Write**（写时复制） | fork 后写共享页 | 复制页面，分别映射 |

### 7.3 页面从磁盘加载（Demand Paging）

**交换空间（Swap Space）**：磁盘上的一个区域，用于保存被换出的页面。

```
物理内存 ←→ 交换空间（磁盘）
   │              │
   │ 换出（Swap Out）：内存 → 磁盘（需 Dirty 页写回）
   │ 换入（Swap In）：磁盘 → 内存（缺页时加载）
```

**关键性能数据**：
- RAM 访问延迟：~100 ns
- 磁盘（SSD）访问延迟：~100 μs（慢 1000 倍）
- 磁盘（HDD）访问延迟：~10 ms（慢 100,000 倍）

**一次缺页 = 数百万条指令时间**，因此缺页率必须极低。

## 8. 写时复制（Copy-on-Write）

### 8.1 fork() 的传统问题

```
fork() 的传统做法：
父进程物理内存 1 GB → fork() → 子进程复制 1 GB → 耗时+耗内存

实际上：fork() 后子进程通常立即 exec() 加载新程序 → 复制的 1 GB 全浪费
```

### 8.2 COW 优化

**核心思想**：fork() 后父子和子进程 **共享所有物理页**，但页表标记为 **只读**。当某一方 **写入** 时才真正复制。

```
fork() 后的内存布局（COW）：

    父进程页表               物理内存               子进程页表
    ┌────────┐              ┌────────┐            ┌────────┐
    │ VA→PA  │──── R/O ───→│  页 A   │←── R/O ───│ VA→PA  │
    │        │──── R/O ───→│  页 B   │←── R/O ───│        │
    │        │──── R/O ───→│  页 C   │←── R/O ───│        │
    └────────┘              └────────┘            └────────┘

子进程写入页 A 后（COW 触发）：

    父进程页表               物理内存               子进程页表
    ┌────────┐              ┌────────┐            ┌────────┐
    │ VA→PA  │──── R/W ───→│  页 A   │            │ VA→PA  │
    │        │──── R/O ───→│  页 B   │←── R/O ───│        │
    │        │──── R/O ───→│  页 C   │←── R/O ───│        │
    └────────┘              ├────────┤            └────────┘
                            │ 页 A'  │←── R/W ───│        │
                            └────────┘           │ VA→PA' │
```

**COW 处理流程**：
1. fork() 时父子共享页面，全部设为 R/O（只读）
2. 页面 PTE 标记特殊状态（COW 标志，OS 利用保留位）
3. 父或子写入 R/O 页面 → **保护错误**（Page Fault）
4. 缺页处理程序检查是否为 COW 页：
   - 是 → 复制该页，两个进程各自获得 R/W 权限的副本
   - 否 → 正常的写保护违规（SIGSEGV）
5. 恢复进程执行，重新执行写入指令（现在可写）

**性能收益**：
- fork() 本身极快（只复制页表，不复制内容）
- 节省大量物理内存
- 只有真正修改的页面才复制

## 9. 大页与小页对比

### 9.1 综合对比表

| 维度 | 4KB 小页 | 2MB 大页 | 1GB 大页 |
|------|----------|----------|----------|
| 页表级数 | 四级 | 三级（跳过 PT） | 二级（跳过 PD+PT） |
| TLB 覆盖（64项） | 256 KB | 128 MB | 64 GB |
| 内存碎片 | 小（4KB 粒度分配） | 大（2MB 对齐要求） | 极大（1GB 对齐） |
| 适用场景 | 通用用途 | 数据库、大数据 | HPC、GPU 直通 |
| 页表开销（1GB 连续） | 512+512+512+1=1537 页 | 512+512+1=1025 页 | 512+1=513 页 |
| 启动时间 | 不需要提前分配 | 需要预分配（hugetlbfs） | 需要预分配 |

### 9.2 典型 TLB 参数

现代 CPU TLB 通常是分层多级：

| CPU | L1 TLB（指令） | L1 TLB（数据） | L2 TLB（统一） |
|-----|:---:|:---:|:---:|
| Intel Skylake | 64 项（4KB）+ 64 项（2MB） | 64 项 | 1536 项 |
| AMD Zen 3 | 32 项 | 64 项 | 3072 项 |
| Apple M1 | 128 项 | 128 项 | 2048 项 |
| ARM Cortex-A78 | 48 项 | 32 项 | 1280 项 |

## 总结

| 概念 | 一句话总结 |
|------|-----------|
| **虚拟内存** | 进程看到的地址空间和物理内存解耦，OS + MMU 做翻译 |
| **多级页表** | 按需分配各级目录，解决单级页表 512GB 的内存开销问题 |
| **TLB** | 页表项的硬件缓存，1 cycle 命中 vs 上百 cycle 缺失 |
| **ASID** | 进程切换时保留 TLB，避免每次都完整刷新 |
| **页面置换** | FIFO（有 Belady 异常）、LRU（近似用 Clock）、工作集模型 |
| **缺页处理** | 中断→内核→磁盘 I/O→更新页表→恢复，代价极高 |
| **COW** | fork 优化：共享 + 只读，写入时复制，省时省内存 |
| **大页** | 减少页表层级和 TLB 缺失，但带来内存对齐和碎片问题 |

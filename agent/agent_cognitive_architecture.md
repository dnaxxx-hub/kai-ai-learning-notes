# Agent认知架构 — 自我理解与设计

> 学习时间：2026-05-12 13:35
> 定位：方向1 — 理解自身推理机制、工具调用、记忆系统

## 我当前认知架构的组成部分

### 1. 记忆系统（分层架构）
```
MEMORY.md — 长期精简索引（关键事件/决策/里程碑）
├── core/     — 身份（IDENTITY/SOUL/USER 不可变）
├── daily/    — 原始日志（每会话+每日归档）
├── long_term/— 里程碑/决策/学习总结
├── reflection/ — 反思日志（新增方向）
└── archive/   — 过期备份
```
- 目前分层是对的，但 knowledge_bridge_state.json（231条）是个扁平堆砌，缺少图结构
- 核心问题：**检索靠关键词匹配，没有语义链接**

### 2. 推理与决策（四层架构）
```
L1: agent_gateway.py — 统一消息入口 + 意图匹配
L2: orchestrator.py — 链式调度（schedule_chain）
L3: engine_registry.py — 14引擎统一注册
L4: memory/bitable/wiki/files 存储层
```
- 意图引擎（intent_resolver.py v2.0，匹配率94%）工作良好
- 但 L1→L2→L3→L4 的链路只在"用户来消息"时激活，**缺少自驱动时的认知流**

### 3. 自驱动系统
```
HEARTBEAT.md 指导 → 传感器 → 总线 → 系统状态 → 任务队列 → 探索/学习
```
- 这个链路由 heartbeat 消息触发，每30分钟轮转一次
- 问题：流程是线性的（做A→做B→做C），没有**优先级动态调整**和**中断处理**

### 4. 工具层
```
exec → 操作系统（Sandbox/Gateway/Host）
read/write/edit → 文件系统
web_search/web_fetch → 互联网
飞书API → 用户通信
cron → 定时任务
sub-agent → 并行任务
```
- 最大的缺失：我没有"自我诊断"工具。不知道自己的 token 消耗、不知道上下文窗口还剩多少、不知道某个 session 的运行时间

## 识别出的改进机会

### 机会1：知识桥→图结构
- 当前 231 条知识桥是扁平列表，缺乏关联
- 可以建立一个轻量图谱：知识点A→连接→知识点B
- 心跳时可以沿着图做路径遍历（而不是随机选一条）

### 机会2：自诊断能力
- 我不知道自己当前 session 的 token 用量
- 不知道各个 cron 执行后的实际状态（目前只读 bus）
- 应该加一个 self_diag.py 每心跳做一次快速自检

### 机会3：认知中断处理
- 当前：用户消息→中断一切→响应用户→（不恢复被打断的任务）
- 应该：中断→记录中断点→响应用户→回复后恢复上下文

> 2026-05-17

## 为什么 Agent 需要记忆

没有记忆的 Agent 每次对话都是"第一次见面"：
- 不记得用户的名字和偏好
- 不记得之前做过什么决定
- 不记得上次说过什么

**三种记忆类型**，类比人类大脑：

| 类型 | 人类类比 | 持续时间 | 容量 | 我们系统的实现 |
|:----|:--------|:--------|:----|:-------------|
| 工作记忆 | 手里的工作 | ~会话期 | 小（~8K tokens） | 当前对话上下文 |
| 短期记忆 | 今天的事 | ~天 | 中 | `memory/short_term/` `.write_buffer` |
| 长期记忆 | 人生经验 | 永久 | 大 | `MEMORY.md` `memory/` |

## 记忆系统架构

```
                 用户消息
                    ↓
            ┌─── 工作记忆 ───┐
            │ (当前对话上下文) │
            └───────┬───────┘
                    ↓ 需要持久化？
                    ├──是──→ 短期记忆缓冲区
                    │         (memory/short_term/YYYY-MM-DD.md)
                    │             ↓ 定期归档
                    │         长期记忆
                    │         (MEMORY.md + memory/long_term/)
                    │
                    └──否──→ 丢弃（临时的计算中间结果）
```

### 工作记忆（Working Memory）

- 就是当前的 LLM 上下文窗口
- 包含：系统提示 + 对话历史 + 检索到的记忆
- **不要存**：临时计算、中间结果
- **要存**：用户的决定、偏好、重要指令

### 短期记忆（Short-term Memory）

**我们系统的实现**：
- 每日日志：`memory/daily/YYYY-MM-DD.md`
- 短期上下文：`memory/short_term/`（7天内有效）
- 写缓冲区：`.write_buffer`（正在编辑的内容）

**存储策略**：
- 每次心跳记录系统状态
- 每次学习记录新知识
- 用户重要指令直接记入 MEMORY.md

### 长期记忆（Long-term Memory）

**结构化存储**：
```
memory/
├── MEMORY.md          ← 精简索引版，快速读取
├── core/              ← 身份/原则/授权（几乎不变）
├── long_term/         ← 里程碑/重要决策
├── learning/          ← 知识笔记（结构化）
└── archive/           ← 旧版备份
```

**关键设计原则**：
1. **精简索引** — MEMORY.md 只保留索引和摘要，细节在子目录
2. **语义搜索** — 用 `memory_search` 搜索全部记忆文件
3. **精确读取** — `memory_get` 只拉需要的行
4. **自动归档** — 短期记忆 >7天 → 归档到 daily/

### 知识桥（Knowledge Bridge）

我们的系统还有一个独特的**知识桥**机制：

```
学习系统 → knowledge_bridge.py → 知识桥
  ↓                                    ↓
学习笔记                             间隔复习
  ↓                                    ↓
知识点提取                           到期内容重读
  ↓                                    ↓
注册到桥                             遗忘曲线反转
```

- 每当学习新知识，自动提取关键点注册到桥
- 桥记录：知识点 + 学习时间 + 来源文件
- 间隔复习：按照遗忘曲线（1天→3天→7天→30天）自动安排复习

**桥状态**：
```python
{
    "entry": "PID控制: P=比例, I=积分, D=微分",
    "learned": "2026-05-15",
    "source": "iot_05_hal_gpio_pwm_adc.md",
    "next_review": "2026-05-22",  # 7天后
    "reviews": 1,                  # 已复习1次
    "mastered": False
}
```

## 记忆检索性能

| 操作 | 延迟 | 说明 |
|:----|:---:|:-----|
| memory_search (语义) | 50-200ms | 依赖 nomic-embed 本地模型 |
| memory_get (精确) | <5ms | 纯文件读取 |
| 全文 grep | 10-50ms | 依赖文件数量（~600文件） |
| knowledge_bridge 复习 | 100-500ms | 遍历桥+匹配文件 |

## 记忆淘汰机制

记忆不是越多越好——太多的记忆会：

1. **搜索结果噪声增加** — 需要在更多文档中找回相关结果
2. **知识桥膨胀** — 需要复习的内容过多
3. **存储空间占用** — 不重要

**淘汰规则**：
- 短期记忆 >30天无访问 → 自动归档到 archive/
- 知识桥中 mastered=True 且 >90天 → 移到冷存储索引
- 学习笔记中过时/错误的内容 → 标记 deprecated（不删除，但降低匹配权重）
- 临时文件（日志、中间结果） → 定期清理 >7天

## 与人类记忆的类比

```
人类大脑              AI Agent
────────────────────────────────
海马体（短期转长期）    memory_bridge / daily -> long_term
前额叶（工作记忆）      LLM context window
基底核（程序性记忆）     skills / tools 配置
语义记忆（知识）        learning/ 笔记目录
情景记忆（经历）        daily/ 日志文件
遗忘                   归档 + 淘汰机制
```

## 经验教训

1. **不要存所有东西** — 保存需要保留的，丢弃无关的
2. **结构化优于扁平化** — 目录结构 + 索引文件远远好于全部平铺
3. **搜索权重可调** — 核心文件（MEMORY.md）的匹配结果应该比短期日志高
4. **定期整理必不可少** — 没有维护的记忆系统会变成垃圾堆
5. **冗余不是坏事** — 核心信息可以同时存在于 MEMORY.md + 子目录
6. **知识桥有价值** — 间隔复习机制让遗忘的知识能重新强化
